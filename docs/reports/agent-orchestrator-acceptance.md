## 交付行为

按用户/画布持久化公平领取，画布内 FIFO；跨执行器画布驻留配额由有效租约与事务校验。空画布采用独立会话键。配置提交与领取共用准入锁，旧 epoch 无法推进或释放新租约。独立 Agent 生命周期保持模型、工具、审批等待不占短步骤调度槽。

管理员入口 `/admin/settings/agent`，导航和标题为“Agent（beta）”；集中调度配置、执行器状态、记忆管理，旧记忆链接保留查询参数并跳转。设置有 revision/CAS、事务审计和事件广播，Node 启动读取及事件热更新，5 秒恢复补漏；缩容保留既有会话排空，待返回领取再次校验容量。默认及最终设置：调度槽 4、单执行器驻留 64、每用户画布驻留 16。

## 3004 实际请求验收

全部负载验收使用可控模型桩，未调用真实收费渠道；原有 3 个渠道配置在验收前后整体指纹一致。用户已配置渠道继续由既有路由和并发限制管理。

| 场景 | 观测 |
| --- | --- |
| 公平准入 | A 画布排队 8 条、画布配额 2；B 在 2.08 秒获准，A 的容量等待原因明确。扩大配额后全部 9 条完成 |
| 热缩容 | 驻留 20 时上限缩至 16，不取消既有运行，第 21 条等待；释放后继续完成。调度槽 4→8→4 应用成功 |
| 配置冲突 | 旧 expectedRevision 保存返回 HTTP 409 |
| 16 路模型并发 | 16 个不同会话真实请求全部到达后才释放，模型活动峰值 16；阻塞时实际驻留 16、调度槽占用 0，短步骤占用峰值 4 |
| 审批不阻塞 | 4 个审批等待会话不阻塞另 12 个会话完成；仅恢复对应批准会话，其他 3 个仍等待 |
| 审批/副作用恢复 | Agent 停止期间批准，恢复后副作用一次、节点数 1，耗时 33.78 秒（含租约等待） |
| 在途模型重启 | 原任务请求数保持 1；总恢复约 51.1 秒，含脚本固定 50 秒旧租约等待；释放响应后 0.57 秒完成 |
| SSE 续传 | 4 个递增事件，从游标 3 重连仅返回后续 1 个事件；重复/乱序及通知缺失另由自动化覆盖 |

检查点、工具批次准入、工具回执、审批和压缩恢复由数据库/SDK故障测试与实际进程重启共同覆盖；没有在所有边界逐一硬杀 Go/PostgreSQL，也没有长期压力压测。请求详细时间线与活动数保存在本地私有 `.local/acceptance.json`、`.local/orchestrator-acceptance.json`。

阻塞模型期间一次资源采样：Agent 74.43 MiB / CPU 13.17%，Go 77.07 MiB / 10.85%，PostgreSQL 225.3 MiB / 1.89%；这不是资源峰值或长期平均。
