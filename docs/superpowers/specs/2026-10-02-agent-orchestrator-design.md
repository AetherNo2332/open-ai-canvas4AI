# Agent Orchestrator 公平准入与统一配置设计

已按用户批准实施并在隔离 3004 完成验证；不切换 3000、3002、3003，不推送远程。

## 目标与边界

Go 领取运行按 userId/canvasId 公平选择，画布内部保持 created_at/id 顺序；解决旧查询只取全局最早 20 条造成的画布饥饿。Node 保留独立异步 AgentSession 与短步骤轮转，不把 prompt() 放入执行槽。

轮转无法抢占已驻留的等待会话。新增严格、可配置的画布驻留上限，建议初始 16；单进程驻留上限保持 64。画布上限按所有执行器的有效租约统计，按 userId/canvasId 隔离，事务校验，不能依靠心跳计数授权。无 canvasId 的运行采用独立会话键，避免集中到一个空画布桶。这会使单一画布最多驻留 16 个会话，是本方案的明确容量取舍。容量耗尽仍允许排队，不承诺有界时间完成。

## 公平准入

新增持久化准入计数器和画布 lastAdmissionSequence。事务锁定计数器，读取所有符合状态、租约条件且未达到画布上限的画布，从最久未领取的画布中选择最早可领取运行。新画布序号为 0，以画布键打破平局。冲突候选跳过并继续；失败领取不推进轮转序号。候选读取、租约/epoch 更新和序号提交同一事务完成。

PostgreSQL 使用事务行锁；SQLite 使用写事务及有界冲突重试。所有准入路径遵循相同锁顺序：准入计数器、配置读取、运行与会话、事件计数器，检查现有回调是否引入反向依赖。保持旧 epoch 写入、续租、释放拒绝。

等候展示区分 executor_capacity 与 canvas_capacity。已有有效等待不重新领取、不抢占；新执行器恢复过期租约时复用已有任务与回执。

## 统一配置

新增独立 AgentSchedulerSetting，不改变现有 workerConcurrency 的 Go 集群后台任务含义。默认 dispatchConcurrency=4（范围 1..16），maxResidentSessions=64（范围 1..64 且不小于 dispatchConcurrency），maxResidentPerCanvas=16（范围 1..maxResidentSessions）。模型额度继续沿用 worker/channel 配置，不复制第二套预算。

Go 提供管理员 GET/PUT /api/admin/settings/agent-scheduler，PUT 携带 expectedRevision；冲突返回 409。通过内部 Token 鉴权的 GET /internal-agent/config 返回有效设置与 revision。保存设置、审计记录和 scheduler_config_changed 发件箱事件同一事务；配置保存与领取共同锁定准入计数器，避免按旧配额的领取越过配置提交。新设置提交前已生效的租约属于既有工作，缩容时排空；Node 对返回的领取请求再检查最新本机驻留和画布上限，超额则安全释放租约。

Node 启动领取前读取配置；无数据库配置时使用服务端默认/部署初始值，数据库保存后优先数据库。首次启动读取失败则不领取新运行；运行中断线保留最后有效设置，通过现有 SSE 和 5 秒恢复扫描补偿。只应用更高 revision；配置广播必须到达所有执行器，不能被 RunEvents 当成单一 runId 唤醒。

EventScheduler 支持更新执行槽；驻留准入控制器与固定数量 claim loops 解耦，分别统计 resident、claimReservations、dispatchActive、readyQueued。缩容时既有步骤和会话排空，暂时超出新上限显示 draining，不取消运行、不破坏租约，也不因容量心跳校验拒绝新的较小上限。已保存的旧配置缺少新字段时合并默认值。

## 后台统一入口：Agent（beta）

将管理员导航中的“Agent 记忆”改为“Agent（beta）”，移动到“平台配置”分组；页面标题使用相同文案。新页面路由为 /admin/settings/agent，原 /admin/agent-lessons 前端路由重定向到新页面的记忆管理区域，保留查询参数。既有 /api/admin/agent-lessons 后端接口继续复用；用户个人设置中的“Agent 记忆”名称和权限不变。

页面包含三个区域：调度配置、运行状态、记忆管理。调度配置管理执行槽、单执行器驻留上限和跨执行器画布驻留上限，说明作用范围、有效值、保存状态与应用版本。运行状态只读展示执行器在线状态、心跳时间、实际驻留、领取预留、槽占用、排队、缩容排空状态及已应用配置 revision；接口不可用时展示不可用，不能伪装为零。记忆管理复用 AgentLessonsPanel 的用户/状态/关键词筛选和删除操作，批准继续由记忆所属用户进行。

Agent 参数唯一编辑入口是本页面；“资源与策略”继续管理 Go worker/渠道并发，提供跳转链接，不复制 Agent 配置表单。新增管理员 GET /api/admin/settings/agent-scheduler/status，仅返回运行统计，不暴露内部 Token、渠道凭据或会话正文。容量上报增加 appliedConfigRevision 和运行统计，由 Go 校验并持久化，以支持页面区分“已保存”和“已应用”。此次运行管理不新增强制取消、删除运行或重启执行器操作。
