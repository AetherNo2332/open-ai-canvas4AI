# 画布资产批量下载与节点命名设计规范

## 目标

为画布增加“下载选中媒体”能力，并让单节点下载与批量下载都使用节点名称作为文件名。用户选择多个图片、视频或音频节点后，浏览器逐项触发单文件下载；不生成 ZIP，不由平台中转媒体正文。

## 已确认的产品决策

- 批量下载方式：直接触发多个单文件下载。
- 文件名：清洗后的节点标题加媒体扩展名，例如 `片头镜头.mp4`。
- 同名处理：按下载队列中的节点顺序追加 ` (2)`、` (3)` 等序号。
- 空标题：按节点类型使用 `图片节点`、`视频节点`、`音频节点`。
- 单节点下载和批量下载共用同一套命名函数。
- 批量下载只包含有可用 `storageKey`、内容 URL 或本地媒体引用的图片、视频和音频节点；文本、文件夹、配置和空媒体节点不进入队列。

## 用户流程

### 单节点下载

节点悬浮工具栏中的现有下载动作保持位置和语义不变。执行时调用统一命名函数，生成 `节点标题.扩展名`，然后复用现有浏览器下载器。

### 批量下载

当用户选中多个节点时，批量操作条显示“下载选中媒体”。按钮旁显示可下载数量；没有可下载媒体时按钮禁用。点击后：

1. 按画布节点数组的稳定顺序筛选图片、视频和音频节点。
2. 为每个节点计算唯一文件名。
3. 逐项触发现有浏览器下载器，每项之间保留短暂间隔，避免浏览器把全部操作判定为异常弹窗。
4. 操作条或轻量反馈显示当前进度，例如“正在下载 2/5”。
5. 完成后报告成功数和失败数；单项失败不阻断后续项目。
6. 浏览器拦截多个下载时，提示用户在浏览器权限提示中允许本站多个下载，并保留已完成项的结果。

批量开始后按钮进入 loading 状态，禁止重复启动同一队列；用户可以继续编辑画布，但不能修改当前队列中的文件名。关闭页面不会保证队列完成。

## 文件命名规则

新增纯函数 `buildCanvasMediaDownloadFileName(node, usedNames?)` 或等价接口，输入节点和已占用文件名集合，输出带扩展名的安全文件名。

- 标题来源：`node.title`。
- 非法字符 `\\ / : * ? " < > |`、控制字符和首尾空格清洗为 `_`。
- 连续下划线折叠，去除首尾下划线和末尾句点/空格。
- 标题为空时按节点类型使用默认名。
- 保留现有 MIME、data URL、URL 后缀推断逻辑；无法推断时按节点类型回退：图片 `png`、视频 `mp4`、音频 `mp3`。
- Windows 保留设备名加前缀下划线，避免导出到本地失败。
- 同名判断以完整文件名为准；第二个同名文件追加 ` (2)`，并在扩展名前插入序号。
- 文件名长度上限保持现有安全上限，扩展名必须保留。

现有的画布名和日期前缀从媒体下载文件名中移除；草稿、版本、调试记录等非媒体下载继续使用各自的命名规则。

## 组件与数据流

### 命名与资源解析

- `web/src/lib/canvas/canvas-media-download.ts`：保留媒体类型和扩展名推断，改为以节点标题为主，并提供批量唯一命名辅助函数。
- `web/src/services/browser-download.ts`：保持远程资源使用下载访问 URL、直链资源直接交给浏览器的行为，不新增 Blob 中转。
- `web/src/pages/canvas/use-canvas-node-editor.ts`：单节点下载调用新的命名接口；新增批量队列回调，统一处理筛选、进度和错误。

### 批量入口

- `web/src/components/canvas/canvas-node-action-context.ts` 或现有选择操作上下文：向批量操作条提供 `downloadSelected` 能力。
- 现有选择操作条：加入“下载选中媒体”按钮，只在有两个或以上选中节点且至少一个节点可下载时显示或启用；具体入口沿用当前画布批量操作条的布局和权限模型。
- 节点悬浮工具栏：继续调用单节点下载，不复制下载逻辑。

### 反馈状态

批量下载状态使用局部 React 状态，不持久化到画布数据。状态至少包括 `idle`、`running`、`completed`，以及每项的 `pending`、`success`、`failed`。反馈使用现有 message/toast 体系，避免新增全局状态库。

## 错误处理

- 节点没有资源定位信息：不加入队列；若单节点直接触发，则提示“当前节点没有可下载媒体”。
- 远程签名或资源读取失败：记录该节点名称和错误，继续后续队列。
- 浏览器拒绝自动下载：将其归类为失败，并提示开启本站多个下载权限。
- 同名文件：在队列生成阶段解决，不依赖浏览器覆盖策略。
- 队列中途组件卸载：取消后续未开始的项目，已触发的浏览器下载不回收；不写入画布数据。

## 非目标

- 不新增 ZIP 或服务端打包接口。
- 不修改资源权限、OSS/CDN 访问协议或存储模型。
- 不把视频、音频或大图片全部读入浏览器内存。
- 不改变草稿、版本、调试导出文件的命名格式。
- 不为批量下载增加后台任务、断点续传或离线队列。

## 验收标准

1. 选中一个名为“片头镜头”的视频节点，下载文件名为 `片头镜头.mp4`。
2. 选中两个同名视频节点，文件名为 `片头镜头.mp4` 与 `片头镜头 (2).mp4`。
3. 节点标题包含 Windows 非法字符时，下载文件名可保存且不包含非法字符。
4. 图片、视频、音频混选时，只下载有媒体定位信息的节点，并分别保留正确扩展名。
5. 一个节点下载失败时，后续节点仍继续下载，完成反馈显示成功/失败数量。
6. 批量下载不通过 Blob 读取远程媒体，仍使用现有 `downloadBrowserMedia` 访问契约。
7. 现有单节点下载、草稿下载、版本下载和调试导出行为不回归。
