# Agent 动态子代理设计

## 状态

- 日期：2026-10-06
- 阶段：开发中
- 目标：父 Agent 自主创建、命名、分配角色和目标，子 Agent 通过结构化消息回报父 Agent。

## 产品语义

用户只在当前画布打开或关闭“允许使用子代理”。开关一旦打开，从下一轮开始持续生效，直到用户关闭；它不是单轮授权，也不要求用户预先创建组、角色或成员。父 Agent 每轮根据任务需要决定是否调用 `spawn_subagent`。

## 架构

- `AgentSubagentPolicy` 按用户和画布持久化，使用 revision CAS；运行开始时冻结策略。
- `AgentSubagentLink` 显式连接父运行和子运行，保存显示名、动态角色标签、目标、指令、预算、深度和状态。
- `AgentSubagentMessage` 保存有序、幂等的进度、提问、结果、错误和取消消息。子消息唤醒父运行，但不直接修改画布。
- 父运行获得 `spawn_subagent`、`wait_subagents`、`message_subagent` 和 `subagent_status`；子运行只获得 `send_parent_message` 与 `finish_subagent`，深度固定为 1。
- 子运行默认只读或请求审批；画布写入仍由父运行聚合后进入现有审批/提交边界。
- 限制由服务端执行：最多 4 个子代理，最多 3 个并发，子代理最多 20 步，消息体有界。
- 子运行继承并冻结父运行的 credits 上限，按各自运行计费；默认只读、不创建生成任务。该版本不把多运行计费聚合成一个共享预算。
- `wait_subagents` 保留工具游标并挂起父 Pi 会话，释放驻留名额；全部子运行进入终态后重领父会话，重放同一调用并提交一次结果。画布会话容量为 1 也能完成父子链路。
- 子消息在模型上下文中标记为 Agent 数据，不提升为用户指令；失败/取消通过可恢复的终态补发事务回报。

## 破坏式迁移

这是开发期切换，不保留旧 Crew API、事件解析器、固定成员表或历史兼容路径。旧 Crew 表和前端配置入口在动态链路稳定后删除，开发数据库允许重建到新 schema。

## 验收重点

1. 开关跨轮持久化，关闭后下一轮不再暴露 spawn 工具。
2. 父运行创建的每个子运行都有独立 conversation 和显式 link。
3. 动态名称、角色和目标可审计；同一幂等键不会重复创建。
4. 子消息按序到达父运行，重复消息不重复唤醒。
5. 子代理不能继续生成子代理，不能直接写画布。
