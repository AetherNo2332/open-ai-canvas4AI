# Agent 工具快照管理

运行总览的工具快照状态独立于统计日期、用户、模型和渠道筛选。管理员可以查看后端实际工具目录、worker 在进程启动时加载的制品和任务冻结定义，比较字段差异、重新检测、导出工具诊断及排空 worker。未知、离线、制品无效和参数不一致分别展示，不能把未检测状态当作一致。

## 身份与加载

worker 启动后读取一次镜像内的 `TOOL_SCHEMA.json`，注册 `instanceId`、`bootId`、`loadGeneration`、构建提交和实际加载的制品。后续容量心跳和领取仅引用注册快照，不反复上传正文。修改宿主机文件不等于进程已经加载；更换制品须通过配套镜像重建和进程重启。

后端权威目录由运行时代码生成。工具定义对象的 JSON 键序不影响判断，任务按冻结工具子集比较，不要求每个权限模式包含完整工具全集。参数定义内的说明文字变化仍按严格规则检测，不提供忽略差异或覆盖历史任务的入口。

## 管理操作

- 运行总览提供快照状态和可链接的管理入口，显示异常实例、受影响任务和具体工具名。
- 快照详情支持完整工具定义及字段级差异；诊断导出只包含工具、版本、状态等白名单信息，不含用户提示词、工具实参、环境变量和内部令牌。
- 重新检测针对已注册、实际加载的制品，不隐含从文件热加载或重启容器。
- 排空阻止实例领取新任务，已持有的兼容任务继续使用原租约。操作需要管理员权限、原因及 `expectedRevision`；并发冲突刷新后重试。解除排空不能绕过快照校验。
- 异常解除后保留恢复记录；历史失败任务不会因检测恢复自动重跑或收费。

## 部署与迁移

标准 worker 镜像包含配套 harness，正式编排不使用活动源码挂载覆盖它。开发或隔离验收若显式挂载目录，需确保后端二进制和 worker 实际加载制品来自同一份源码。

`CANVAS_AGENT_BUILD_COMMIT` 在构建时标识 worker 源码提交。旧 worker 升级期间，`CANVAS_AGENT_REQUIRE_TOOL_SNAPSHOT=false` 允许旧领取协议继续运行，但后台显示未上报；完成全部 worker 升级后设为 `true`，拒绝没有完整注册身份的领取。已经注册的新 worker 始终接受身份、排空和冻结工具兼容性检查，不依赖该开关。

无兼容执行组合时任务保持等待，标记工具快照原因；不先授予租约再让任务因 schema 漂移失败，也不提交模型请求。多个 worker 中有兼容实例时继续处理兼容任务，不因单个异常实例暂停全部队列。运行中的任务快照不可编辑。

## 数据结构

数据库迁移 59 增加不可变工具快照及进程注册状态。快照保存 schema 版本、来源、工具数量、构建提交和工具定义正文；进程记录注册快照、启动标识、加载代次、心跳、手工排空和并发 revision。具体表与索引以 model 和迁移为准；历史运行按已有冻结定义读取，不在服务启动时扫描改写全部历史。

异常记录与管理审计保留检测和恢复依据。没有创建 Docker、SSH 或管理员任意命令执行接口；后台管理操作不会执行部署。

正文在 `agent_tool_snapshot_contents` 去重；`agent_tool_snapshots` 保存来源引用和工具名索引；`agent_tool_runtimes` 保存进程注册及排空状态；`agent_tool_snapshot_alerts` 保存异常生命周期；`agent_tool_snapshot_counters` 单独串行化快照写入。运行记录新增实际领取进程、任务快照和 worker 快照 ID，随租约原子绑定。旧任务无法确认的 schema 版本显示 `unknown`。新任务保存创建时的 schema 版本。

列表在服务端分页，支持来源、完整工具名、版本和 `runId` 筛选。按 `runId` 可提取已有历史任务的冻结定义。健康检测最多检查 500 个未完成任务，超限明确提示结果不完整。历史告警按后端快照区分；其他后端版本留下的记录显示为历史未复验，不推断其已经恢复或仍在运行。

worker 心跳只观察制品文件元数据，文件变更、不可访问会提示检查，但不替换内存快照。该观察不能证明文件内容一致，也不改变领取资格。
