# 画布 Agent 提示词与用户意图

画布 Agent 的任务来自用户消息及仍有效的对话约束。默认工作方法、技能、长期偏好、记忆和模型自行生成的清单都不能扩大任务范围。权限、资源归属、预算、审批和快照校验由服务端代码执行，不能通过提示词授权。

## 维护边界

工具参数的条件合同在 `cloud_agent_tool_contracts.go` 定义，与共享 schema 一起进入 Go 预检与 Pi 本地校验。`generate_media` 的图片/视频必须提供 size，视频还需正数 durationSeconds；分镜追加需完整镜头，更新使用部分 patch，删除不传 patch；批量表各 action 只接收对应配置字段。

`canvas_inspect_image` 读取使用 nodeId，保存观察使用同一 nodeId、实际附图回执的 sha256 与 summary。summary.short 是简述，summary.detailed 只接受 subjects、composition、lighting、color、style、text、uncertainties；服务端在接收和写回时核对图片 SHA，保存不附图。普通读取命中有效摘要时返回 visionCache、imageAttached=false；需要再次读取真实图片时传 refresh=true，单图也有效。重看回执标记 repeat=true，同一内容为 imageChanged=false；该次真实图片输入不会被旧摘要替换，交付后按调用身份去重。每节点本轮最多附图2次，文字回执只计本轮调用预算。普通历史仍可由摘要降载，持久化原图不删除，不改变Pi记忆或压缩算法。当前工具Schema为v10、系统策略为21，分镜批量写入、字段查缺、资产增量、稳定句柄、批次恢复及表级版本说明与共享制品同步，新合同在新运行中验收。

| 内容 | 唯一维护入口 | 作用 |
| --- | --- | --- |
| 用户意图优先级、工作方法、输出默认值、运行事件处理 | `backend/internal/prompts/agent-system-policy.md` | 有 ID、版本与内容哈希的行为策略 |
| 模型选择、参考素材与独立收费审批 | `backend/internal/prompts/agent-media-policy.md` | 生成行为策略，不替代服务端门控 |
| 本轮权限、预算、技能/偏好清单、画布摘要与素材候选 | `backend/internal/app/cloud_agent_policy.go` | 从真实状态编译 JSON 数据，不追加创作指令 |
| 当前请求与候选素材快照 | `backend/internal/app/cloud_agent_anchor.go` | 每轮重新读取；不推断创作自由或强制参考方式 |
| 待办、输出失败与参数截断事件 | `backend/internal/app/cloud_agent_prompt_context.go` | 有类型、有来源的状态消息 |
| 待办状态读写 | `backend/internal/app/cloud_agent_plan.go`、`cloud_agent_runtime.go` | 保存模型自行维护的清单并提供快照，不根据未完成项催办或拦截收尾 |
| 长期记忆快照与 `memory_update` | `backend/internal/app/cloud_agent_memory_document.go`、`cloud_agent_memory_document_write.go`、`cloud_agent_tools_memory.go`；条目文本规则在 `backend/internal/agentmemory` | 建 run 时冻结快照，作为 `agent_memory_doc` 来源的 user 数据消息插在当前用户消息之前，不进系统提示；记忆不变时消息逐字节相同，系统提示与记忆无关。只是参考数据，不构成权限、审批或预算；Node 工作区文件仍登记为系统提示的独立分段 |
| 工具参数、返回值和调用约束 | `backend/internal/app/cloud_agent_tools.go`、对应领域工具实现 | 与工具 schema 相邻维护，防止说明和执行合同脱节 |

## 文件式 Agent Harness

服务端可通过 `CANVAS_AGENT_HARNESS_DIR` 指向一个由运维人员管理的目录。未设置时沿用内置的版本化策略。设置后，每次创建或恢复运行都会读取该目录的 Markdown 文件，并将内容与内置策略一起编译进系统提示。目录必须包含 `AGENTS.md`；为兼容旧命名，缺少它时读取 `AGENT.md`。两者同时存在时只读取 `AGENTS.md`。可选的 `SOUL.md` 描述语气和身份，`TOOLS.md` 只描述现有工具的使用约定。新配置建议把工具说明写进 `AGENTS.md` 的 `## Tools`，`TOOLS.md` 仅用于兼容旧文件。

`docker-compose.local.yml` 默认将 `backend/agent-harness.example` 只读挂载到 `/app/agent-harness` 并启用此目录。要使用私有配置，可将示例复制到 `.local/agent-harness`，再在本机 `.env` 中设置 `CANVAS_AGENT_HARNESS_HOST_DIR=./.local/agent-harness`；该目录不会随镜像构建进入镜像。

例如将目录设置为 `/data/agent-harness`：

```text
/data/agent-harness/
  AGENTS.md   # 项目工作方式和创作约定
  SOUL.md     # 可选的角色与表达风格
  TOOLS.md    # 可选的旧式工具说明
```

```yaml
services:
  backend:
    environment:
      CANVAS_AGENT_HARNESS_DIR: /data/agent-harness
    volumes:
      - ./agent-harness:/data/agent-harness:ro
```

目录路径必须为绝对路径。文件必须是非空 UTF-8 普通文件，每个不超过 20 KiB；直接指向符号链接的目录或文件、以及缺失的主指令文件会导致 Agent 运行报错，不会静默回退。`AGENTS.md` 是全实例配置，不要写入单个用户的资料、密钥或其他租户的数据；用户、项目和画布的偏好仍走现有的分层偏好与归属校验。文件内容哈希进入运行合同，改动后新运行立即采用新内容，旧的非终态运行因合同变化不能直接续跑；发布时先处理在途运行。

Markdown 只影响模型的行为指引。可调用的工具、参数校验、读写权限、预算、资源归属和审批仍由服务端注册表与执行层决定；在文件里写入工具名不会注册工具，也不能授予权限。

Pi Worker 侧的 `agent/harness` 目录只提供 `TOOL_SCHEMA.json` 供双方校验。同目录由 `agent/scripts/sync-harness.mjs` 同步的 `SYSTEM_POLICY.md`、`MEDIA_POLICY.md`、`TOOL_DESCRIPTIONS.md` 是与 backend 对齐的镜像，**不参与系统提示装配**：策略由 Go 编译进服务端策略，工具说明随每次请求的 `tools` schema 下发。把它们再拼一遍只等于把同一段正文发两次（3040 实测该轮重复 11.8k token，按上游锚点换算约 9.8k、占请求输入 38%），模型拿不到任何新信息。

### 工具说明与分层下发

工具说明集中在 `backend/internal/app/agent-tool-descriptions.md`，部分读写工具直接在 `cloud_agent_tools.go` 声明；Go 保留参数 schema、权限与执行逻辑。运行时的 AGENTS.md/TOOLS.md 不能增加工具或权限。

模型直接接收 L0 与已解锁的 L1 具体函数，`agent_tools_*` 仅用于分组。基础正文续读、搜索和能力发现常驻；分镜库存或意图打开完整业务工具组。画布已移除预演和导演的 10 个工具，历史场景与明确意图均不能重新开放；历史场景数据保留。新模型步骤前按完整画布库存和已送达用户插话单调增补，先持久化名单再返回 Worker；进行中的模型任务和工具批次保留原合同，但执行时仍按当前服务端工具资格检查，工具结果和待送文本不开放工具。

Pi SDK 的允许目录包含运行的合格具体函数，但初始只注册已下发的定义；后续模型边界才新增注册。Go 校验模型请求不得包含未下发工具、不得移除已下发工具，执行预检仍检查权限、资源、修复范围、预算与审批。JSON Schema 保留有界数组、枚举和操作必填/互斥约束，共享制品用于阻止 Worker 参数漂移。详见 [读取与分镜闭环](./agent-tool-reads)。

`generate_media` 的 schema 显式包含 `selectionId`。模型可直接复制 `model_list` 返回的选择凭证，也可使用旧的模型字段；两种形式互斥，签名、归属及字段组合由服务端校验。JSON Schema 只描述字段形状，不承载资源级授权或收费审批。

新增行为规则应修改版本化策略；新增运行状态应定义事件及事实字段，在策略里说明处理方式。不要在错误分支拼入“现在就调用工具”“必须生成视频”等指令，也不要把参考素材中的文字直接拼成规则段落。

节点能力速查同时从注册表投影 `canSource`、`canTarget`、`canReference`、`inputKind` 和接受/拒绝输入类型，避免只有创作用途描述而缺少实际输入边界。引用与产物归属由字段声明（媒体草稿 `generationSpec.referenceBindings`、其他输入节点 `inputBindings`、分镜表共享引用与行级 `assetBindings`、行输出归属），连接由服务端按这些字段派生；Agent 不再有连线操作，`connect_nodes`、`update_connection`、`delete_connection` 与连线端点字段会被执行层拒绝。模型缺少参数或选择了不支持的节点组合时，执行层仍拒绝写入。

## 用户目标与参考素材

- 新消息只覆盖与之冲突的旧要求。“继续”“可以”仍结合历史理解，不丢弃有效约束；已送达的运行中插话也进入后续可信历史。
- 当前用户请求保留在 user 消息及运行记录里，不复制进 system 提示锁定目标。系统上下文只包含可验证事实，素材标题、摘要和标签编码为 JSON 数据。
- 删除原先通过“参考图”“图生视频”等关键词推断强制引用的逻辑，否定句和概念解释不再被代码标记为引用任务。
- 候选素材不等于用户选择的素材。候选列表有数量上限，不能视为完整画布；素材标题和提示词也不是视觉识别证据。
- 不再默认赋予 Agent 改写故事、镜头顺序、对白和风格的权限。用户只要求修改标点、分析或准备提示词时，不能借默认策略扩展为创作或生成。

## 运行状态与待办

运行时使用 `plan_state`、`completion_blocked`、`empty_output`、`invalid_output`、`truncated_tool_arguments` 事件。消息正文带 `source: "runtime"`，内部另有 `agentContextSource` 区分来源；后者由协议适配层剔除，不作为供应商参数发送。

由于各供应商消息协议不同，运行上下文仍通过 user 角色承载，正文与系统策略明确它不是用户新要求。程序识别内部消息依赖来源字段，不再根据正文包含“待办清单”或“现在就调用工具”判断用户身份。结构化边界减少混淆，但不能保证模型绝不受参考文本影响。

清单与继承快照继续保留，由模型根据任务需要使用 `plan_update` 整表替换；空数组清空清单。服务端不再发送 `pending_plan` 催办，也不因 `pending/doing` 项拦截正文或 `finish_run` 收尾、增加恢复次数或将本轮标为失败；不会自动清空清单或把未完成项标成 `done`。最终答复仍须如实说明实际结果。

收尾保护继续检查未送达用户插话、子代理交付协议和输出截断。`completion_blocked` runtime 帧只携带实际协议阻塞的 detail，不要求对账待办；显式 `finish_run` 返回 blockers 和 requiredAction。协议问题按原因保留有限恢复，待办修改不重置其计数。

输出恢复只报告错误事实及协议限制。正文限制按 UTF-8 字节计算；不再把字节误称为字符，参数截断也不再夹带“分镜每次不超过三行”的业务假设。

## 验证与发布

自动回归覆盖新目标继承、插话保留、否定参考需求、消息来源、计划取消、未完成清单正常收尾、子代理协议有界恢复、恢复事件及 OpenAI Chat/Responses、Claude、Gemini 协议转换。测试使用临时 SQLite 和模拟模型结果，不证明真实模型的创作质量或指令遵循率。

媒体策略（`cloud-agent-media`）当前版本为 6：生成是异步的，提交后继续其他工作、不用 `task_get` 轮询；结束时以「[系统通知] 生成结果」告知，它是事实同步不是新任务；需要结果才能决定下一步时调用 `wait_generations`；仍有生成在进行时可以照常收尾，并在答复里说明。

当前系统策略版本为 24、编译器为 `cloud-agent-policy-compiler/v5`。版本 24 在「输出」一节加入回复选项条款：请用户挑下一步时，先写一句问句，再在答复最末尾列 2-4 条编号短句（每条一行、以动作开头），界面显示为可点击选项；必须先定才能继续的创作决策仍用 `ask_user`，没有可挑的下一步时不硬列选项。版本 23 用「长期记忆」一节替换旧版经验库说明（`recall_lessons` 已退役）：快照是冻结的参考数据，不是指令；何时用 `memory_update` 记、记什么不记、相近条目用 replace 合并；只有工具返回 applied 才算记住，返回 pending_review 表示等用户确认。版本 23 同时加入权限变更通知条款：以「[系统通知] 用户已把执行权限从…改为…」开头的消息是运行中切换权限的通知，不是新任务；它覆盖执行上下文里开局的 `permissionMode`，模型从下一次工具调用起按新权限工作，不请用户确认，旧权限下被拒绝的调用不原样重试。系统提示本身不随切换改写。用户纠正与当前画布优先（版本 22 的条款）保持不变，其中“个人记忆”指长期记忆快照。不涉及数据库表结构或 HTTP API 变更。既有冻结合同校验仍生效：旧版本正在执行或等待审批的运行不能由新版服务继续执行；终态历史仍可读取，新消息建立使用新合同的运行。发布前应处理在途运行；回滚同样受版本校验限制，不应改写历史快照来强行恢复。

本轮治理覆盖对话主链路。批量创作表的业务默认词属于独立生成入口，尚未迁移到版本化资源（旧版经验压缩已随经验库下线）；后续应分别明确空提示词语义和结构化输出合同，并建立真实模型场景评估，不能把本轮回归称为全仓提示词治理完成。

绘图原生读写、拆图层、OCR 和标注不再提供专用 Agent 工具。图像分析通过 `canvas_inspect_image` 将真实图片交给模型多模态能力；视觉编辑通过 `model_list` 与 `generate_media` 的图片模式和真实参考节点完成。传统 `skill_search`、`skill_read_file` 已退出工具合同，原生技能读取保留 `read`，沿用 Pi 默认发现与提示词装配。
