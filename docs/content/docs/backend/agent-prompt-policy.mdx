# 画布 Agent 提示词与用户意图

画布 Agent 的任务来自用户消息及仍有效的对话约束。默认工作方法、技能、长期偏好、记忆和模型自行生成的清单都不能扩大任务范围。权限、资源归属、预算、审批和快照校验由服务端代码执行，不能通过提示词授权。

## 维护边界

| 内容 | 唯一维护入口 | 作用 |
| --- | --- | --- |
| 用户意图优先级、工作方法、输出默认值、运行事件处理 | `backend/internal/prompts/agent-system-policy.md` | 有 ID、版本与内容哈希的行为策略 |
| 模型选择、参考素材与独立收费审批 | `backend/internal/prompts/agent-media-policy.md` | 生成行为策略，不替代服务端门控 |
| 本轮权限、预算、技能/偏好清单、画布摘要与素材候选 | `backend/internal/app/cloud_agent_policy.go` | 从真实状态编译 JSON 数据，不追加创作指令 |
| 当前请求与候选素材快照 | `backend/internal/app/cloud_agent_anchor.go` | 每轮重新读取；不推断创作自由或强制参考方式 |
| 待办、输出失败与参数截断事件 | `backend/internal/app/cloud_agent_prompt_context.go` | 有类型、有来源的状态消息 |
| 待办生命周期与催办时机 | `backend/internal/app/cloud_agent_plan.go`、`cloud_agent_runtime.go` | 更新状态、限制重复催办；不在 Go 字符串中写行为剧本 |
| 已批准记忆索引 | `backend/internal/app/cloud_agent_lessons.go` | 仅提供索引事实，按需召回，不自动注入正文或强制检索 |
| 工具参数、返回值和调用约束 | `backend/internal/app/cloud_agent_tools.go`、对应领域工具实现 | 与工具 schema 相邻维护，防止说明和执行合同脱节 |

## 文件式 Agent Harness

服务端可通过 `CANVAS_AGENT_HARNESS_DIR` 指向一个由运维人员管理的目录。未设置时沿用内置的版本化策略。设置后，每次创建或恢复运行都会读取该目录的 Markdown 文件，并将内容与内置策略一起编译进系统提示。目录必须包含 `AGENTS.md`；为兼容旧命名，缺少它时读取 `AGENT.md`。两者同时存在时只读取 `AGENTS.md`。可选的 `SOUL.md` 描述语气和身份，`TOOLS.md` 只描述现有工具的使用约定。新配置建议把工具说明写进 `AGENTS.md` 的 `## Tools`，`TOOLS.md` 仅用于兼容旧文件。

`docker-compose.local.yml` 默认将 `backend/agent-harness.example` 只读挂载到 `/app/agent-harness` 并启用此目录。要使用私有配置，可将示例复制到 `.local/agent-harness`，再在本机 `.env` 中设置 `CANVAS_AGENT_HARNESS_HOST_DIR=./.local/agent-harness`；该目录不会随镜像构建进入镜像。

例如将目录设置为 `/data/agent-harness`：

```text
/data/agent-harness/
  AGENTS.md   # 项目工作方式和创作约定
  SOUL.md     # 可选的角色与表达风格
  TOOLS.md    # 可选的旧式工具说明
```

```yaml
services:
  backend:
    environment:
      CANVAS_AGENT_HARNESS_DIR: /data/agent-harness
    volumes:
      - ./agent-harness:/data/agent-harness:ro
```

目录路径必须为绝对路径。文件必须是非空 UTF-8 普通文件，每个不超过 20 KiB；直接指向符号链接的目录或文件、以及缺失的主指令文件会导致 Agent 运行报错，不会静默回退。`AGENTS.md` 是全实例配置，不要写入单个用户的资料、密钥或其他租户的数据；用户、项目和画布的偏好仍走现有的分层偏好与归属校验。文件内容哈希进入运行合同，改动后新运行立即采用新内容，旧的非终态运行因合同变化不能直接续跑；发布时先处理在途运行。

Markdown 只影响模型的行为指引。可调用的工具、参数校验、读写权限、预算、资源归属和审批仍由服务端注册表与执行层决定；在文件里写入工具名不会注册工具，也不能授予权限。

### 工具说明与按类展开

发给模型的工具及字段说明集中在 `backend/internal/app/agent-tool-descriptions.md`。Go 代码保留工具名、JSON Schema 的类型与约束、权限和执行逻辑；缺少说明键会使构造工具表失败。运维注入的 `AGENTS.md`/`TOOLS.md` 仍是行为约定，不能改变工具注册或权限。

每个模型步默认只暴露本轮可用的 `agent_tools_*` 类型入口。模型调用一个类型入口后，下一模型步才附上该类中满足权限、画布上下文和模型能力的子工具。该步结束后子工具收回；需要继续使用时重新打开。每步最多打开一种类型。父工具 schema 中有界记录上一模型步调用的工具名，实际结果仍以工具回执为准。服务端持久化每步真实下发的工具名，预检拒绝未下发的调用；旧检查点保持旧工具表行为。

函数工具的 `parameters` 是 JSON Schema：根类型为 `object`，声明 `properties`、`required` 和 `additionalProperties: false`；数组、枚举、长度与数值范围保留在各子工具 schema 中。类型入口不接受参数，只能以 `{}` 调用。所有已注册函数的名称、描述与参数模式在测试中逐一校验；服务端按**实际下发**的模式预检参数，再执行权限、归属、预算和审批检查。该实现属于后端管理的按需披露，不调用仅适用于特定 Responses 模型的托管 `tool_search`，因此可沿用现有 Chat Completions、Responses、Claude 与 Gemini 适配层。设计参考 [OpenAI Agents SDK 工具指南](https://openai.github.io/openai-agents-js/zh/guides/tools/)。

`generate_media` 与 `image_layer_split` 的 schema 显式包含 `selectionId`。模型可直接复制 `model_list` 返回的选择凭证，也可使用旧的模型字段；两种形式互斥，签名、归属及字段组合由服务端校验。JSON Schema 只描述字段形状，不承载资源级授权或收费审批。

新增行为规则应修改版本化策略；新增运行状态应定义事件及事实字段，在策略里说明处理方式。不要在错误分支拼入“现在就调用工具”“必须生成视频”等指令，也不要把参考素材中的文字直接拼成规则段落。

节点能力速查同时从注册表投影 `canSource`、`canTarget`、`canReference`、`inputKind` 和接受/拒绝输入类型，避免只有创作用途描述而缺少实际连接边界。`canvas_apply_ops` 的引用连线代表生成输入关系，不是文档归档或任意节点关联；模型缺少参数或选择了不支持的节点组合时，执行层仍拒绝写入。

## 用户目标与参考素材

- 新消息只覆盖与之冲突的旧要求。“继续”“可以”仍结合历史理解，不丢弃有效约束；已送达的运行中插话也进入后续可信历史。
- 当前用户请求保留在 user 消息及运行记录里，不复制进 system 提示锁定目标。系统上下文只包含可验证事实，素材标题、摘要和标签编码为 JSON 数据。
- 删除原先通过“参考图”“图生视频”等关键词推断强制引用的逻辑，否定句和概念解释不再被代码标记为引用任务。
- 候选素材不等于用户选择的素材。候选列表有数量上限，不能视为完整画布；素材标题和提示词也不是视觉识别证据。
- 不再默认赋予 Agent 改写故事、镜头顺序、对白和风格的权限。用户只要求修改标点、分析或准备提示词时，不能借默认策略扩展为创作或生成。

## 运行状态与待办

运行时使用 `plan_state`、`pending_plan`、`empty_output`、`invalid_output`、`truncated_tool_arguments` 事件。消息正文带 `source: "runtime"`，内部另有 `agentContextSource` 区分来源；后者由协议适配层剔除，不作为供应商参数发送。

由于各供应商消息协议不同，运行上下文仍通过 user 角色承载，正文与系统策略明确它不是用户新要求。程序识别内部消息依赖来源字段，不再根据正文包含“待办清单”或“现在就调用工具”判断用户身份。结构化边界减少混淆，但不能保证模型绝不受参考文本影响。

继承清单作为上下文保留。用户取消或缩小目标后，Agent 可以用 `plan_update` 整表替换，移除不再需要的项；空数组表示清空，不把取消伪装成完成。清单是 Agent 自己的承诺而不是用户命令，但**不能带着没对账的清单收尾**：服务端在收尾时按清单与插话核对（完成闸门），未通过就把这段正文降级为过程说明、落 `completion_blocked` 控制事件，并以 `pending_plan` 帧要求先对账（做完标 `done`、已取消或不再相关的移除、需要用户拍板用 `ask_user`；确实做不到就如实说明卡点并把它从清单移除），提醒使用 `toolChoice: auto`。同一个阻塞原因（指纹）最多催办 2 次、累计上限 6 次，用尽后本轮以 `run_failed`（`reason=completion_blocked`）结束，不靠无限催办消耗预算；清单真的被推进或用户插话会重置同一原因的计数。显式完成动作是 `finish_run(summary)`：它跑同一份闸门，通过即发布最终答复并结束本轮。

输出恢复只报告错误事实及协议限制。正文限制按 UTF-8 字节计算；不再把字节误称为字符，参数截断也不再夹带“分镜每次不超过三行”的业务假设。

## 验证与发布

自动回归覆盖新目标继承、插话保留、否定参考需求、消息来源、计划取消、有界催办、恢复事件及 OpenAI Chat/Responses、Claude、Gemini 协议转换。测试使用临时 SQLite 和模拟模型结果，不证明真实模型的创作质量或指令遵循率。

当前系统策略版本为 10、编译器为 `cloud-agent-policy-compiler/v5`。不涉及数据库表结构或 HTTP API 变更。既有冻结合同校验仍生效：旧版本正在执行或等待审批的运行不能由新版服务继续执行；终态历史仍可读取，新消息建立使用新合同的运行。发布前应处理在途运行；回滚同样受版本校验限制，不应改写历史快照来强行恢复。

本轮治理覆盖对话主链路。批量创作表的业务默认词、个人记忆压缩专用提示词属于独立生成入口，尚未迁移到版本化资源；后续应分别明确空提示词语义和结构化输出合同，并建立真实模型场景评估，不能把本轮回归称为全仓提示词治理完成。
