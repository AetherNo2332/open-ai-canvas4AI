## 分镜输入框发送到当前 Agent

分镜表输入框保存剧情后，构造包含目标节点真实 ID、原始剧情、镜头数及单镜时长的提示词模板，直接交给当前 Agent 面板，并遵守账号默认插队/排队方式。插队沿当前轮补充，排队由服务端保存并在后续轮次执行；没有对话时由面板按原流程创建首轮。节点不再提供独立模型选择或调用文本任务拆镜，章节分镜等其他入口维持原实现。

模板要求 Agent 先读取目标表及相关上下文、选择适用的已启用技能，再推荐项目基调和拆镜方案，通过 `ask_user` 取得用户确认后将剧情写入原表 composerContent、风格要求写入相连文本节点，再调用 split 服务端拆镜；部分不满意用 resplit，写回后 read 核对。画风节点和有效预设不是规划前提，现有画风可作参考。确认前不改镜头行、不创建画风节点或生成媒体；实际权限、预算、快照与资产引用校验继续由服务端执行。用户确认是模型行为约定，模板本身不能替代服务端审批，也不保证模型永不跳过提问。

发送复用会话的幂等与恢复机制；外部节点请求不覆盖 Agent 输入草稿。未知 POST 保留原接口、body/key/parent、mode 和 questionId，不能因默认方式改变而改投递；原请求正文与新草稿分别保留，重试不覆盖新草稿。节点调用明确区分已发送、已排队和未确认，节点新任务不自动附带问题回答关联。切会话后旧回执不释放新请求锁或覆盖新作用域。

排队状态与原始提交收条独立于运行检查点。`ask_user` 虽然将本轮置为 completed，队列仍会等待与当前 questionId 关联的明确回答；选项回答绕过默认排队方式，普通排队消息不会代答。模板仍不能替代模型行为控制、写权限或媒体审批；这次未修改 Agent 记忆与上下文压缩。

## 画布读取

`canvas_get_state` 提供 `catalog`、`detail`、`references`、`edit` 四种视图。未指定节点时默认目录；指定节点时默认 detail。只有 edit 返回 editable 和富文本。正文被截断时，`nextRead` 给出 `canvas_read_content` 的实际续读参数，偏移按 Unicode 字符计算。

`connections` 参数为 `none`、`selected` 或 `incident`：默认不附边，子图默认 selected。连线是派生的只读关系；业务输入以引用字段及解析结果为准。`type` 表示底层存储，所有节点均提供 `kind` 表示业务能力，角色卡为 `kind=character`。

## 分镜绑定检查

`storyboard` 的 `read` 默认 `view=creative`，返回创作说明、时长、对白、实际引用的名称/角色版本与就绪状态。`summary` 扫描缺口，`bindings` 排查底层声明；三者默认且最多100行，按结果字节预算分页。`full` 读取高级字段，默认1行、最多20行。可按 `rowIds` 精确选行，与非零 offset 互斥。返回 `rowId` 作为唯一编辑句柄。

`fields` 只选择需要的创作列，例如图片提示词、视频提示词、景别、运镜或时长；`missingAnyFields` 按“任一指定列缺失或空白”筛选，时长缺失或非法也视为缺口。筛选在 rowIds 选择后、分页前进行，续页参数保留筛选条件。summary 默认不返回行正文，显式传 fields 时也会返回所选正文。长文本预览被截断时，通过 `nextReads` 中的 `canvas_read_content` 读取原始字段和准确偏移；首尾空白不会被预览或续读丢掉，逐页读取仍受字节预算约束。

`hasImagePromptOverride`、`hasVideoPromptOverride` 区分独立提示词覆盖，`effectivePromptSource.image/video` 返回 `imageGenerationPrompt`、`videoMotionPrompt`、`plotDescription` 或 `none`。覆盖为空时实际生成可回退到创作说明，字段查缺不等于生成被阻塞，也不代表资产和模型已就绪。

结果显式包含共享 referenceNodeIds、行 assetBindings/characters、图片和视频产物以及有效输入。`mode=image/video` 复用生成的引用解析规则；video 遵守关键帧模式，省略 mode 时仅检查声明引用。

上述底层声明在 bindings/full 中读取，creative 只返回合并后的实际输入，避免重复维护关系图。搜索节点同时返回业务类型标签、可引用状态和角色实际版本；素材库结果有 `scope=library_asset`，其 assetId 只供 `canvas_bind_asset` 替换画布媒体节点，不能直接填进分镜引用。

`coverage` 中 totalRows 是全表规模，selectionRows 是筛选前的选择范围，selectedRows/matchedRows 是筛选匹配数量，inspectedRows 是本页行数。selectionComplete 表示本页到达匹配范围末尾，tableComplete/complete 表示本次响应覆盖整表所有行；contentTruncated 独立标记正文是否仍需续读。不能把“最后一页”理解成“本次响应包含全部内容”。summary 的缺媒体输入、引用无效、资源不可用、状态未知、待迁移和缺输出分别统计；待迁移的旧连线不算作确认空输入。没有镜头产物不代表不能执行文生模式，行级数组为空也不代表共享输入为空。分页按 nextRead 继续，不把未返回字段当作明确为空。

## 分镜创作与生成闭环

分镜读取同时返回 `storyboardRevision`，覆盖整表、共享/行级资产、输出依赖及持久实体世代。纯创作字段的 `update`（patch 或 updates） 可携带该版本与 `snapshotHash`：无关节点布局不阻塞编辑，同表或依赖内容、表重建仍产生冲突。没有表版本时沿用全画布保护；拆镜、资产和产物动作仍校验当前画布；镜头增减通过 resplit。该版本当前按整表计算，另一行的人工修改也会冲突。

增量行资产使用 `add_assets`、`remove_assets`、`upsert_assets`，由 `ref` 和 `role` 定位，未提及的角色/资产保留；增量共享输入使用 `add_references` / `remove_references`。增量数组必须非空。`set_assets` / `set_references` 保留明确替换与清空语义。回执 `assetChanges` 列行资产新增、移除、保留及有效输入的计数，小变更直接列明细；明细总预算为8KiB，超出时标记 `detailsOmitted` 并给出 `assetChangesNextRead`，用绑定分页核对，不重复返回每行全部资产。`referenceChanges` 列共享增减及影响行数，不将共享删除误报为行资产删除。

有效媒体输入提供现有 `bindingId` 及 `promptHandle`，例如 `{{ref:node:hero:reference}}`。在分镜提示词中复制这个句柄；Agent 与浏览器的实际分镜生成入口都在最终素材顺序确定后转换为供应商序号，原表正文不改写。调整另一行、共享输入或当前资产优先级不会改变句柄指向；当前输入移除该资产、句柄格式无效或无实际媒体槽位时拒绝生成。旧的数字编号文本仍按既有协议处理，新的创作应使用稳定句柄。

## 分镜分块恢复

每个编辑批次可提供8–128字符的稳定 `operationId`。画布写入和已有命令回执表中的批次记录在同一事务提交；相同标识、相同操作参数返回原结果，不重复追加或审批；同标识不同参数拒绝。版本前置条件不属于操作身份，冲突后可刷新版本继续原操作。恢复生成新画布 epoch 后，旧标识返回 `operation_epoch_conflict`，不允许将历史追加当作未执行而重发；重新确认目标后，新操作使用新标识。

`storyboard` 的 `read` 的 `operationIds` 每次可查1–20个不同批次，返回 `committed` 及其目标行/字段、追加行，或 `not_found`；旧画布世代的记录标记 `retired_epoch`。目标清单过大时应减少每次查询的批次数量。继续用 `fields` / `missingAnyFields` 核对当前持久内容与剩余缺口；历史已提交不代表后来未被人工修改。重放返回 `replayed=true` 和当前版本提示 `currentSnapshotHash`，原 `snapshotHash` / `storyboardRevision` 仍属于原提交，不加入新的写入版本链；新批次应从当前目标状态继续。数据库或回执写入失败时整次回滚，不留下“行已改但无回执”的状态。

## 分镜创作字段

新建用 canvas_apply_ops 创建 script 并写剧情，随后 storyboard.split 由服务端分配行 ID。行以 `plotDescription` 维护创作说明，并可独立编辑景别、运镜、光影、表演、节拍和连续性等领域创作字段；时长、对白与可选图片/视频提示词覆盖分别维护。UI 与 Agent 的创作字段来自同一领域合同，任务状态和产物身份仍由专用流程管理。已有提示词覆盖优先于创作说明，修改说明不会隐式清空覆盖。

行 `assets` 为 `{ref,role}` 数组，ref 接受当前画布节点 ID 或唯一完整名称，服务端转成现有 `assetBindings` 并校验用途。同名多版本、缺失、归档或用途不匹配时整次拒绝，禁止模糊匹配和猜版本。共享上下文用 `references`；仍可显式使用真实 `referenceNodeIds`。

`storyboard` 的 `update` 使用 `updates:[{rowId,patch}]` 为不同行写入不同内容；增减镜头用 resplit，不手工追加整表。每批最多100项，表内总数最多100行；长内容按必要批次拆分。`update/set_assets` 继续使用 rowId 或 rowIds，其中 update 给全部目标行应用同一 patch。set_assets 完整替换行资产并清空旧 characters，空数组不影响共享输入。整批在副本上校验并基于同一快照提交，一处失败不部分落库；删除镜头仍检查行状态和持久任务占用。

编辑回执以 `applied` 表示已执行，`changed` 表示内容是否实际变化；`affectedRows` 是处理目标数，`changedRows` 只列真正变化的行和字段，删除导致的镜号重排也会列出。创建和追加通过 `createdRows` 返回新行身份，删除通过 `removedRowIds` 返回已删除身份；普通编辑不再回传全表 ID。全表共享字段的变化另见 `changedFields`。每个模型步骤只放行一个写入或生成调用；下一模型步骤可直接复用成功回执的 snapshotHash，实际冲突或所需状态未知时再读取并核对原操作。审批卡仍提供面向用户的变更预览。

分镜 `generate_media` 只需模式及表/行身份，输入从行读取，自动分配目标和标题、使用项目及模型目录默认值、管理位置并回填产物。已有绑定必须通过原占用规则，省略 nodeId 不会绕开已有任务或产物。身份由运行、模型步骤和调用共同确定，重复 provider callId 不会与另一模型步骤碰撞；审批和恢复复用已解析目标。收费任务继续逐镜受理，价格、预算、资源与审批边界保留，提交失败不触发自动收费重试。

`model_list` 可用 `storyboardNodeId+storyboardRowIds` 批量查询，复用生成解析器和真实资源检查，在同一画布快照上按输入类型、数量及视频时长分组。每组返回一份模型目录，各行保留对应组或问题。角色创建同样支持省略 nodeId，默认布局由系统管理；普通画布编辑和显式整理工具保留。

## 画布工具披露

有画布上下文就提供 storyboard、canvas_create_character、canvas_list_assets、canvas_bind_asset，不再按关键词或是否已有 script 节点解锁。批量表保持既有条件。权限、审批、归属、快照、预算和每步写入限制继续执行。read 只读，其余 action 按写入处理；拆镜异步回执不是已写回。

## 角色媒体来源

角色卡仍使用 current/pinned 版本策略。读取返回实际版本、各表现资源的来源，以及 resolvedImage 表示最终选用的图片角色。主图和三视图可分别指定，单图模式会明确复用；primaryReusesTurnaround 只表示资源相同，不证明图片视觉内容满足三视图要求。

新建角色卡支持 imageNodeId 单图模式，或 primaryImageNodeId/turnaroundImageNodeId 分别指定。来源节点和画布与表现资源一起记录，后端校验所有权和资源匹配。历史没有记录时 sourceStatus=unrecorded；sourceCandidates 只是当前画布中同资源的候选，不自动认定来源。

HTTP `POST /api/characters` 支持 representations 数组，与 imageResourceId 互斥；每项包括 role、resourceId、metadata。metadata 中声明来源时必须同时提供可访问的 sourceCanvasId 和实际指向该资源的 sourceNodeId。角色详情返回这两个来源字段及可选 reusedFromRole，修改表现资源继续使用现有 representations 接口。

## 画布素材留档

可引用节点通过能力合同暴露 usageStatus（active/archived）、usageNote 和 supersededByNodeId。使用 canvas_apply_ops 的 update_node 修改，沿用快照、审批与撤销机制；替代节点必须存在、业务类型一致且不成环。恢复 active 时清理替代项。

用途状态只作用于当前画布节点，不改变素材库全局状态或资源就绪状态。归档不删除文件、节点、标题、任务或已有显式引用；默认候选与搜索排除归档项，搜索历史内容需 includeArchived=true。已有固定版本引用保留，读取会提示归档状态，不自动换用替代版本。

## 视觉观察

候选的 observationStatus 描述未观察、有待验证缓存或已有观察，不强制本轮识图。关系检查直接读取引用；外观判断才请求图片。inspect 回执包含本轮调用额度、剩余额度、模型批次图片数和成本预算。

`canvas_inspect_image({nodeId})` 默认读取该节点图片，有效摘要命中时只返回 `visionCache`、`imageAttached=false`。保存摘要使用同一 nodeId、实际交付回执的 sha256 和 summary；保存操作不附图，图片内容变化后旧摘要失效。

需要重新核对画面时调用 `canvas_inspect_image({nodeId,refresh:true})`，单图可省略 purpose。即使已保存摘要，服务端仍读取资源字节，将真实图片作为下一次模型请求的图片输入；重复读取标记 `repeat=true`，内容SHA相同时为 `imageChanged=false`。显式附图按本次调用单独登记交付，送达一次后不会在每个后续请求中自动重发。每节点本轮最多附图2次；只返回文字的缓存读取计入本轮调用预算，不占真实附图次数。

视觉对比使用 `purpose=compare`，在同批中逐个指定待对比节点；重看已缓存图同样传 `refresh=true`。所有附图继续受模型图片数量、文件大小和成本预算限制。Worker保留模型允许的近期原图，普通历史可用摘要降低上下文开销；显式重看不会被旧摘要替换。附图准备成功不等于识别成功，模型应根据收到的画面作答。

## 终态回执恢复

finish_run 通过后，工具回执、最终答复和终态共同保存。回执包含 committed、runId、finalMessageId。Pi 查询终态时仍须校验用户、模型步骤和调用 ID，优先返回已持久化回执，再通知 Worker 停止；查询不会重新执行工具。活跃运行继续要求有效租约。

下一轮只为缺失的历史 finish_run 补回执。模型消息检查点与模型任务在同一事务中记录精确的会话条目 ID，批次准入时绑定该 ID；恢复同时核对原运行、条目、批次和调用内容，不将后续步骤复用的 callId 认作早前调用成功。补齐只影响模型投影，不重做写入。升级前未保存条目与任务关联的历史调用仍标记未知，不靠内容相同猜测成功。committed 表示已保存、可重放，不表示客户端已经展示或用户已经阅读。

## 后台调用上限

管理员在「资源与策略 → 画布 Agent 执行限制」配置以下字段，保存在 `system_settings.runtime_policy.task`，无需数据库迁移：

| 字段 | 默认值 | 范围 | 生效边界 |
| --- | --- | --- | --- |
| `agentMaxToolCallsPerStep` | 8 | 1–64 | 新工具批次准入 |
| `agentMaxReadToolCallsPerRun` | 32 | 1–9999 | 下一次只读工具执行 |
| `agentMaxStepsPerRun` | 0（不限） | 0–9999 | 下一次模型调用前 |

配置保存、重置均沿用运行策略的缓存失效和管理员审计机制；跨进程缓存约 2 秒刷新。旧配置缺少新字段时取上述默认值。已有请求的 `budget.maxSteps` 仍有效，与后台配置取更严格的非零上限；请求的 0 无法绕过后台的正数上限。

模型调用前由服务端注入 `call_limits` 事实，包含当前实际限制与已累计的只读次数；`mutationCallsPerStep=1` 是独立于总调用数的固定写入/生成上限。固定系统提示不再写死总调用数或初始步数预算。Pi 批次入口与执行状态使用统一策略来源；已接受的批次在配置调低后仍能恢复和幂等重放，后续新批次按新上限检查。

只读次数覆盖画布、分镜、素材、技能与模型查询以及联网搜索；缓存命中不增加累计次数。原生技能 `read` 与画布只读工具共享预算，同一模型步骤重试读取相同技能文件页时不重复计数。单步工具数量包含模型回复中的原生技能读取。图片识别仍使用独立的次数和图片成本预算。

## 同步工具制品

修改工具协议后，从 backend 目录运行 `go run ./cmd/export-agent-tool-schema -output ../agent/harness/TOOL_SCHEMA.json` 导出实际运行时目录，再运行 `node agent/scripts/sync-harness.mjs --tool-descriptions-only` 同步说明。导出命令不启动服务、不连接数据库、不运行测试。
