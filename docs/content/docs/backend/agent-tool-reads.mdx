## 画布读取

`canvas_get_state` 提供 `catalog`、`detail`、`references`、`edit` 四种视图。未指定节点时默认目录；指定节点时默认 detail。只有 edit 返回 editable 和富文本。正文被截断时，`nextRead` 给出 `canvas_read_content` 的实际续读参数，偏移按 Unicode 字符计算。

`connections` 参数为 `none`、`selected` 或 `incident`：默认不附边，子图默认 selected。连线是派生的只读关系；业务输入以引用字段及解析结果为准。`type` 表示底层存储，所有节点均提供 `kind` 表示业务能力，角色卡为 `kind=character`。

## 分镜绑定检查

`canvas_read_storyboard` 默认 `view=creative`，返回创作说明、时长、对白、实际引用的名称/角色版本与就绪状态。`summary` 扫描缺口，`bindings` 排查底层声明；三者默认且最多100行，按结果字节预算分页。`full` 读取高级字段，默认1行、最多20行。可按 `rowIds` 精确选行，与非零 offset 互斥。返回 `rowId` 作为唯一编辑句柄。创作说明和对白超过2000字符时标记截断，并通过 `nextReads` 给出 `canvas_read_content` 的 nodeId、rowId、field、offset 参数；不会靠富文本补正文。

结果显式包含共享 referenceNodeIds、行 assetBindings/characters、图片和视频产物以及有效输入。`mode=image/video` 复用生成的引用解析规则；video 遵守关键帧模式，省略 mode 时仅检查声明引用。

上述底层声明在 bindings/full 中读取，creative 只返回合并后的实际输入，避免重复维护关系图。搜索节点同时返回业务类型标签、可引用状态和角色实际版本；素材库结果有 `scope=library_asset`，其 assetId 只供 `canvas_bind_asset` 替换画布媒体节点，不能直接填进分镜引用。

`coverage` 区分全表规模、选择范围、已检查行数与完整覆盖。只有 complete=true 才支持全表结论。summary 的缺媒体输入、引用无效、资源不可用、状态未知、待迁移和缺输出分别统计；待迁移的旧连线不算作确认空输入。没有镜头产物不代表不能执行文生模式，行级数组为空也不代表共享输入为空。分页按 nextRead 继续，不把未返回字段当作明确为空。

## 分镜创作与生成闭环

`canvas_create_storyboard` 自动分配节点、行 ID 与默认位置。行以 `plotDescription` 维护创作说明，构图、表演、运镜、节拍和连续性可在该字段内组织；独立保留时长、对白与可选图片/视频提示词覆盖。旧细分列仍保存在原行内供界面与高级编辑使用，Agent 不需要逐列填写。已有提示词覆盖优先于创作说明，修改说明不会隐式清空覆盖。

行 `assets` 为 `{ref,role}` 数组，ref 接受当前画布节点 ID 或唯一完整名称，服务端转成现有 `assetBindings` 并校验用途。同名多版本、缺失、归档或用途不匹配时整次拒绝，禁止模糊匹配和猜版本。共享上下文用 `references`；仍可显式使用真实 `referenceNodeIds`。

`canvas_edit_storyboard` 的 update/remove/set_assets 可用 `rowId` 或 `rowIds` 选择目标。update 将同一个 patch 应用于全部所选行；set_assets 完整替换资产声明，同时清空旧 characters，空数组表示清空。共享引用不受清空行资产影响。整批在副本上校验、同一快照提交，一处失败不部分落库；删除镜头同时检查行状态和持久任务占用。回执直接返回真实行身份，审批预览列出所选镜头和资产。

分镜 `generate_media` 只需模式及表/行身份，输入从行读取，自动分配目标和标题、使用项目及模型目录默认值、管理位置并回填产物。已有绑定必须通过原占用规则，省略 nodeId 不会绕开已有任务或产物。身份由运行、模型步骤和调用共同确定，重复 provider callId 不会与另一模型步骤碰撞；审批和恢复复用已解析目标。收费任务继续逐镜受理，价格、预算、资源与审批边界保留，提交失败不触发自动收费重试。

`model_list` 可用 `storyboardNodeId+storyboardRowIds` 批量查询，复用生成解析器和真实资源检查，在同一画布快照上按输入类型、数量及视频时长分组。每组返回一份模型目录，各行保留对应组或问题。角色创建同样支持省略 nodeId，默认布局由系统管理；普通画布编辑和显式整理工具保留。

## L0 / L1 工具披露

L0/L1 描述运行时下发层次，与实施先后顺序无关。基础续读、节点搜索和能力发现常驻；有分镜节点或分镜意图时开放完整业务工具组，并继续按原权限过滤。每个新模型步骤前，边界快照依据当前完整库存和已送达用户插话只增补工具，先以 CAS 持久化，再向 Worker 返回。进行中的模型任务和工具批次保持名单；待送插话、工具回执和其他 Agent 的文本不能开放工具。已交付意图保存为有界工具名，压缩不会使名单缩回。

Worker 的 SDK 白名单预留整份合格目录，只注册已下发的具体工具；新边界才动态登记新增项。Go 模型准入、Worker 真实请求和执行预检使用持久化名单，修复范围仍独立限制执行。工具出现不等于获得新的画布、生成或计费权限。

## 角色媒体来源

角色卡仍使用 current/pinned 版本策略。读取返回实际版本、各表现资源的来源，以及 resolvedImage 表示最终选用的图片角色。主图和三视图可分别指定，单图模式会明确复用；primaryReusesTurnaround 只表示资源相同，不证明图片视觉内容满足三视图要求。

新建角色卡支持 imageNodeId 单图模式，或 primaryImageNodeId/turnaroundImageNodeId 分别指定。来源节点和画布与表现资源一起记录，后端校验所有权和资源匹配。历史没有记录时 sourceStatus=unrecorded；sourceCandidates 只是当前画布中同资源的候选，不自动认定来源。

HTTP `POST /api/characters` 支持 representations 数组，与 imageResourceId 互斥；每项包括 role、resourceId、metadata。metadata 中声明来源时必须同时提供可访问的 sourceCanvasId 和实际指向该资源的 sourceNodeId。角色详情返回这两个来源字段及可选 reusedFromRole，修改表现资源继续使用现有 representations 接口。

## 画布素材留档

可引用节点通过能力合同暴露 usageStatus（active/archived）、usageNote 和 supersededByNodeId。使用 canvas_apply_ops 的 update_node 修改，沿用快照、审批与撤销机制；替代节点必须存在、业务类型一致且不成环。恢复 active 时清理替代项。

用途状态只作用于当前画布节点，不改变素材库全局状态或资源就绪状态。归档不删除文件、节点、标题、任务或已有显式引用；默认候选与搜索排除归档项，搜索历史内容需 includeArchived=true。已有固定版本引用保留，读取会提示归档状态，不自动换用替代版本。

## 视觉观察

候选的 observationStatus 描述未观察、有待验证缓存或已有观察，不强制本轮识图。关系检查直接读取引用；外观判断才请求图片。inspect 回执包含本轮调用额度、剩余额度、模型批次图片数和成本预算。

`canvas_inspect_image({nodeId})` 默认读取该节点图片，有效摘要命中时只返回 `visionCache`、`imageAttached=false`。保存摘要使用同一 nodeId、实际交付回执的 sha256 和 summary；保存操作不附图，图片内容变化后旧摘要失效。

需要重新核对画面时调用 `canvas_inspect_image({nodeId,refresh:true})`，单图可省略 purpose。即使已保存摘要，服务端仍读取资源字节，将真实图片作为下一次模型请求的图片输入；重复读取标记 `repeat=true`，内容SHA相同时为 `imageChanged=false`。显式附图按本次调用单独登记交付，送达一次后不会在每个后续请求中自动重发。每节点本轮最多附图2次；只返回文字的缓存读取计入本轮调用预算，不占真实附图次数。

视觉对比使用 `purpose=compare`，在同批中逐个指定待对比节点；重看已缓存图同样传 `refresh=true`。所有附图继续受模型图片数量、文件大小和成本预算限制。Worker保留模型允许的近期原图，普通历史可用摘要降低上下文开销；显式重看不会被旧摘要替换。附图准备成功不等于识别成功，模型应根据收到的画面作答。

## 终态回执恢复

finish_run 通过后，工具回执、最终答复和终态共同保存。回执包含 committed、runId、finalMessageId。Pi 查询终态时仍须校验用户、模型步骤和调用 ID，优先返回已持久化回执，再通知 Worker 停止；查询不会重新执行工具。活跃运行继续要求有效租约。

下一轮只为缺失的历史 finish_run 补回执。模型消息检查点与模型任务在同一事务中记录精确的会话条目 ID，批次准入时绑定该 ID；恢复同时核对原运行、条目、批次和调用内容，不将后续步骤复用的 callId 认作早前调用成功。补齐只影响模型投影，不重做写入。升级前未保存条目与任务关联的历史调用仍标记未知，不靠内容相同猜测成功。committed 表示已保存、可重放，不表示客户端已经展示或用户已经阅读。

## 后台调用上限

管理员在「资源与策略 → 画布 Agent 执行限制」配置以下字段，保存在 `system_settings.runtime_policy.task`，无需数据库迁移：

| 字段 | 默认值 | 范围 | 生效边界 |
| --- | --- | --- | --- |
| `agentMaxToolCallsPerStep` | 8 | 1–64 | 新工具批次准入 |
| `agentMaxReadToolCallsPerRun` | 32 | 1–9999 | 下一次只读工具执行 |
| `agentMaxStepsPerRun` | 0（不限） | 0–9999 | 下一次模型调用前 |

配置保存、重置均沿用运行策略的缓存失效和管理员审计机制；跨进程缓存约 2 秒刷新。旧配置缺少新字段时取上述默认值。已有请求的 `budget.maxSteps` 仍有效，与后台配置取更严格的非零上限；请求的 0 无法绕过后台的正数上限。

模型调用前由服务端注入 `call_limits` 事实，包含当前实际限制与已累计的只读次数。固定系统提示不再写死 8 次或初始步数预算。Pi 批次入口与执行状态使用统一策略来源；已接受的批次在配置调低后仍能恢复和幂等重放，后续新批次按新上限检查。

只读次数覆盖画布、分镜、素材、技能与模型查询以及联网搜索；缓存命中不增加累计次数。原生技能 `read` 与画布只读工具共享预算，同一模型步骤重试读取相同技能文件页时不重复计数。单步工具数量包含模型回复中的原生技能读取。图片识别仍使用独立的次数和图片成本预算。

## 同步工具制品

修改工具协议后，从 backend 目录运行 `go run ./cmd/export-agent-tool-schema -output ../agent/harness/TOOL_SCHEMA.json` 导出实际运行时目录，再运行 `node agent/scripts/sync-harness.mjs --tool-descriptions-only` 同步说明。导出命令不启动服务、不连接数据库、不运行测试。
