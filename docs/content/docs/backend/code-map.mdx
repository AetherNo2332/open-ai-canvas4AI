# 代码功能地图

## 分镜 Agent 创作闭环

以下 Go 文件位于 `backend/internal/app/`：

- `cloud_agent_storyboard_workflow.go`：名称/ID 精确解析、资产用途转换、批量行副本规划、按运行与模型步骤分配创建身份。
- `cloud_agent_storyboard.go`、`cloud_agent_storyboard_read.go`、`cloud_agent_content.go`：一次快照的创建/编辑/落库，creative/summary/bindings/full 读取及行文本续读。
- `cloud_agent_storyboard_generation.go`、`cloud_agent_storyboard_models.go`：生成目标分配、归属与任务回填，按真实输入和时长合并选模结果。
- `cloud_agent_tool_tiers.go`、`cloud_agent_tool_refresh.go`、`cloud_agent_pi_bridge.go` 和 `agent/src/session-tools.ts`、`runner.ts`：边界单调披露、CAS 持久化与 SDK 动态注册，权限和批次执行继续由 Go 校验。内置 `backend/builtin/canvas-tools-guide` 与共享 schema 同步说明合同。

## 生成素材身份与来源归属

- `backend/internal/app/task_output_assets.go`：任务详情按输出序号解析服务器登记 ID，核对当前用户、资源和项目版本表示；`task_media_assets.go` 登记生成来源、画布名称与确定性素材 ID。
- `backend/internal/app/asset_origins.go` 与 `repository/asset_origins.go`：分页素材按当前用户批量查询画布名称，历史生成素材通过任务查回画布；`canvas/user_asset_client_payload.go` 保留列表所需来源字段。
- `web/src/lib/canvas/registered-generation-output.ts`、`services/project-asset-sync.ts`：复用服务器素材，未登记或资源不匹配时报错，避免随机新建；`lib/asset-origin.ts` 统一资产页来源与归属文案。

## 工作台侧栏动画

- `web/src/components/layout/app-top-nav.tsx`：响应视口、桌面折叠偏好、Motion 宽度/位移与遮罩、移动端 Escape 和焦点恢复；`workspace-sidebar-motion.css` 统一宽度与 flex-basis，隔离旧 CSS 过渡。
- `workspace-sidebar-nav.tsx`：实际导航入口、选中背景、图标反馈、标题/账户文案过渡和分组折叠；共享 `workspace-sidebar-motion.tsx` 保留 Router Link 语义，并管理退出动画中的不可聚焦状态。专项在 `web/test/workspace-sidebar-motion.test.tsx`。

## 摄影机控制前端

- 入口与弹窗：`web/src/components/canvas/canvas-camera-control-popover.tsx`，复用于图片提示词和 `batch-generation-settings-dialog.tsx`；`AppModal` 承载上游的四列卡片面板。
- 四列卡片（相机、镜头、焦距、光圈）、悬停说明、配置摘要与提交：`canvas-node-camera-dialog.tsx`。卡片外层包裹必须保持整列宽度（`HoverTip` 包裹层 `w-full`），否则角标会遮住居中的档位标签、四列宽度也会被内容撑成不等宽。
- 参数枚举、提示词合同与产品图路径由 `web/src/lib/canvas/camera-prompt-library.ts` 维护（9 台相机、10 支镜头，设备目录与文案来自 TapNow 相机控制素材整理）；真实产品图位于 `web/public/camera-controls/cameras`、`lenses`，`web/test/camera-control-assets.test.ts` 校验每个 profile 都有图且目录无孤立文件。生成执行器调用路径不变；界面回归在 `web/test/camera-control-panel.test.tsx`。
- 滚轮切档：`web/src/lib/canvas/camera-wheel.ts` 负责滚轮增量归一化与累计步进（一次事件最多切一档），`canvas-node-camera-dialog.tsx` 用非 passive 原生 `wheel` 监听把四列卡片分别绑定到对应档位，并阻止滚轮同时滚动弹层；回归在 `web/test/camera-wheel-step.test.ts`。

## Agent 工具合同

- 后台导演台预演：`cloud_agent_previs_render.go`（冻结输入、审批与任务回执）、`task_previs_render.go`（执行、资源检查点和原子写回）、`repository/task_previs.go`（租约条件检查点）、`renderer/src`（实际视口、CDP和FFmpeg）。专题见[导演台后台预演](./previs-background)。

- Worker 恢复：`agent/src/runner.ts`、`pi-stream.ts`（当前轮工具恢复、检查点队列与 SDK 错误传播）；`worker-runtime.ts`（共享错误边界与有限上报）；`bridge.ts`（传输分类与实例暂停领取）；`backend/internal/app/cloud_agent_worker_recovery.go`（持久化预算、幂等上报、看门狗）；`backend/internal/repository/agent_worker_recovery.go`（control-only 终态事务与接管保护）。`agent/src/session-history.ts` 保留终结轮次缺失回执的模型投影；`backend/internal/platform/api_call_payload.go` 负责日志 UTF-8 截断。实施合同见 [数据库](./backend-database)、[HTTP API](./http-api) 与 [Pi worker 错误恢复](../../../design/agent-worker-recovery.md)。

- 工具及字段说明：`backend/internal/app/agent-tool-descriptions.md`；目录编译：`cloud_agent_tools.go`；L0/L1 下发过滤：`cloud_agent_tool_tiers.go`（建 run 时按画布库存和封闭意图词表冻结 `AdvertisedToolNames`）；条件参数合同：`cloud_agent_tool_contracts.go`；零副作用预检：`cloud_agent_tool_schema.go`。

## Canary 事件调度

`agent/src/event-scheduler.ts` 管理短时调度槽、画布轮转、会话驻留和事件等待；`server.ts` 启动独立异步会话，`bridge.ts` 对接内部事件 SSE。Go `app/agent_scheduler.go` 提供阶段、控制和异步工具编排；`repository/agent_scheduler.go` 管理持久状态及工具租约，`database/agent_events.go` 保证状态与 outbox 同事务，`model/agent_scheduler.go` 分配提交有序事件。部署与验证入口见 [多会话事件调度](./agent-event-scheduler)。

## 前端页面

## 画布声明式引用

- 旧画布问题定位：`web/src/lib/canvas/canvas-reference-migration-issues.ts` 只读检查声明输入中的缺失节点和自身引用，返回关联所属节点、素材来源和行/字段位置；`canvas-reference-migration-panel.tsx` 展示标题与缩略图并阻止带已识别问题的升级。`project.tsx` 的定位回调关闭弹窗并复用画布聚焦及选择能力；预览资源沿用共享授权 URL 解析，不新增资源接口。此检查仅用于用户提示，服务端引用校验保持不变。

## 后端调用链

```text
HTTP 请求 -> handler -> service（稳定导入面 / 别名）-> app（组合根）-> 业务域包 -> repository/model
                                                                     |
                                                                     -> protocol / payment / generation / outbound
```

`internal/service` 只再导出 `internal/app` 的类型、常量和包级函数，handler/cmd 仍 import `internal/service`。组合根和尚未拆出的业务实现在 `internal/app`。已抽出的域包不得 import `service` 或 `app`（防回环）。共享错误码与 ID/字符串工具在 `internal/kernel`。

## 修改原则

- HTTP 参数与响应只在 handler 处理，业务规则进入 service。
- 页面保留流程协调；可独立理解和测试的算法进入同业务域的 `lib`。
- 新增功能时只更新本页的主要入口，不增加逐文件清单。
