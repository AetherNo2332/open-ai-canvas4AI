title: 导演台后台预演
description: 关闭网页后继续生成白模视频、原子写回画布及异常恢复
---

`previs_preview`冻结当前镜头的场景、机位、动画和已授权资源，创建`previs_render`持久任务。独立renderer运行实际Three.js视口，输出H264 MP4与PNG构图帧。任务worker保存资源并写回最新画布后才给出成功工具回执。用户网页、SSE连接与Pi worker不是渲染执行器。

## 执行与授权

- `auto`沿用当前运行的授权范围；`request_approval`在批准前不提交，批准绑定参数及源输入。拒绝和过期审批不能恢复运行。
- 默认演员模型打包在镜像中；其他模型、背景、billboard必须引用当前用户已导入的资源。无头浏览器只允许该任务的本地服务、data和blob URL，额外HTTP请求会使任务失败。
- 输入时长0.1–60秒，帧率1–60，首版按镜头比例输出360×640、640×360或640×268；输出只包含场景实际对象和动画，不自动产生提示词中描述的特效、配音。
- 任务、资源、画布、Pi run分别记录状态。只有MP4可解码、构图帧合法且画布提交成功才算交付。任务结果中的`outputReady`表示资源已保存，`linked`表示已关联目标镜头。

## 人工介入与异常

普通插话在下一安全边界处理，已提交任务使用原快照。暂停审阅沿用持久`ask_user`等待明确答复，停止后续投递；不会逐帧冻结已运行的Chromium或FFmpeg。立即停止正在渲染的任务应使用单任务取消或run取消。取消决定和有效租约共同阻止迟到写回，已完成节点保留。

Pi崩溃、模型超时、看门狗失败或预算耗尽不撤销此前获准的预演。后台可继续保存和写回，但不会复活失败、取消或拒绝的run，也不会伪造Agent最终回答。关闭网页和登录失效不等同于取消；账号停用、资源或目标失去归属则拒绝执行和回写。

无关画布修改从最新文档合并；目标人物、机位、动画、镜头时长变化或目标被删除时，停止关联并保留已保存的原版本产物。画布大小、配额或数据库冲突也不能用渲染成功代替交付。资源ID在回写前持久登记，稳定节点ID与任务成功在同一事务提交。写回版本冲突最多尝试3次；保存阶段按稳定上传身份对账并有界重试。

renderer并发1，CPU软件渲染，不申请模型推理GPU。Chromium崩溃最多额外渲染1次；确定性模型、数据、权限、编码或回写错误不重渲染。重启先探测已有完整MP4和PNG，再决定是否需要恢复。续租不作为实际进展；帧数或阶段5分钟不变、任务30分钟总超时均停止。

## 原结果恢复

任务中心显示原视频与诊断。失败且已有产物时提供“只回写原镜头”和“保留为独立旧版本”。接口为`POST /api/tasks/:id/recover-previs-writeback`，请求`{"mode":"link"}`或`{"mode":"independent"}`。

恢复建立新操作，保留原失败历史。同方式的排队、运行和成功操作幂等；失败或取消后再次点击会创建新操作，每个原任务每种方式最多8次。`link`仍检查原目标与源输入；`independent`仅在原画布添加明确标记为旧版本的节点，不重建删除的镜头。若只是上传未完成而renderer仍持有完整产物，恢复仅下载、保存和回写；产物过期时明确失败，不偷偷启动新渲染。需要扩大范围、换画布或重新渲染时，应通过新的用户授权任务执行。

## 部署与资源边界

在正常部署Compose上叠加`docker-compose.previs.yml`，设置独立的至少32字符`CANVAS_PREVIS_RENDERER_TOKEN`和renderer镜像。后端运行镜像需有`ffprobe`。renderer无宿主机公开端口，仅连内部网络，资源限制2CPU、2GiB内存、256进程/线程、256MiB共享内存，持久卷保存受控任务产物。启用init回收孤儿进程；浏览器结束按本任务profile和进程组清理子进程。

镜像固定Node22.19.0、Alpine3.22、Chromium与chromium-swiftshader142.0.7444.59-r0、FFmpeg6.1.2-r2。生产目标从冻结的前端lockfile构建；本地`tools/build-previs-runtime.ps1`可复用刚验证的实际Vite构建，减少验证上下文。浏览器脚本、密钥及私密素材不进入用户诊断。

最多保留16个未确认持久保存的renderer任务，到达容量时明确`renderer_busy`；后端两资源完成检查点后发owned ack释放中间产物与容量，上传未完成的终态产物6小时回收。单任务素材总量64MiB、MP4最大128MiB、帧暂存最大1GiB。已保存但未关联资源由任务租约保护24小时，视频和构图帧也纳入任务结果的持久引用，租约过期后不会被孤儿清理当成无引用产物。关闭网页后重新打开，以服务器画布和任务为准，不重新触发录制。

隔离验收使用`docker-compose.previs-test.yml`，只读挂载当前renderer源码，不复用生产数据、端口或容器。测试后端通过`tools/previs-go-test.Dockerfile`使用renderer已安装的FFprobe及配套动态库，仍在后端独立探测下载的真实MP4。生产升级需另行核对版本、完整锁文件镜像构建、在途任务、CPU/存储及回退兼容性；旧后端无法执行新增任务类型，回退前必须停止新投递并处理在途预演。

## 本地验证记录（2026-10-08）

Linux隔离Compose在没有用户网页和Pi模型进程的情况下完成三镜真实任务，保存3个H264 MP4、3个PNG、6个资源及6个画布节点。各片为360×640、4帧、500ms；三镜合计92.28秒，属于短片正确性验证，不是长片吞吐结论。第三镜期间注入Pi失败并运行清理，渲染仍完成，Pi保留失败终态。

另一真实任务在冻结后修改目标机位，资源保存后拒绝关联画布；还原目标后执行只回写恢复，视频与预览资源ID保持不变，渲染次数为1，原任务仍保留失败历史。Node12项测试包含真实演员、体块、相机运动、起末帧像素变化及执行后无本任务浏览器进程残留；web全量2189项、Agent全量157项和Go预演/资源/接口专项通过。

完整锁文件生产镜像构建、目标服务器性能、真实模型/Pi进程故障和用户页面重开播放仍需验证，详见[待测试清单](/docs/progress/pending-test)。本轮仅本地实现与隔离测试，未更新生产3000，也未给原生产画布生成媒体。
