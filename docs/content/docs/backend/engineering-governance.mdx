## 变更边界

app 是组合根，域包不得反向导入 app、service 或 handler；沿已有 platform、agentcontext 等边界提取真实策略。新包应减少跨层知识，而不是只把文件搬家。公共 HTTP 以 OpenAPI 与注册路由核对，内部 Agent wire 是独立合同。工具定义继续以 Go 目录为源，通过共享制品和 Pi 校验验证；不能另建一份人工工具名单来判断运行成功。

历史问题登记精确位置和规则，新增问题应被检查拒绝。修复后减少 baseline，不能通过重新生成 baseline 接纳新增违规。依赖升级需跑真实入口的定向合同测试；Agent 记忆、压缩与恢复设计按独立方案管理，不在本轮治理中改写。

## 上游采纳

上游是 `ddcat-ai/open-ai-canvas`，本 fork 是 `AetherNo2332/open-ai-canvas4AI`。每次调查记录两端完整 SHA，按数据正确性、安全、协议、交互和架构分组，逐项决定移植、不适用或待评估。具体起始台账见[上游采纳台账](../../../design/upstream-adoption-ledger.md)。独有提交数、文件交集或同名函数不能证明缺陷存在；应沿当前调用链验证。

实际移植在隔离分支完成，记录源提交、落地提交、真实冲突与语义选择。优先移植小型修复；工具披露、事件调度和租约已分叉的部分重新适配，不整库自动 rebase。没有发生移植时，不能填写“已移植”。

## 发布证据

1. 记录目标提交和根 VERSION。内部版本与正式 tag、镜像 tag 必须来自同一发布基线，更新日志写用户可见行为与迁移影响。
2. 检查 CI 与独立审查，明确未执行的环境验收。正式发布确认三份镜像、updater 二进制、校验清单与 Compose 资产均属于目标版本。
3. 在隔离环境安装，检查迁移、backend 健康、Agent 就绪、一次实际工具写入及持久化终态，再演练升级和回退。静态解析、进程在线与模型成功是不同证据。
4. 生产操作前复盘计划、数据备份、停机窗口与回退目标。真实升级和回退应记录实际输出，失败时保留脱敏日志；不得把未执行的演练标记为完成。

## 维护交接

交接材料应含仓库与发布权限的受控入口、环境配置字段说明、数据与备份职责、安装更新命令、报警定位及恢复步骤。正文不存 Token、Cookie、密码或生产 DSN。接手者在不依赖原维护者逐步指导的条件下完成隔离演练，记录遇到的缺口并修订 runbook。仓库文档和 CI 只能降低接手成本；实际人员、权限和演练记录才能证明维护能力已交接。
