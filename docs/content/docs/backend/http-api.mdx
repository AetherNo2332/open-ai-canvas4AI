# HTTP API 合同

## 画布实时会话

`GET /api/canvas-projects/:id/realtime` 使用登录 Cookie 升级为 WebSocket，握手校验当前用户对画布的归属和请求 Origin。首帧 `welcome` 提供服务端分配的 `selfId` 和窗口 Presence；客户端发送 `presence`，服务端推送 `peer`、`leave`、`invalidate`、`canvas_changed`、`agent_presence` 和 `heartbeat`。Presence 只含有界世界坐标和拖拽矩形，不包含密钥、编辑租约 token、画布正文或实际保存指令。

产生新 revision 的画布写入（浏览器保存与 Agent 写入共用同一序列）在事务提交后推送 `{"type":"canvas_changed","revision":<int>,"actor":"agent"|"browser"}`；同一事务多次写入只推送最终 revision，回滚不推送。租约、删除和任务准入等不产生 revision 的变化仍推送 `invalidate`。`agent_presence` 为 `{"type":"agent_presence","agent":{"runId":"…","nodeIds":["…"],"phase":"reading"|"editing"|"idle"}}`，由服务端在 Agent 工具读写节点前发出、运行结束时发 `idle`，最多 100 个节点 ID，只用于界面提示，不持久化，也不能由客户端发送。

`invalidate` 在事务提交后发送，客户端通过 `GET /api/canvas-projects/:id/sync-status` 校验版本与租约，再按需读取正文；长连接不代表云端保存成功。正常且无活动 Agent 时每 30 秒补偿查询，断线或活动 Agent 期间使用原有轮询。未登录返回 401，画布缺失或不属于当前用户返回 404，不允许的来源返回 403，实时服务不可用返回 503。完整协议和部署边界见[画布操作同步](./canvas-operations-sync)。

## 视频工作台的生成模式

`POST /api/workbench/tasks` 的视频任务根据已校验的 `references` 推导操作类型，客户端不需要提交泛化的 `video` 操作：

| 输入 | 操作 |
| --- | --- |
| 无媒体素材 | `text_to_video` |
| 仅首帧或尾帧图片，可附带音频 | `image_to_video` |
| 普通参考图、参考视频，或包含普通参考图的组合 | `reference_to_video` |
| 仅音频 | `audio_to_video` |

图片的 `role=first_frame/last_frame` 表示帧约束；`reference` 或未指定角色表示普通参考，不能静默改成首帧。模式、素材数量和参数共同参与模型能力校验及价格档选择；不支持的组合在创建任务和计费前拒绝。执行输入的 `metadata.videoEditOperation` 与任务操作保持一致，并保留帧素材标识。浏览器自定义渠道的工作台任务使用同一模式规则，其他入口沿用各自的意图解析。

## 图片响应格式

渠道模型的 `capabilityConfig.image.responseFormat` 包含 `supported` 和可选的 `default`。默认值为 `auto`，表示请求中不发送 `response_format`，由上游决定返回 URL 或 Base64；`b64_json` 和 `url` 会分别强制发送对应值。该配置按模型保存，不根据 `openai-image` 协议名称自动推断，避免兼容网关不接受 Base64 时生成失败。需要持久化 Base64 结果的模型（例如已验证的 ddcat 图片模型）应将默认值设为 `b64_json`。

## 用户登录日志

菜单“用户与运营 → 用户登录日志”，页面 `/admin/login-logs`。查询在 service 校验管理员权限：匿名 401、普通用户 403。

- `GET /api/admin/login-logs`：支持 `keyword`（用户名、昵称、脱敏账号或用户 ID）、`event=login|logout`、`method=password|email|sms|linuxdo|verification|unknown`、`result=success|failed`、精确 `ip`、RFC3339 `from/to`（含边界）、`page/pageSize`。开始时间不能晚于结束时间。默认每页 20 条、时间倒序；成功 `data={logs,total,page,pageSize}`，空结果 `logs=[]`。
- `GET /api/admin/login-logs/:id`：成功 `data={log}`；不存在返回 404。包含用户快照、时间、事件、来源、方式、IP、UA、安全原因码/文案和非凭据的关联会话标识。

后端在密码、邮箱/短信验证码、Linux.do 登录、注册后自动登录及主动退出的真实认证路径记录，不提供客户端任意新增日志接口。`verification` 表示凭据/请求无效导致方式无法识别；`unknown` 表示上线前会话未保存方式。`source=registration` 标记注册自动登录。退出失败不清 Cookie，不再忽略撤销错误。刷新状态和会话自然过期不新增事件。浏览器/系统由页面根据 UA 展示，无法识别时明确标注；UA 是客户端自报信息。

## 个人信息

所有 `/auth/profile` 路径均要求当前活动用户的登录 Cookie，不能通过用户 ID 修改他人资料。

| 路径 | 入参与结果 |
| --- | --- |
| `GET /auth/profile` | 返回 `user`、`hasPassword`、`emailEnabled`、`linuxdoEnabled` 和可选 `reauthenticatedUntil`；密码散列、头像图片正文、内部缓存版本均不在用户 JSON 中 |
| `PUT /auth/profile/avatar` | multipart `file`，只接受真实 PNG/JPEG、最大 5 MiB；返回 `{ user }`，包含带版本的头像地址 |
| `DELETE /auth/profile/avatar` | 清除个人头像并明确选择系统默认头像；第三方重新登录不会覆盖该选择；返回 `{ user }` |
| `POST /auth/profile/avatar/default` | `{ preset }`，只接受 `person/director/camera/cat/rabbit/robot/rocket/sparkles`；保存选择并清除个人图片，返回 `{ user }` |
| `GET /auth/profile/avatar/:userId` | 只读取本账号的 PNG，`Cache-Control: private, no-store`；账号之间拒绝读取 |
| `POST /auth/profile/password` | `{ currentPassword, newPassword }`；新密码至少 8 个 Unicode 字符、UTF-8 不超过 72 字节；返回 `{ changed: true }` 并清除 Cookie、撤销全部会话 |
| `POST /auth/profile/email-code` | `{ email, currentPassword }`；向未占用的新邮箱发送验证码，返回 `{ ticket, expiresIn, retryAfter }` |
| `POST /auth/profile/email` | `{ ticket, emailCode, currentPassword }`；验证后更新邮箱及验证时间、撤销全部会话并清除 Cookie；返回 `{ changed: true, notificationStatus }` |
| `GET /auth/profile/linuxdo/start` | 纯第三方账号重新核验身份的入口；绑定原用户和原会话，成功回到 `/settings?section=profile&reauth=success`，失败回到该页的 `reauth=error` 状态 |

已有本地密码的账号必须验证当前密码。纯 Linux.do 账号设置密码或更换邮箱时，必须先完成同一会话内的重新授权，核验必须匹配原第三方用户标识；有效期为 5 分钟。邮箱验证码用途固定为 `profile_email`，绑定当前会话与凭据状态，6 位数字、10 分钟有效、最多 5 次核验；收件地址跨场景共享 60 秒发送冷却、每小时 5 次和每天 20 次额度。发送失败明确报错；邮件服务未启用时禁止更换邮箱。

新邮箱验证之前保留原绑定。更新及验证码消费、登录会话撤销一起提交，唯一性检查在事务内重复执行。更新后向原邮箱发通知，`notificationStatus` 为 `sent`、`failed` 或 `not_needed`；`failed` 表示邮箱已更新、原邮箱通知失败，不能把已成功更新显示成未保存。接口使用现有业务错误信封和限流规则，密码、验证码和 ticket 不进入 URL。

上传头像先通过共享裁剪弹窗选择 1:1 区域，支持拖动、缩放裁剪框、键盘调整与重置；确认后导出最大 512×512 的 PNG 到待保存预览，点击“保存头像”才上传。取消裁剪保留原头像；待保存图片可重新调整裁剪。选择系统头像使用现有 AppModal、Avatar 与主题 token，支持 8 个预设，确认后才写入服务端。


## 用户反馈

所有反馈接口使用登录 Cookie 和标准业务信封。普通用户只能提交反馈、上传附件和读取本人列表；`/api/admin/feedbacks` 下的写入与全量列表由 service 强制校验管理员权限。

| 接口 | 入参与结果 |
| --- | --- |
| `POST /api/feedbacks` | `{ type, title, content, contact?, attachments?, environment? }`；类型为 `bug/feature/improvement/other`，标题最多 200 个 UTF-8 字节、正文最多 10000 个 UTF-8 字节。附件和环境字段是 JSON 字符串；返回 `data` 反馈记录 |
| `GET /api/feedbacks/my` | 返回当前账号自己的反馈列表，按创建时间倒序，包含处理状态、管理员答复与归档标志 |
| `POST /api/feedbacks/attachments` | multipart 字段 `file`；支持 PNG/JPG/JPEG/WebP/GIF/BMP 与 MP4/WebM/MOV/AVI/MKV，单文件最大 50 MiB，请求体最大 55 MiB；文件通过现有资源服务保存，返回附件元数据 |
| `GET /api/admin/feedbacks` | 支持 `type`、`status`、`keyword`、`archived`、`page`、`pageSize`；默认每页 20 条，`pageSize` 超过 100 时使用默认值。返回 `data={list,total,page,limit}`，按创建时间倒序 |
| `PATCH /api/admin/feedbacks/{id}` | 可更新 `status=pending/processing/resolved/closed`、`adminReply`、`archived`；返回更新后的反馈记录 |
| `POST /api/admin/feedbacks/{id}/archive`、`POST /api/admin/feedbacks/{id}/unarchive` | 归档或恢复历史反馈，返回更新后的反馈记录 |
| `DELETE /api/admin/feedbacks/{id}` | 删除反馈记录，返回 `data={ok:true}` |



## KM 图片尺寸能力

图片能力 `size.presets[].tier` 在已有档位之外接受 `1.5k`；前端档位选择、请求归一化与服务端预设校验保持一致。`km-kemei-seedream` 默认 `2048x2048`、单次一张、最多十张参考图，提供二十四个精确尺寸。透明输出使用插件扩展字段，不开启宿主通用透明背景开关。模型能力仍保存在现有 JSON 字段，无数据库迁移或新端点。

## 注册邮箱等价检查

公开注册与邮箱绑定的唯一性检查将 `gmail.com` 和 `googlemail.com` 视为同一域，移除本地部分的点及 `+` 后缀。例如 `a.b+x@googlemail.com` 与 `ab@gmail.com` 不允许创建两个账号。其他域保留点和 `+`；现有域名白名单规则保持不变。

邮箱原值仍按原有小写、去首尾空格规则保存。登录、密码重置、验证码收件地址保持精确邮箱匹配，避免既有重复别名账号被合并或错误授权。已存在的重复账号不迁移、不删除、不重新发放注册奖励；它们会阻止相同规范信箱的新注册。写入前在事务内重新检查，以覆盖不同实例使用不同验证码的并发注册。无数据库结构迁移；唯一性由公开注册与绑定的事务入口保证，直接 SQL 写入不属于该约束入口。

## 分片上传配额

`POST /resources/uploads` 在接收分片前预留整个文件的日额度和账号容量。文件大小必须严格小于 `resourceUploadMB`；同一账号最多 32 个未到期会话，跨后端实例共同计数。未满足配额的请求不会创建分片目录。分片和完成请求按会话串行执行；会话过期或已完成返回 404，重新创建会话后可整传重试。

完成上传时以数据库事务提交容量并消费预留，使用既有资源幂等标识。失败释放预留；跨 UTC 日期完成需要通过当天日额度检查。请求与响应字段不变。

## 存储容量与只读

账号有效文件容量 = 后台全局 `storedFileGB` + 当前生效的存储扩容（支付购买或管理员赠送，多笔叠加、各自到期）。

`GET /api/resources/storage-usage` 返回 `{ usage }`：

| 字段 | 说明 |
| --- | --- |
| `usedBytes` / `totalBytes` | 已用与有效总容量 |
| `baseBytes` / `purchasedBytes` | 全局基础容量与生效扩容合计 |
| `nextExpiresAt` | 最近一笔有期限扩容的到期时间，可为空 |
| `overLimit` | `usedBytes > totalBytes` |
| `overLimitSince` / `readOnlyAt` | 首次观察到超额的时间及其 7 天后进入只读的时间 |
| `readOnly` | 宽限期已结束且仍超额 |

该接口每次实时计算，并刷新本实例的只读判定缓存（15 秒），所以用户删除素材或扩容后刷新用量即可解除限制。

超额后的行为：

- 宽限期内：上传、分片上传、生成资源落库和媒体生成任务准入返回 `storage_capacity_exceeded`，其它写入照常。
- 宽限期结束：`/api` 下的非 GET 请求先经过只读守卫，返回 HTTP 403、`code=40302`、`reason=storage_read_only`。放行的请求：所有 `GET`/`HEAD`/`OPTIONS`/`DELETE`；路径前缀 `/auth/`、`/payments/`、`/wallet/`、`/admin/`、`/settings/`、`/diagnostics/`、`/model-catalog/`；以及 `POST /assets/batch-delete`、`/assets/batch`、`/resources/access`、`/announcements/read`、`/models/available`、`/models/:id/quote`、`/ai/models`、`/runninghub/*-info`、`/canvas-projects/:id/edit-lease`、`/feedbacks`、`/feedbacks/attachments`、`/tasks/:id/{cancel,query-provider,recover-media,text-deltas,text-replay-complete}`、`/agent/runs/:id/cancel`、`/dramas/:id/pause`、`/creation-runs/:id/{release,heartbeat}`。新增的写接口默认受只读约束，确需放行时在 `backend/internal/handler/storage_guard.go` 登记。

扩容相关接口：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/resources/storage-grants` | 当前用户的扩容记录（含已到期、已撤销），最多 100 条 |
| GET | `/api/admin/users/:id/storage` | 管理员查看用户有效容量（不写入超额状态）和扩容记录 |
| POST | `/api/admin/users/:id/storage-grants` | 管理员赠送，请求 `{ "bytes": 10737418240, "durationDays": 30, "note": "" }`；`bytes` 必须是整 GB，`durationDays=0` 为永久；写管理员审计 |
| POST | `/api/admin/storage-grants/:id/revoke` | 管理员撤销，请求 `{ "reason": "线下退款" }`，原因必填；写管理员审计 |

存储空间商品与积分商品共用 `/api/payments/*` 和 `/api/admin/payments/products`。商品和订单增加 `kind`/`productKind`（`credits`|`storage`）、`storageBytes`、`storageDurationDays`。`/payments/providers` 与下单不再要求积分功能；积分功能关闭时，`/payments/products` 只返回存储空间商品，积分商品下单返回功能未开启。商品类型创建后不能修改。

## AutoDL 视频画面规格配置

渠道模型的 `capabilityConfig.video.resolutions` 与 `defaultResolution` 直接表示所选完整分辨率与默认值，始终生效；不再使用或返回 `customSizeEnabled`、`customScreenSpec`。AutoDL v2.3.0 未声明独立比例参数，因此 `ratios` 为空、`defaultRatio` 为空字符串，横竖与方形由完整分辨率标签表达。

服务端返回 `fixedScreenSpec` 供前端展示插件预设；写入时重新读取官方插件的当前工作流规格，不信任客户端传入的固定值。上游模型 ID 原样透传为 AutoDL 工作流 ID：插件 v2.4.0 已声明的工作流使用各自预设，未声明的 ID 使用清单 `*` 工作流的默认预设（`480p竖/768p竖/960p竖/480p横/768p横/960p横`，默认 `768p竖`）。所选列表可包含预设外的自定义标签（最多 32 个，每个不超过 40 个字符），必须非空，默认值必须属于所选列表；与预设大小写不同的值归一化为插件原始标签，自定义标签按输入保存，发送时统一转小写。任务创建在价格选择前清空无效的 `size`、归一化 `vquality`；自动选择使用配置的默认值，不支持的显式选择被拒绝。价格档可保留全部插件预设，但任务和模型目录只采用所选列表。数据库继续使用现有能力 JSON 字段，无新增表或迁移。

路径前缀是 `/api`。前后端一起发布，不按 `/api/v1`、`/api/v2` 做路径版本。不兼容变更随版本一起改接口和调用方。

机器可读规范：运行中的 `GET /api/openapi.yaml`，源文件 `backend/internal/handler/openapi.yaml`。前端 TypeScript 仍走 `web/src/services/api` 的 `http`，不从 OpenAPI 生成客户端。

出站模型服务域名解析失败返回 HTTP / `code: 502`、`reason: upstream_dns_failed`，不归类为用户参数错误。公开消息不包含上游域名、DNS 服务器或请求 URL；原始解析错误仅保留在内部错误链。此分类不会自动重试、切换渠道或放宽 SSRF 校验；上下文取消仍按取消处理。

模型 HTTP 失败及经过 Provider 错误转换的业务失败，在通用提示后追加经过过滤的 `；上游：具体原因`，供任务错误和画布卡片展示内容安全、提示词、尺寸等可操作信息。只读取上游 `error` / `message` / `msg` / `detail` 消息字段，不回传整个 JSON；消息中的 HTTP(S) URL 隐藏，包含余额、账务、凭据、请求诊断或 HTML 的消息不追加原文，保留通用分类提示。后台响应拦截规则仍对最终用户文案生效；不会修改历史任务错误或改变重试、退款策略。

## 资源访问与 OSS/CDN 分发

普通上传、分片合并及 URL 导入按内容签名识别 MIME，不以客户端声明或文件扩展名决定媒体类型；无法识别的内容仍可作为附件上传。上传标识对应的 ready/failed 重试均先读取内容，并核对检测后的 MIME、资源类型与大小；不一致返回 409，不覆盖原对象。这是内容判型与元数据一致性校验，不是完整格式解码或内容摘要去重。

非媒体文件（包括可执行脚本的 SVG）通过平台本地读取或代理交付，强制 `Content-Disposition: attachment` 与 `Content-Security-Policy: sandbox; default-src 'none'`，不向浏览器或访问描述返回其 OSS/CDN 直链。普通图片、音频及视频保持原有媒体分发规则。历史资源不在本次变更中批量重新判型。

资源展示、播放、下载、复制地址和模型输入统一消费资源访问合同，不在客户端通过 `direct=1`、`proxy=1` 或存储厂商规则选择出口。

- `POST /api/resources/access` 要求登录，请求体为 1–100 项 `{ resourceId, purpose?, variant? }`。`purpose` 支持 `display`、`copy`、`download`、`browser-process`、`provider-input`；`variant` 支持 `original`、`playback`、`thumbnail`（缩略图未生成前回落原件，`fallbackReason` 为 `thumbnail_not_ready`）。每项独立返回 `access` 或结构化 `error`。
- `access.delivery` 为 `cdn`、`origin`、`platform-local` 或 `platform-proxy`。媒体配置了可用 CDN 时返回 CDN 地址；OSS 源站签名是源站直连，不等于 CDN。媒体的 `requireCDN` 开启且 CDN 鉴权不完整时失败，不静默回源。浏览器媒体的展示、复制、下载和本地处理不使用 `platform-proxy`，正文由 OSS/CDN 直接发送；`allowPrivateProxy` 允许服务端在 `provider-input` 场景读取私有媒体源站。非媒体附件始终通过平台控制响应头，不受上述媒体直连规则影响。
- `expiresAt` / `refreshAt` 只描述当前授权有效期。有效期来自后台「资源与请求策略」（`provider-input` 与其余签名访问分别配置，默认均为 4 小时）；公开 CDN 可没有 `expiresAt`。签名地址不写入画布或服务端持久化内容。
- `display`、`copy`、`browser-process` 的源站签名把签名起始时间对齐到有效期 1/4 的时间窗（按 Unix 纪元对齐），过期时间为窗口起点加有效期：同一窗口内重复签发得到逐字节相同的 URL，刷新画布或多实例签发都能命中浏览器 HTTP 缓存；签名同时携带 `response-cache-control=private, max-age=<有效期>, immutable`，由对象存储回写缓存头。`download` 与 `provider-input` 仍按当前时间签发，不带缓存覆盖。
- `GET /api/resources/:id/file` 仍是稳定平台入口，负责本地/平台代理字节流，可直连的云媒体返回 307 到 CDN 或对象存储，非媒体附件走平台流；`?access=1` 只返回访问描述，不打开正文。`Range` 只影响字节流路径。
- 公共资源、画布分享、外观、公告、管理员资源和日志媒体复用同一个 HTTP 执行器。公共签名链接受自身到期时间和变体绑定限制，但已签发的外部 URL 不承诺立即撤销。

当前自动签名能力：公开 CDN、七牛私有下载签名和对象存储源站签名。阿里云/腾讯云私有 CDN 签名尚未自动支持，不能仅填写 CDN 域名就宣称已命中 CDN。真实 CORS、Range、CDN 命中率及账单收益必须在实际云环境通过浏览器网络记录和服务端流量观测验收。

## AI 拆图视觉规划输入

文本生成任务的 `metadata.edit = "layer-planning"` 使用图片参考时，服务端从当前用户归属的就绪资源读取实际像素并转换为内嵌图片，清除附带的旧 URL。图片数量与字节数沿用文本模型能力及资源读取上限；不允许其他用户资源或客户端内嵌内容替换资源文件。普通生成的签名 URL 策略保持不变，任务端点、账务与数据库结构沿用已有合同。

## 画布资源完整性与 operations 写入

`PATCH /canvas-projects/:id/operations` 每次接受 1–500 条操作。前端超限变更按原顺序分批提交，每批发送前保存准确的请求 ID、请求正文和未提交操作；只有全部确认并读回后，界面才标记整份画布已保存。响应丢失时重放同一批 ID 和正文，依靠服务端事务回执去重；冲突停止在当前批，不放宽字段基线。大变更由多笔事务组成，中途失败可能已有部分批次落库，本地仍保留完整待提交快照与后续操作，不能将部分成功显示成全部完成。

画布 operations 应用前校验当前文档中的资源引用；引用须属于当前用户且处于 `ready`。引用收集器递归遍历受支持的资源字段，因此 `nodes[节点 ID].metadata.videoPreview.storageKey` 等嵌套派生封面也会参与检查。维护写入会保留必要的损坏文档审计信息；若资源在事务期间缺失或状态变化，事务回滚，画布 revision 不递增。

HTTP 409 不能一概解释为并发冲突：对象或字段基线冲突使用 `reason: conflict`；资源完整性失败使用 `reason: canvas_history_resources_missing`，并在 `details` 中返回 `resourceIds` 和 `missingResources`（含资源 ID、JSON 路径、节点 ID、引用类型及 `source`）。客户端应按 `reason` 分流，不解析 `msg` 猜测原因。普通 operations 不会绕过资源校验或 revision 语义，维护修复也不能把缺失主媒体写回为有效画布。

运维扫描/修复仅处理当前画布中可安全清除的失效 `videoPreview`；不删除主媒体、不扫描并改写所有维护记录，也不替代备份。使用目标数据库对应的新版本二进制，先在维护窗口备份并执行只读扫描：

```sh
CANVAS_BACKEND_DATA_DIR=/明确的数据目录 ./migrate-schema repair-canvas-resources
```

复核 JSON 报告后，只有 `repairable` 项可由明确授权的操作员再次运行 `repair-canvas-resources --apply`。命令要求显式配置 `CANVAS_BACKEND_DATA_DIR` 或 `DATABASE_URL`，逐画布按当前 revision CAS 保存并保留维护审计记录；有未解决主媒体/素材绑定问题时以非零退出，不会自动重传或重建节点。发生并发编辑时停止并重新扫描，不能用整批快照替换或绕过 operations 校验。

## 生成成功后的重试保存

`POST /tasks/:id/recover-media` 无需请求体。当前用户只能恢复自己有保存恢复记录的失败任务；重入队仍返回原任务 ID，不请求重新生成、不新建计费订单。已排队、运行或完成时幂等返回当前任务。取消任务、已退款订单、任务/账单归属不一致、项目已删除或归档时拒绝恢复。

管理员接口 `POST /admin/api-logs/:id/recover-media` 按请求日志关联的任务重新排队保存作品（图片、视频、音频），不重新生成、不新建订单，不受用户手动次数限制，并重新给满 20 分钟自动重试窗口；写管理员审计 `api_log.recover_task_media`。请求体可选 `{"refundedBilling": "charge" | "waive"}`：原订单已退款时必须提供，`charge` 在作品保存成功后从可用余额补扣（余额不足会变为负数），`waive` 保持已退款；订单未退款时忽略该字段，成功后按原订单结算。响应 `data.task` 为任务摘要。

生成作品直传平台对象存储失败或该存储处于熔断时，作品先保存到服务器并继续登记、结算，任务状态为成功；请求日志依次出现失败的 `upload`（错误文案附存储错误码，如“上传 OSS 失败（存储返回 SlowDownWrite/503）”）和成功的 `local_fallback`，后台补传写 `offload` 阶段日志。`GET /admin/storage/stats` 的 `data.stats.offload` 返回待补传数量、字节数、最早时间、最近错误码和本地文件丢失数。

冻结积分自动退回不处理“上游已确认生成作品”的订单：任务带作品恢复记录，或诊断为结果保存失败时跳过，等待作品交付后结算或由管理员处理。

任务详情和摘要新增 `mediaStage`、`canRecoverMedia`。后者表示失败任务存在保存恢复记录，实际操作仍校验权限、账单、项目及重试额度。每任务最多手动恢复三次，两次之间至少一分钟，每次手动操作只执行一次保存尝试；接口另受用户维度任务请求限流约束。普通 `/tasks/:id/retry` 不接受带保存恢复记录的任务，避免误走重新生成。

保存网络故障在原 worker 中最多自动重试四次（15 秒、1 分钟、3 分钟、10 分钟并加抖动；超过 20 分钟不再安排自动重试），使用 `next_poll_at` 释放 worker，而不是在请求内睡眠。不可重试错误直接保留为保存失败。画布和任务中心显示“作品已生成，正在保存”或“作品保存未完成”，失败按钮为“重试保存”。完成后客户端消费原任务的结果。

请求明细保留上游生成与结果下载的独立状态，新增 `upload`、`local_save`、`register` 内部非计费明细；列表和详情通过 `mediaStage` 展示交付摘要。`recordType=request` 排除这些保存明细和下载，`all` 查看全部阶段，`download` 仍仅查看下载。视频下载失败不会再覆盖生成请求的成功记录。

此恢复能力接入声明式媒体协议返回 URL/data URL 的任务路径；旧协议自行下载、协议二进制下载端点以及无恢复记录的历史失败任务不自动补录。历史任务需先核实上游结果可用性、资源归属及原账单，再单独制定修复动作。

## 素材读取合同

素材详情、批量读取、分页列表和用户数据快照统一返回完整素材记录。`id`、`kind`、`title`、分类、状态和主版本以素材表列为准；媒体内容保留在 `data` 中。项目上传资源转换为素材时即写入该合同，媒体大小使用 `data.bytes`；只有存储键的媒体仍返回字符串类型的 `url`（图片为 `dataUrl`），可以为空，由 `storageKey` 定位资源。

已有项目上传素材的资源元数据在读取时组装为同一合同，真实大小从已记录的 `size` 映射为 `bytes`。该过程不创建新素材 ID，也不为缺少资源定位或真实文件大小的素材伪造有效数据。

## 素材彻底删除

`DELETE /assets/:id` 表示用户确认后的彻底删除，不依赖服务端当前记录是否已经同步为 `archived`。接口仍校验登录用户和素材归属，但不会因画布、任务、项目或历史快照仍有引用而拒绝；事务会删除素材及对应历史资源索引，并通过删除 Outbox 清理未被其他素材复用的物理对象。其他素材共享的同一物理对象继续保留。移入回收站仍通过素材写入接口把状态更新为 `archived`，不能用 DELETE 代替可恢复归档。

素材页及素材选择器的批量彻底删除、清空回收站统一调用 `POST /assets/batch-delete`，请求体直接为 JSON 数组（不是 `{ ids: [...] }`）：

```json
["asset-1", "asset-2"]
```

- 每次 1–1000 项，单个请求体最多 256 KiB；ID 去除首尾空白并去重，空 ID / 非数组返回 400，任一 ID 不存在或不属于当前用户返回 404，整批不删除。
- 成功信封 `data.ids` 为请求传入的数组。前端等待服务端成功后一次更新本地集合并冲刷持久化；失败不回退为逐条 DELETE，不先移除本地记录。
- 整批素材、版本、表现、业务关联、待删资源及对应历史资源索引，与物理删除 Outbox 在同一数据库事务中提交，数据库失败整批回滚。共享检查排除整批被删素材，避免两条互相共享的选中素材残留文件。
- 物理空间由后台删除队列异步释放，失败保留任务重试；接口成功不代表对象存储已经清理完成。未选中素材使用的资源，以及其他 Resource 行（包括其他用户）复用的物理对象继续保留。
- 旧画布 / 任务 / 历史快照记录本身保留，但被删媒体链接将失效。此操作不可恢复；没有数据库结构迁移。

## 密码登录限流

`POST /auth/login` 保留 IP 总请求限制与十分钟账号请求限制。同一 IP 下，用户名和邮箱解析为同一用户时共享账号计数；不存在的账号仍按去除首尾空白、转小写后的输入计次。错误密码与不存在的账号使用相同的 401 响应，达到限额后均返回 429，不返回限流键或用户身份。计数仍涵盖所有登录请求，成功不清零。

## 注册服务协议

`POST /auth/register` 的 JSON 请求必须携带布尔值 `acceptedTerms: true`，首次创建管理员也适用。缺省、`false` 或 `null` 均按未同意处理，在创建用户、消费验证码和创建会话前返回 HTTP 400，提示 `请先同意<协议名称>`。原有注册开放、邮箱白名单、验证码与限流校验继续生效。

`GET /auth/linuxdo/start` 可携带 `acceptedTerms=true`，只有该精确值表示同意。服务端将标志写入一次性的 OAuth state；回调仅在新建 Linux.do 用户时要求该 state 已同意，不从回调参数重新取值。已有 Linux.do 用户可从登录页继续登录，无需传此参数；同意协议不绕过注册关闭策略。

协议名称与正文由管理员在 `PATCH /admin/settings/registration` 配置，公开读取面是 `GET /auth/settings` 的 `agreementTitle`、`agreementContent`。`agreementTitle` 未配置时按当前外观品牌名生成 `<品牌名>服务协议`，因此外观改名后注册页文案同步；接口返回的标题不含书名号，由注册页补《》。`agreementContent` 支持多段文本，按空行分段渲染，留空时注册页提示“服务协议内容待补充”。

读取注册配置失败（如 JSON 损坏）时，`RegistrationAgreement` 返回空标题而不是品牌名兜底标题，注册页据此隐藏协议入口并提示可重新读取，避免展示后台并不存在的协议名称；此时错误提示统一回落为“请先同意服务协议”。

`PATCH /admin/settings/registration` 的两个协议字段为可选指针语义：不提交表示保留已保存内容，提交空串表示明确清空。注册开关与协议正文可以分开保存，单独切换 `enabled` 不会覆盖协议。当前只校验本次注册的同意标志，不保存长期协议版本或签署凭证。前后端需一起更新，旧客户端缺少同意标志时无法注册。
## 站点皮肤主按钮

### 画布配置、更新公告、状态动画包与 Live2D（外观合同版本 11）

外观设置新增 `updates: { enabled, currentVersion, releases }`，由管理员通过 `PATCH /admin/settings/appearance` 保存；关闭开关保留草稿，但 `GET /public/appearance` 返回关闭状态与空公告列表，前端恢复内置更新日志。开启时公开版本与内容块，当前版本须对应公告版本。媒体上传、管理员预览、公开引用读取及限制详见 [自定义更新公告](/docs/backend/update-announcements)。JSON 请求上限为 512KB；无数据表迁移。

`GET /public/appearance` 和管理员 `GET /admin/settings/appearance` 返回 `canvas`；管理员通过 `PATCH /admin/settings/appearance` 随外观配置统一保存。字段为 `agentName`（1–24 字）、`launcherLabel`（0–24 字）、`panelTitle`（1–40 字）、`welcomeTitle`（1–100 字）、`welcomeDescription`（0–200 字）、`inputPlaceholder`（1–160 字）、`avatarType`（`orb|bundle|live2d`）、`avatarHeight`（120–360 整数）、`live2dResourceId`、`live2dEntry`、`avatarBundleResourceId` 和状态到 clip 名的 `avatarClipStates`。状态键为 `idle|queued|running|waiting_approval|completed|failed|cancelled|rejected`；状态动画包为空资源 ID 时使用内置 `/doll/avatar.json`。启用上传包时服务端核验资源归属、ZIP 与每个状态引用的 clip。名称以数据形式投影到每轮 Agent 执行上下文，不提供自由系统提示词配置，也不改变工具权限。

- `POST /admin/settings/appearance/live2d`：管理员 multipart `file` 上传，受上传频率和配额限制。成功信封的 `data.model` 为 `{ resourceId, entry }`，上传不会发布。ZIP 限 128 MiB、256 条目、解压合计 384 MiB、单文件 128 MiB；只接收 model3/MOC3/PNG/JSON，拒绝路径穿越、脚本和外部资源。
- `GET /admin/settings/appearance/live2d/:id/*file`：管理员预览，校验资源归属；其他管理员仅能查看当前外观已引用模型。
- `GET /public/appearance/live2d/:id/*file`：仅提供当前启用模型的数据文件。停用或更换后旧模型拒绝公开访问。成功为文件内容，失败为错误信封；响应带 `nosniff` 和私有、需重新验证的缓存策略。
- `POST /admin/settings/appearance/avatar-bundles`：管理员 multipart `file` 导入状态动画 ZIP，受上传频率和配额限制。ZIP 最大 128 MiB、解压总量最大 384 MiB、最多 128 个条目；包含根目录 `avatar.json` 和其逐一引用的 MP4。成功信封 `data.bundle` 返回 `{ resourceId, manifest }`，不会自动启用。
- `GET /admin/settings/appearance/avatar/:id/*file`：上传者可预览未启用包，其他管理员只能预览当前配置引用包中的 manifest 或 MP4。
- `GET /public/appearance/avatar/:id/*file`：只提供当前启用动画包中经 manifest 引用的文件；MP4 支持 Range，停用或更换后旧包拒绝公开读取。

管理员资源列表增加 `kind=live2d` 筛选；引用中的模型禁止删除，清除外观引用后按既有资源删除流程清理。

部署要求与更详细的文件限制见 [画布 Agent 外观与 Live2D](/docs/backend/canvas-agent-appearance)。

`GET /public/appearance` 返回当前 `activeSkin`；管理员通过 `GET/PUT /admin/settings/appearance` 读取、保存完整主题库。外观合同版本 8 新增 `tokens.buttons.light/dark`，字段为 `mode`（`solid|gradient`）、整数 `angle`（0–360）、HEX 色值 `start/end`、`hoverStart/hoverEnd`、`activeStart/activeEnd`、`foreground`。纯色模式使用既有主操作颜色，渐变仅用于主按钮。非法模式、角度、色值或修改锁定经典主题均拒绝保存；整块缺失的旧配置按主题身份补齐。此变更不增加数据表迁移。

## 模型规格报价

### 管理员批量调价

`POST /admin/channels/:id/models/batch-reprice` 接收最终售价及原始价格版本，返回 `{ code: 0, data: { updated: number }, msg }`。仅管理员可调用；单批 1–100 个模型，空 ID、重复 ID 或不属于当前系统渠道的记录整批拒绝。请求结构如下（价格为整数微积分）：

```json
{
  "models": [{
    "modelId": "MODEL001",
    "priceVersion": 4,
    "priceTiers": [{
      "id": "TIER001",
      "priceVersion": 8,
      "prices": { "unitPriceMicrocredits": 1370000 }
    }]
  }]
}
```

弹窗一行一个模型，列为模型展示名、渠道展示名（上游模型 ID）、规格、成本价和销售价输入框；多个规格在模型行内纵向对齐。利润率沿用财务口径：`(销售价 − 成本价) / 销售价 × 100%`，并非成本加价率。目标利润率为 0–99.99%，最多两位小数；售价按 `成本价 / (1 − 目标利润率)` 计算，按所选 0–6 位积分小数四舍五入（默认 2 位）。成本 1 积分、目标 20%、保留 2 位时售价为 1.25 积分。修改比例或精度实时计算，也可点击「重新计算」按当前参数覆盖全部手动售价；随后允许逐规格手动修改，保存以最终输入值为准。舍入和手动修改可能使实际利润率偏离目标；售价为零时利润率显示 `—`。

每个模型必须提交全部已启用规格（模型本身可停用），且每个规格只提交当前计费方式需要的完整 `prices` 字段：按次/秒为 `unitPriceMicrocredits`；文本 Token 为 `inputTokenPriceMicrocredits`、`outputTokenPriceMicrocredits`、`cachedTokenPriceMicrocredits`；视频 Token 仅为 `outputTokenPriceMicrocredits`。缺失、多余、重复、停用规格、null、负数或非整数价格均拒绝。成本和售价配置必须已保存；成本及 Token 售价上限为 1,000,000 积分，按次/秒售价不得超出 JavaScript 安全整数微积分范围。

服务端校验最终售价和模型/规格版本，不重新计算覆盖手工价格。价格快照过期必须刷新后重试。所有模型与价格档在单事务中更新，增加价格版本、失效目录缓存；无效配置、归属错误、超限或并发版本冲突均不部分提交。不改变成本、规格、计费方式和启停状态；未启用规格保持原值。此接口不新增数据表或迁移，不追溯修改已下单的计费快照。

### 用户模型目录

`GET /model-catalog` 固定返回 `source=system`，直接查询所有启用系统渠道下的渠道模型，目录数据在 `channels[].models[]`，`models` 固定为空数组。不受逻辑模型开关影响，不反查逻辑模型或供应线路。每项的 `modelKey` 是调用标识，`displayName` 是一级分组展示名（未设置时归入 `未分类`），`icon` 是模型图标键，`channelLabel` 是二级渠道展示名。后台渠道模型创建与更新请求使用相同的 `channelLabel` 字段；服务端去除首尾空白后限制为 80 字，空值或与上游模型 ID 相同的值表示不固化该名称，读取时回退到上游模型 ID（默认与上游 ID 保持一致，上游改名时自动跟随）。

渠道模型创建、更新、管理列表、公开目录和会话模型价格信息均使用 `description` 表达模型描述。服务端去除首尾空白后限制为 500 字，允许空字符串清除描述；无管理员权限或超长内容拒绝保存。创作端二级选项常驻展示该字段，不依赖悬浮 Tooltip；未填写的系统模型不按名称生成宣传文案。

以上模型接口同时使用 `tags: [{ text, color }]` 传递有序展示标签，例如 `[{"text":"限时特价","color":"purple"},{"text":"官方1折","color":"gold"}]`。最多 5 个，文字去除首尾空白后为 1–12 字且不可重复；颜色仅接受 `purple`、`blue`、`green`、`gold`、`orange`、`pink`。创建/更新由管理员操作，非法标签拒绝整个保存；提交 `tags: []`（或省略字段）清空标签。用户模型选择器在对应二级渠道项中常驻展示，标签不参与路由、价格计算或权限判断。

创作端跨渠道按模型 `displayName` 分组为一级菜单（新导入模型默认 `未分类`），二级菜单使用每条模型的 `channelLabel`；未手动设置时与上游模型 ID 保持一致，例如 `MiniMax H3 → minimax-h3`。选中值继续使用 `channelId::modelKey`，报价和生成请求保留该渠道身份。展示字段不参与路由、权限及计费。系统渠道的“前台名称/前台显示别名”已移除，管理 API 不再接受或返回 `publicAlias`。

同一产品在不同渠道中使用相同的模型展示名即可归组，`modelKey` 可以不同；相同 `modelKey` 但展示名不同会分为不同组。一级顺序与图标按后台渠道和模型排序首次出现的位置确定，二级保持后台渠道与模型顺序。即使二级展示名相同，也保留独立选项及各自能力、价格，不自动改写历史配置或交换两个展示字段。

`GET /admin/references` 的 `channels[]` 同时返回 `modelDisplayNames`，包含系统渠道已创建模型的一级分组名称（含停用模型）。已设置过展示名的分组保留原值，即使与模型 ID 相同也算作已分组；未设置的模型不进入该列表，避免把模型 ID 当成一级分组。编辑器“模型展示名（一级目录）”汇总去重后提供可搜索下拉，点击即可展开全部已有分组，同时允许输入新分组；保存后刷新引用数据。

以下接口需要登录 Cookie，返回 `data.quote`，仅校验和报价，不创建任务、账单或冻结余额，不调用供应商生成接口。

| 接口 | 请求 |
| --- | --- |
| `POST /model-catalog/quote` | `{ channelId, modelKey, intent }`，仅允许启用的系统渠道与可用模型，复用任务准入、默认参数和价格档选择 |
| `POST /models/:id/quote` | 直接提交 `intent`，按前台逻辑模型当前可用线路和价格策略报价 |

`intent` 包含 `capability`（`text/image/video/audio`）、`operation`、`inputs`（素材类型到数量的映射）和 `options`（请求规格）。素材数量必须为 0–128 的整数，再按模型能力限制校验。视频规格包括 `vquality`、`size`、`videoSeconds`、布尔值 `videoGenerateAudio`，显式 `false` 必须保留。

报价包含 `logicalModelId`（系统渠道直连为空）、`billingMode`、`quantity`、`amountMicrocredits`、`estimated`。视频 Token 报价另有 `videoTokenEstimate`：`formulaTokens`、`reservedTokens`、`outputWidth`、`outputHeight`、`framesPerSecond`、`outputSeconds`、`referenceSeconds`、`referenceDurationEstimated`、`dimensionsEstimated`、`reservationMarginPercent`。

Token 报价的 `estimated` 为 `true`，`quantity` 是预留 Token 数。参考素材数量不包含时长信息，带参考视频时统一按 15 秒估算并返回 `referenceDurationEstimated: true`。所有视频协议均支持 Token 定价；10% 预留是平台策略，不是费用上限。成功后优先有效上游用量，无有效用量时按提交的公式快照结算，余量不计入公式费用。账单新增 `videoFormulaTokens` 及 `usageSource`（`provider` / `video_formula`），公式结算的 `usageAvailable` 为 `false`，`outputTokens` 表示公式数量。算法、配置与异常用量处理见[视频 Token 计费](/docs/backend/video-token-billing)。

## 用户分组与多币种计价

用户模型目录、报价、任务创建、工作台任务、短剧模型选择、云端 Agent 模型列表和系统渠道中转都按当前用户分组过滤系统渠道：分组未绑定的渠道不出现在 `GET /model-catalog` 与 `GET /models`，直接提交其 `channelId` 时报价、建任务和中转返回 `reason=model_catalog_mismatch`。管理员账号可见全部渠道。目录与报价返回的价格档单价（`unitPriceMicrocredits`、Token 单价）已按分组换算为实际扣费的微积分，含全局积分倍率、分组倍率和模型倍率；分组未配置该货币兑换比例的模型不进入目录，报价返回 `model_price_not_configured`。

`GET /auth/session` 增加 `userGroup`：`{ code, name, badgeLabel, badgeStyle, ratioBasisPoints }`，分组配置缺失时为 `null`。用户对象增加 `userGroup`（空串表示 `default`）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/user-groups` | 分组列表，含 `isDefault`、`channelIds`、`modelOverrides`、`userCount` |
| POST | `/api/admin/user-groups` | 创建分组：`code`（`^[a-z0-9][a-z0-9_-]{0,39}$`，不可改）、`name`、`description`、`badgeLabel`、`badgeStyle`（`none`/`vip`/`svip`）、`sortOrder`、`ratioBasisPoints`（1–1000000）、`pointsPerUsdMicrocredits`、`pointsPerCnyMicrocredits`（0–10¹²）、`allChannels`、`channelIds`、`modelOverrides[]`（`modelKey`、`ratioBasisPoints`、`pointsPerUsdMicrocredits`、`pointsPerCnyMicrocredits`，0 表示沿用分组值） |
| PATCH | `/api/admin/user-groups/:id` | 更新分组，请求体同上；`code` 与原值不同时拒绝 |
| DELETE | `/api/admin/user-groups/:id` | 删除分组；`default` 和仍有用户的分组拒绝 |
| GET | `/api/admin/users?group=vip` | 按分组筛选用户，`group=default` 同时匹配未分组用户 |
| PATCH | `/api/admin/users/:id` | 增加可选 `userGroup`；省略表示不修改 |
| POST | `/api/admin/users` | 增加可选 `userGroup`，默认 `default` |

渠道模型创建与更新增加 `priceCurrency`：`credits`（默认）/ `USD` / `CNY`。省略时更新保留原值、新建为 `credits`。货币计价时价格档售价字段表示百万分之一货币单位，例如 `unitPriceMicrocredits: 40000` 表示每次 0.04 USD；成本价仍是微积分。渠道导出文件携带 `priceCurrency`。

充值商品增加 `currency`（`CNY` / `USD`），`amountFen` 表示该货币最小单位（分 / 美分）；新建未传 `currency` 时使用默认充值货币，更新未传时保留原值。支付订单 `currency` 取自商品，支付插件按该货币下单和校验。默认充值货币接口：`GET /api/payments/settings`（登录用户）、`GET/PUT /api/admin/payments/settings`（`{ defaultCurrency: "CNY" | "USD" }`）；用户端 `/payments/products` 把默认货币的商品排在前面，切换默认货币不改写已有商品价格。

## 管理员积分成本

`GET/POST /admin/channels/:id/models` 与 `PATCH /admin/channels/:id/models/:modelId` 的 `priceTiers[]` 增加 `costPricing`：`configured`、`unitPriceMicrocredits`、`inputTokenPriceMicrocredits`、`outputTokenPriceMicrocredits`、`cachedTokenPriceMicrocredits`。成本沿用该价格档的计费方式；按次/秒使用单位价，文本 Token 按输入/输出/缓存分别定价，视频 Token 只使用输出价。价格为整数微积分，范围为 0 到 1000000000000；`configured=false` 表示未配置，`true` 且价格为 0 表示显式零成本。

成本保存到下单时的内部账单快照，不受售价倍率或扣费上限影响，后续改价不重算旧订单。历史逻辑模型任务切换备用线路时，成本更新为实际执行线路的快照，独立于用户售价策略。管理员请求列表、详情与 CSV 分列展示预授权、实收及成本金额；JSON 返回 `billingReservedMicrocredits`（订单预授权额）、可选 `billingSettledMicrocredits`（仅已结算订单返回实收）、`creditCostConfigured` 和可选 `creditCostMicrocredits`。预授权、待核对和已退回订单不返回实收，不能把预授权额当作扣费额；CSV 对应列为“预授权(微积分)”“实收(微积分)”。成功结算后按实际计费数量、Token 用量或视频公式快照核算；未结算、已退回、历史无快照或缺少有效用量时不编造成本金额。

成本字段仅通过经过管理员权限校验的接口显式返回；普通用户的模型目录、会话模型信息、报价、任务与账单 JSON 均不包含成本配置、成本快照或成本金额。底层价格档和账单成本字段禁止 JSON 序列化，不以页面隐藏代替接口隔离。

数据概览不再提供独立的“模型价格配置”入口。`GET /admin/analytics/overview` 的 `kpi`、`models[]` 使用 `finance` 返回 `settledOrders`、`costedOrders`、`revenueMicrocredits`、`costMicrocredits`、可空的 `profitMicrocredits`、`profitMargin`，取代旧的费用/币种字段。按当前请求日志时间及筛选范围关联已结算订单，以订单 ID 去重并核对用户与实际结算渠道；轮询、下载、未结算、退款和无关联账单请求不计入财务汇总。收入为实际结算积分，成本复用系统模型价格档的订单快照与计费用量，利润为收入减成本，利润率为利润占收入百分比。已知成本可显示部分合计；只要有已结算订单缺失成本，利润和利润率返回 `null`，不把未知成本视为零。无订单时利润为 `null`；零收入时利润率为 `null`。历史无成本快照的订单不按当前价回填。此处为已结算生成订单的积分毛利，不含充值收入或失败请求的上游损耗。

总览的请求类指标（`kpi.upstreamRequests`、`kpi.successRate`、`kpi.p95DurationMs`、`trend[].requests`、`models[].requests` 与耗时、`failures[]`、按调用计入的活跃用户）只统计 `request_kind = create` 的模型生成请求；图片、视频的轮询结果已合并进 create 根记录，轮询、下载、上传、本地保存等阶段不计入。成功率按 succeeded /（succeeded + failed）计算，`trend[].requestSuccessRate`、`models[].taskSuccessRate`、`models[].requestSuccessRate` 在没有样本时返回 `null`，不返回 0。`trend[].consumedMicrocredits` 为当天已结算订单的实收积分，与 `kpi.finance.revenueMicrocredits` 同一口径，按订单首条可计费调用的 UTC 日期归属；`kpi.totalConsumedMicrocredits` 已移除。

`GET /admin/api-logs` 与 `GET /admin/api-logs-export.csv` 支持 `from`、`to`（`YYYY-MM-DD` 按 UTC 自然日、含结束日，或 RFC 3339 时间点）、`userId`、`model`、`channelId`、`capability`；不传日期时默认近 30 个 UTC 日，单次最多 366 天。

`GET /admin/billing-orders` 的每条订单额外返回 `userDisplayName`、`userAccount`，按当前页用户 ID 批量读取；字段不入库，普通用户的订单接口不返回。

`GET /admin/users` 的每个用户额外返回 `rechargedMicrocredits`（已到账支付订单的到账积分合计）和 `consumedMicrocredits`（已结算计费订单的实收合计），按当前页用户批量汇总。

渠道模型运营接口（均要求管理员）：

| 接口 | 行为 |
| --- | --- |
| `GET /admin/channel-models` | 返回全部系统渠道（含停用渠道）的模型，结构同 `GET /admin/channels/:id/models` 的单项，另加 `channelName`、`channelEnabled`，供按模型名称跨渠道筛选。 |
| `GET /admin/channel-models/health?channelId=` | 返回模型调用稳定性 `{ items, computedAt, truncated }`。每项含 `channelId`、`modelKey`、近 24 小时 `requests24h` / `succeeded24h` / `failed24h` / `successRate24h`、近 7 天 `requests7d` / `successRate7d`、`p95DurationMs24h`、最近 10 次结果 `recentResults`（左旧右新）、`lastErrorCode`、`lastFailedAt`、`lastCalledAt`。成功率为 0–1 小数，没有样本时为 `null`。只统计 `request_kind = create`，不设用户端的最少样本门槛；读取近 7 天最新 50,000 条记录，超出时 `truncated = true`。结果缓存 30 秒；不传 `channelId` 时返回全部系统渠道。 |
| `PATCH /admin/channels/:id/models/:modelId/enabled` | 请求体 `{ "enabled": boolean }`，只改启停，不重写价格档、能力配置和价格版本；能力或协议未配置的模型不能启用。写管理员审计 `channel_model.enable` / `channel_model.disable`。 |

`GET /admin/analytics/export.csv` 沿用相同口径，CSV 输出收入、成本、利润（整数微积分）；重复请求只在该筛选范围内选定的一行记录金额，未知值留空。

上传、工作流结构查询、取消查询和取消请求也不参与财务归属，即使日志被标记为可计费；它们不能代替生成请求承载订单金额。订单是否已结算以账单状态为准，保留人工核账后结算订单的统计能力。

## 画布保存与 operations 同步

画布写入统一使用 `PATCH /canvas-projects/:id/operations`。请求只携带对象级或字段级变更，不提交整批画布快照；`mutationId` 是一次写入的幂等身份，客户端在响应丢失、断网、刷新或后台重试时必须复用同一个 ID 和原始 `operations`。`baseRevision` 记录生成请求时的已确认基线版本，用于诊断和响应；字段/对象的 `before`、`expected`、`beforeValue` 是实际并发校验，允许不同字段合并，拒绝同字段覆盖和缺失对象更新。可选顶层字段缺失时必须显式编码为 JSON `null`；服务端仅对早期客户端省略这些可选字段的 `value` 或 `beforeValue` 按 `null` 兼容处理，并继续执行基线校验。

| 接口 | 行为 |
| --- | --- |
| `GET /canvas-projects/:id` | 返回当前完整画布及权威 `revision`；响应包含基于数据库版本的弱 `ETag` 和 `Cache-Control: private, no-cache`。请求可用 `If-None-Match` 做条件读取，版本未变化时返回 `304`。 |
| `PATCH /canvas-projects/:id/operations` | 接收 `{ mutationId, baseRevision?, operations[] }`，返回当前项目摘要和 `mutationId`。`create_canvas` 建出的新画布带 `referenceFieldsVersion: 1`（声明式引用）。支持 `create_canvas`、`create_node`、`patch_node`、`remove_node`、`create_connection`、`update_connection`、`remove_connection`、`set_field`。 |
| `GET /canvas-projects/:id/reference-migration` | 只读预览旧版画布的引用规范化：返回 `{ revision, required, conflicts[] }`，`required=false` 表示已使用声明式引用。 |
| `POST /canvas-projects/:id/reference-migration` | 接收 `{ revision, choices }`（冲突作用域 → `fields`／`connections`），一次性写入声明式引用并保留历史快照；`reason` 为 `reference_migration_conflict`、`reference_migration_not_required`、`reference_migration_invalid`。 |
| `DELETE /canvas-projects/:id` | 显式删除画布。删除后迟到的更新不会重新创建画布；只有新的 `create_canvas` 操作可以显式创建同 ID 画布。 |

`create_node`、`create_connection` 和 `create_canvas` 是唯一的创建语义；更新、删除和连接操作都要求目标存在并通过对象基线校验。当前值已等于本次目标值的补丁、字段、连线更新和同内容的重复新增按已应用处理；整对象基线忽略节点 `updatedAt`，规则见 [画布 operations 同步协议](./canvas-operations-sync)。节点删除会同步移除关联连接，迟到媒体回写或编辑更新返回结构化冲突，不会复活已删除节点。请求摘要与确定性结果写入 `canvas_mutation_receipts`，画布内容、版本递增和 receipt 在同一数据库事务完成；同一 `mutationId` 和相同摘要返回原结果，摘要不同返回 `canvas_mutation_id_reused`。

前端先把未确认请求和请求基线写入账号隔离的本地 journal，再发 HTTP 请求。journal 保存已确认基线、原始请求、请求生成时的本地投影和创建时间；刷新后只重放原请求，随后把请求之后的新编辑按新的基线生成下一批 operations。服务端返回完整画布时，客户端只合并仍未确认的本地 mutations，视口仍属于本地视图状态，不进入远端 operations。

打开画布时，旧浏览器缓存与云端更新按会话原基线合并，再同时更新编辑器与缓存。不能先把最新云端版本设为基线、再直接提交旧缓存，否则其他设备或 Agent 新增而缓存中没有的节点会被误判为删除。已落盘的明确删除请求仍按原 journal 重放。operations 明确返回字段冲突后，客户端读取最新基线，保留当前本地编辑的字段，合入云端无关变化，再以新 mutationId 提交；响应未知时仍重放原 ID/body。已删除对象不复活，旧任务观察值不能覆盖云端的新任务绑定及较新结果。对于没有可验证内容哈希、又与云端不同的旧缓存，合并前在当前账号的 localforage 中保存最多三份恢复副本（`yingce:canvas-unverified-recovery:<canvasId>`）；副本落盘失败时不替换本地内容、不发送推导删除。

云端 Agent、媒体生成终态回写、预演台、创作提交以及 LibTV/TapNow 导入都复用同一 operations 服务。Agent 事件中的 `canvasPatch` 只是一种有界通知；过大、删除或无法完整表达的变更使用 `requiresRefresh: true`，客户端重新读取后按未确认请求继续重放。用户界面不提供版本记录、加载云端版、覆盖云端或手动重试入口，不弹出同步报错；失败请求由后台自动重放，未确认时不显示已同步。同账号同输入框并发输入按共同基线的文字增删合并；租约只约束服务端写入，客户端保持可编辑，每批保存确认后释放凭据供另一端接手。存在未确认请求时，先重放 receipt，再合入后续输入，避免响应丢失后重复插入本机文字。

平移和缩放只持久化浏览器视口，不生成远端 operations。保存日志仅记录请求/链路 ID、画布/用户 ID、版本、节点数量变化及 HTTP 状态，不记录正文、提示词或媒体 URL。

operations 的结构化配额在提交事务内实时统计账号的素材/画布数量和 JSON 字节数，不为画布保存扫描任务正文及 API 请求/响应日志。接口请求、响应、容量上限及错误语义均不变；性能排查应分别记录成功写入、同请求重放和冲突请求的耗时，冲突请求提前退出不能代表完整提交耗时。

## 推广中心

推广设置保存在 `system_settings` 的 `referral` 键，管理员通过 `GET/PATCH /admin/settings/referral` 读写 `{ enabled, mode, commissionRateBasisPoints }`，保存记录管理员审计。`mode` 为 `all`（全民推广）或 `assigned`（指定推广人）；返佣比例为万分比，范围 0–5000。推广人标记通过 `PATCH /admin/users/:id` 的可选布尔字段 `isPromoter` 修改，省略表示不变。

`GET /auth/session` 的 `data.referralAvailable` 表示当前账号能否进入推广中心：推广已开启、账号正常，并且是全民模式或账号为推广人。用户接口 `GET /referral`、`GET /referral/invitees`、`GET /referral/commissions`（`page`、`pageSize`）在无资格时返回 403 `forbidden`；被邀请用户名称只返回首字加 `**`。`GET /admin/referral/commissions` 返回全站返佣，名称不脱敏。

`POST /auth/register` 接受可选 `referralCode`（来自推广链接 `/register?ref=推广码`）。推广码无效、推广人当时无资格或绑定写入失败时注册照常成功，只是不记录归属。积分充值订单入账后按当时设置计算返佣：`floor(到账积分 × 比例 / 10000)`，以积分写入推广人账户，流水类型 `referral_commission`；同一订单只返佣一次，存储空间订单不返佣。

## 欢迎页开放配置

`GET /public/welcome` 无需登录，信封 `data` 仅包含布尔值 `welcomeEnabled`，响应禁用缓存。读取失败按标准错误信封返回。

管理员通过 `GET/PATCH /admin/settings/features` 读取和保存 `welcomeEnabled`，默认 `true`，与其他功能开关一起存入 `system_settings` 的 `feature_availability` JSON，并记录管理员审计。关闭后新访问 `/welcome` 的浏览器跳转到 `/`。

## 云端 Agent

云端目录支持跨设备发现当前账号画布的会话：`GET /api/agent/conversations?canvasId=...&before=...&limit=...` 返回items和可选nextCursor，`GET /api/agent/conversations/:id/runs?after=...&limit=...` 分页读取轮次。游标是不透明值，直接使用响应值续读；动态子代理不作为独立父会话重复列出。接续已过期父轮会在计费前拒绝，重复已确认请求仍先回放回执。

从头恢复事件可用运行详情的 `fromStart=true`、`sinceSeq`、`eventLimit`，运行中继续沿SSE游标增量消费。前端保留本地草稿和未知POST身份，目录刷新不能回退刚提交的新轮次；缺失旧事件的历史明确标记不完整，不伪造完整聊天。这里同步的是已有会话与展示事件，Agent记忆、长期偏好和压缩算法继续独立设计。

所有 `/agent` 路径都需要登录 Cookie。`GET /agent/capabilities` 返回当前版本（2）、权限模式、上下文范围、技能和工具清单；跨轮历史仍按可恢复事实和发送预算整理，不把某个固定字节数当作模型窗口。Agent 运行由服务端任务 Worker 驱动，浏览器断开不会停止运行。

文本模型能力合同包含 `contextWindowTokens`（模型总上下文窗口）、`reservedOutputTokens`（为输出预留的窗口）、`maxOutputTokens`（单次调用输出上限）与 `thinking`（该模型是否暴露用户可选的推理/思考模式；缺省表示未声明，面板隐藏推理选项且不发送 reasoning 参数）。Agent 每轮根据实际执行的渠道模型计算输入预算，并预留工具 schema、协议包装与兜底轮空间；逻辑模型按候选文本线路取安全交集。窗口未声明（0）时不猜默认窗口，判据退回字节口径，不做 128K / 16K 之类的猜测回退。1M 模型可通过后台能力配置使用更大输入预算。前后端的 Token 估算用于提前压缩和拒绝病态请求，最终仍以上游 tokenizer 和响应为准。运行 checkpoint 的 512KB 持久化上限只约束恢复状态，不限制模型上下文窗口。

- `POST /agent/runs` 创建一轮；`POST /agent/runs/:id/messages` 以上一轮为父节点创建新的不可变轮次，两者返回 `{ run }`，追加后必须使用新的 `run.id` 订阅。
- `POST /agent/runs/:id/permission` 在运行中切换执行权限，请求 `{ permissionMode, requestId }`（`read_only` / `request_approval` / `auto`，`requestId` 最多 160 字符），返回 `{ permissionMode, changed }`。放宽和收紧都从**下一次工具调用**生效；正在等待的审批卡保持原样，仍需用户批准或拒绝，之后的写入按新权限处理；收紧到不允许该写入后再批准，返回 409 `reason=agent_approval_not_permitted`。该接口按画布写入频率限流。同一 `requestId` 幂等，与当前权限相同时直接成功（`changed=false`）。生成预算不随权限改变：从只读放宽时生成预算保持原值，生成仍受本轮积分上限约束。成功时追加运行事件 `permission_changed`（`{ from, to, requestId }`），并在下一次模型调用前把一条「[系统通知] 用户已把执行权限从…改为…」消息按插话通路送达（送达事件 `permission_notice_delivered`）；下一步前多次切换只送一条，切回模型已知的权限则不送。系统提示、执行上下文里的 `permissionMode` 与 prompt cache 键保持开局值，工具列表按新权限变化（工具段缓存失效一次）。运行已结束返回 409 `reason=agent_run_finished`，子代理运行返回 409 `reason=agent_subagent_permission_fixed`，别人的运行返回 404。
- `POST /agent/runs/:id/interjections` 向**正在运行**的轮次插入一句话，不新建轮次、不产生新的扣费身份。请求 `{ text, messageId }`，`text` 最多 4000 字符；同一 `messageId` 幂等。插话在下一次模型调用前注入；运行已结束返回 409，前端应回落为新一轮发送。步数耗尽或运行失败时发出 `user_interjection_dropped`，不会静默吞掉，也不会自动替用户开新一轮。
- 请求字段：`canvasId`、`prompt`、受管 `logicalModelId` 或 `channelId` + `channelModelKey`、`permissionMode: "read_only" | "request_approval" | "auto"`、`reasoningMode: "off" | "auto" | "deep"`、`profileRevision`、`skillIds`、`contextScope: [] | ["canvas"]`、`subagentEnabled`、`budget: { maxCredits, maxGenerationTasks, maxVideoSeconds }`、`idempotencyKey`。不接受密钥、自定义 URL、客户端历史或未知字段。
- `GET /agent/subagent-policy?canvasId=...` 读取持续生效的画布子代理授权，返回 `{ canvasId, enabled, revision }`；`PUT /agent/subagent-policy` 接受 `{ canvasId, enabled, expectedRevision }`，revision 冲突返回 409。授权默认关闭，开启后直到用户关闭都有效；运行准入冻结当时策略，客户端 `subagentEnabled: true` 不能绕过服务端授权或平台 `agentSubagentsEnabled` 开关。
- `GET /agent/runs/:id/subagents` 返回该父运行的动态子代理列表，包含名称、角色、目标、子运行 ID、状态和有序消息，服务端校验运行与画布归属。父 Agent 使用 `spawn_subagent` 自主分配角色和任务，通过 `message_subagent`、`subagent_status`、`wait_subagents` 协调；子 Agent 使用 `send_parent_message` 和 `finish_subagent` 回报。消息对应 `subagent_spawned`、`subagent_message` 事件，沿用运行详情和 SSE 的递增游标。
- 每个父运行最多创建 4 个子代理、最多 3 个同时活动；子运行深度为 1、最多 20 步，独立 conversation/Pi session，固定只读，不能继续创建子代理、写画布或生成媒体。父运行有活动子运行时不能完成；等待释放父会话驻留名额，全部子运行终态后恢复同一工具调用。子运行分别继承并冻结父 credits 上限、独立计费，没有共享家庭预算。旧 Crew API、固定成员配置和事件解析器已删除。
- 同用户同幂等键及相同请求返回同一运行；不同请求复用键返回 409。失败后重试同一提交应保留键。上一轮未完成时禁止追加；已完成、失败、取消或已拒绝的终态轮次作为不可变历史读取，即使其冻结的策略或节点能力版本早于当前服务，也可用于创建采用当前执行合同的新一轮，父运行不会被改写。旧版合同下仍活动或待审批的运行不得恢复执行。历史只保留最近 10 轮用户目标；运行历史与跨轮摘要仍受独立的持久化 JSON 保护，超限先丢掉更早的可重读正文并保留结构化事实，单轮仍超出当前模型能力预算时才提示缩小范围或新建对话；历史结构损坏返回明确 409，不投影为通用 500。
- 续轮交接是一条**有界结构化事实帧**（`{ source: "server", kind: "run_handoff", parentRunId, status, failureReason?, submittedTaskIds?, canvasChanges?, omittedCanvasChanges?, authority }`）：画布改动取自上一轮真实的 `canvas_updated` 事件，最多 12 组（operation、去重后的 nodeId/title、actionCount），超出的组数只记 `omittedCanvasChanges`，不静默丢弃；帧还带 `authority` 明写"执行事实交接，不是重放写入、重复提交任务或扩大权限的授权"。帧按字节封顶（单个 nodeId 截 64 字符、整帧 8 KiB，超限按最近改动优先裁剪），失败原因沿用 `cloudAgentSafeUserMessage` 的脱敏口径，不合格退回固定说法。身份由服务端字段 `agentContextSource=continuation` 承载并要求"来源元数据 + `【运行状态】` 前缀 + JSON `source=server`/`kind=run_handoff`"三者同时成立，因此用户逐字复制帧正文也拿不到该身份；升级前落库、没有来源字段的旧散文交接只在历史裁剪与轮次计数上按"紧跟上一轮 assistant 回复 + 旧版文案前缀"识别，该判据不影响 canonical 身份。
- `POST /agent/runs/:id/approvals/:approvalId/decision` 的 `{ decision, reason? }` 可在批准图片生成时附带 `mediaSettings: { logicalModelId? | channelId? + channelModelKey?, size, quality }`。仅替换本次模型选择、画幅和质量，不允许修改目标、提示词、引用、模式或快照。服务端先无收费预检，失败保留待审批状态；成功原子更新审批调用、哈希及预览，提交任务时再次校验内容、资源归属、模型能力、价格与累计预算。相同参数重复批准幂等，不同参数复用已决定审批返回 409。
- 审批拒绝是独立终态 `rejected`，表示本次操作未执行；不会生成 `tool_failed`、继续调用模型、写入画布、提交生成任务或扣费。拒绝后的草稿按既有草稿策略保留，用户可在下一轮说明修改方向。
- 创建和追加消息可选择 `reasoningMode`，默认 `off`；`auto`/`deep` 为服务端行为策略与模型推理配置的选择，不等于允许暴露内部思维链。供应商能力由后端校验；声明式 Agent 渠道不支持时明确报错。推理可能增加耗时和费用。
- Cloud Agent 与首页创造的规划请求使用自动工具选择。OpenAI Chat Completion 兼容协议会把显式 `auto` 归一化为省略 `tool_choice`，沿用协议默认的自动选择语义；显式开启思考模式时还会在首个上游请求前移除 `required` 或指定函数对象。非思考模式仍保留艺术点评、提示词优化等结构化任务的强制函数选择。若上游隐式开启思考而本地未声明，仍按 `required` → `auto` → 省略字段做兼容重试。
- 长期偏好接口 `/agent/profile`、请求字段 `profileRevision` 和工具 `agent_profile_read` 已移除。账户默认工作方式使用 `/agent/settings`；当前画布规则使用 `GET/PATCH /agent/workspaces/:canvasId`，保存正文传 `{ revision, agentsMd }`，正文最多 65536 UTF-8 字节，revision 冲突返回 409。Workspace 返回文档信息，不含技能；其 `/skills` 配置接口停用。
- 系统行为策略与媒体默认策略是版本化、编译进后端发布物的资源，修改它们仍需发布后端，不是后台热更新；工具、校验、扣费和审批在代码侧强制执行。系统行为策略当前版本为 10：`canvasSummary` 被定义为节点目录，模型不得把它当成完整画布。画布节点能力由服务端 registry 定义，工具 schema、创建、连线与画布目录读取共同消费；新生成模式还必须接入媒体任务适配器，不能仅凭 md 或注册节点启用收费操作。
- 新画布 Cloud Agent 运行使用 `skillRuntimeMode: "pi-native"`，前端只提交 `skillIds`。Go 固定 `versionId`、内容哈希、原生名称和文件白名单；Pi 0.87.1 发现运行隔离目录中的标准化 `SKILL.md`，用受限 `read` 按需读取入口和引用。更新技能不会改变在途运行的冻结版本，停用或移除安装则阻止后续读取和恢复。传统技能工具已从可调用合同移除；携带旧工具的在途运行须在升级前排空或通过正常终结流程结束。技能是不可信数据，不能创造工具、改变权限或覆盖系统规则；其他生成链路继续使用 `linked-context`。
- 快照冲突是可恢复的工具失败：审批前准备发现画布已变化时，服务端把冲突作为工具结果交回模型（并提示重新读取、重新申请审批），而不是终止整轮；参数、权限、模型与预算类准入失败仍然终止本轮。
- 同批写入自动重基：一个助手消息里可以有多个画布写入，它们都基于同一次读取提交，首个写入必然改变版本。服务端记录本批已消费与产出的快照版本，后续写入若携带的是本批出现过的版本，就自动替换成该批最新的版本后再校验；若模型携带陌生版本（第三方/浏览器并发改动），仍然按"画布已变化"拒绝。写入回执对模型给出结果口径：`applied:true`、`outcome` 说明已写入、`summary` 使用变更条目短句，不再回传审批卡的人话文案（曾导致模型以为仍在等审批而反复重读）。
- 分镜行的资产关联使用 `canvas_edit_storyboard` 的结构化 `assets:[{ref,role}]`，ref 是当前画布节点 ID 或唯一完整名称，服务端校验资产用途并转换为行绑定；`set_assets` 整体替换行资产并清空旧角色列表，新增前需合并保留项，共享输入不随此动作清空。逐行不同补丁用 `batch_update.updates`，批量追加用 `append_rows.rows`；任一项非法则整批不执行。产物归属及任务状态仍通过专用流程维护，工具不接受任意 URL。完整字段和回执见 Agent 读取专题。
- 续轮使用带 `source=server`、`kind=run_handoff` 的有界结构化事实帧：包含父运行 ID / 终态 / 脱敏失败原因、已提交任务 ID，以及上一轮真实 `canvas_updated` 事件中最多 12 组画布改动（操作、节点 ID / 标题和数量）；超出的组数只记录 `omittedCanvasChanges`。帧明确声明它不是重放写入、重复提交任务或扩大权限的授权，并以 `agentContextSource=continuation` 进入模型请求，不能仅凭用户输入相似前缀伪装。读取上一轮事件不使用默认分页（上限 1000 条），避免长运行的早期改动在 handoff 中消失。
- 上游连续返回空内容（思考模型把整个输出预算花在推理上，实测 `output_tokens` 正好等于每步上限且正文为空）时：先按空输出催办（最多 2 次），仍空则**关思考 + 放大输出预算（默认上限的 2 倍，封顶 131072）重试同一步**，只有在这些手段都用尽后才停止本轮，并给出可操作的原因（换非思考模型或收敛上下文）。
> **合并上游 v1.5.7 的持久化与接口变化**：运行事件的活存储已换成上游的 `cloud_agent_event_records`（`event_json` 整条 JSON，主键 `(run_id, sequence)`），我们自研的 `cloud_agent_run_events` 随迁移 v35 退役（表与数据保留、代码不再读写；上游把 v33 用给了 `oauth_state_accepted_terms` 注册协议同意校验、v34 用给了 `task_media_recovery` 作品保存恢复，我方两条 no-op 让位迁移顺延到 **v36/v37**，上游随后把 v35 用给 `auth_notifications`）；`CloudAgentEvent` 的结构逐字段未变，因此前端事件面板与 SSE 消费方无感。事件分页/增量读取、`context_pressure` 计量事件、输入预算三段算式、单步边界、语义压缩与 `canvas_inspect_image` 都已按上游的持久化结构重新实现（见下方各条）。**尚未实现**：事件保留期 TTL（需要给上游事件表加列，属待人工确认的分叉项）；`GET /agent/capabilities` 的 `historyPolicy` / `contextCompaction` 字段仍按上游口径返回。
> 库侧还需要一次一次性搬运：`migrate-schema up` 会把退役表里的事件行按 `seq` 转成上游 `event_json` 形态写进 `cloud_agent_event_records`（仅当该 run 在上游事件表里一行都没有且 `event_count > 0`；全新库与纯上游库是 no-op，可重复执行）。

- 文本模型的 `reservedOutputTokens` 为自动计算的只读元数据，不再采用旧的手填值。能力配置展示以 `maxOutputTokens` 为基础；未声明最大输出时按窗口的 1/8 推算，最多 32768 Token，窗口为 0 时展示未知。Agent 每次请求再与单步输出策略取较小的正数值，并以同一值约束实际请求及输出预留；窗口未知时使用有界兜底预算，不将其当成已验证的模型能力。输入预算为窗口减去本步预留及协议开销（窗口的 4%，夹在 4096–32768 Token）。Pi 快照分别返回 `modelLimits.maxOutputTokens`（实际请求上限）和 `modelLimits.reservedOutputTokens`（输入预算预留）；逻辑路由分别保留最小安全输入容量与最小输出上限，两者可以来自不同路由。
- 前端上下文压力按画布会话持久化：同一 session 的续轮在新读数到达前保留上一份计量，新 session 清零，切回历史 session 恢复其读数；已退出的事件订阅不得改写当前 session 的计量。

- 画布 Agent 的**单步边界可配置**（管理端"画布 Agent 执行限制"分组，保存在 `system_settings.runtime_policy` 的 `task` 下，保存后热更新，不需要迁移）：`agentStepMaxOutputTokens` 是每次模型调用的输出上限（含思考、正文与工具调用参数），默认 `16384`（实测 222 步的 P50 为 1187 token、15% 顶到旧上限 6144 后被截断），可设 `0` 表示不限制；`agentStepTimeoutSeconds` 是单步墙钟的秒级值（30–3600），`0` 表示沿用文本任务超时（默认 8 分钟）。取值也可用环境变量 `CANVAS_AGENT_STEP_MAX_OUTPUT_TOKENS` / `CANVAS_AGENT_STEP_TIMEOUT_SECONDS` 覆盖（环境变量无法表达"不限制"）。单步模型调用或上下文摘要调用超时后，**立即将本轮 Agent 标记为失败并停止，不自动重试或继续压缩降级**；`run_failed` 的 `reason=model_step_timeout`，提示“Agent 超时失败”。UI 失败卡片显示并可复制事件的 `runId`，实时事件与恢复的 `run_status` 使用同一运行身份。两个生效值都会出现在 `context_pressure` 事件的 `stepMaxOutputTokens` / `stepTimeoutSeconds` 中（上限配为 0 时不返回 `stepMaxOutputTokens`），前端上下文计量弹窗直接显示"哪条线在管这一步"。
- Agent 调用次数同样由上述后台分组配置：`agentMaxToolCallsPerStep` 默认 8、范围 1–64；`agentMaxReadToolCallsPerRun` 默认 32、范围 1–9999；`agentMaxStepsPerRun` 默认 0（不限）、范围 0–9999。每轮模型步数与请求 `budget.maxSteps` 取更严格的非零值。新批次和下一次模型/只读调用读取生效策略；已准入批次在调低后仍可恢复与幂等重放。原生技能读取共享只读预算，并计入单次模型回复的工具数量。模型收到实时 `call_limits` 事实，详见 [Agent 读取与收尾合同](/docs/backend/agent-tool-reads)。
- 画布 Agent 的**每一步模型调用都记终止原因**（`result_json` 的 `stopReason` / `stopReasonKind`）：两个键取自上游的权威字段——OpenAI 的 `choices[0].finish_reason`、Claude 的 `message_delta.stop_reason`、Responses 的 `status` + `incomplete_details.reason`——并归一化成 `stop` / `tool_calls` / `length` / `context_limit` / `pause` / `refusal` / `content_filter` / `incomplete_unknown` / `unknown`（`content_filter` 与拒答分开记：过滤可能意味着内容被省略；Reports 只报 incomplete 而没给 reason 时单列 `incomplete_unknown`，不猜成输出截断）。每步落一条 `model_step_stop` 事件，载荷含三个**解析事实** `terminalEventSeen` / `stopReasonPresent` / `streamDoneSeen`（由解析器记录，不从归一化结果反推：上游给了新词时 kind 是 `unknown`，但"确实收到终态事件"仍为真）、`truncated`、`partialAnswer`、`disposition` 与 `textBytes` / `reasoningBytes` / `toolCalls`。旧任务结果没有这些键时记 `unknown`，不需要数据迁移。
  处置按 kind 显式分支，先定处置再产生任何副作用：`stop` / `tool_calls` 照常；`context_limit` 允许发布但标 `partialAnswer=true`（官方口径是 "response is still valid but was limited by context window"），并把压缩信号交给后续请求；`length` 判 `retry`（整步作废——不写 assistant/canonical、不记视觉观察、**不执行任何已解析出的工具调用**；关思考并放大输出预算重发同一步一次，`model_failure_recovered` / `reason=truncated_output_escalated`，`TruncatedStepEscalated` 上限 1），重试后仍截断则判 `fail`（`run_failed` / `reason=truncated_output`）；`pause` / `content_filter` / `refusal` / `incomplete_unknown` 一律判 `fail`（`reason=step_stop_<kind>`，如实终止且不发布半截正文）。升级时会把升级前的 `ForceThinkingOff` / `BoostStepOutputBudget` 存进检查点的 `escalationRestore`，重试被接受（或撞上别的失败阶梯）时复位，避免一次截断让本轮余下步骤都关着思考。`unknown` 暂按可用处理，先靠上面三个事实统计各 provider 的覆盖率。设计与证据见 `docs/design/cloud-agent-stop-reason.md`。
- `canvas_read_storyboard` 默认 creative 视图；非 full 默认且最多100行，full 默认1行、最多20行，实际分页同时受字节预算限制。fields 选择创作列，missingAnyFields 在选行后、分页前筛选任一列的缺口；nextRead 保留续页条件，nextReads 指向被截断字段的原文续读。行正文返回真实 rowId，响应返回 snapshotHash；覆盖范围、提示词来源与编辑短回执见 Agent 读取专题。
- 技能正文只进入模型会话：原生 `read` 结果保存为 Pi `toolResult` 检查点，不进入 Go 画布工具批次；历史传统技能调用仍可展示和统计，但不再注册执行工具。公共运行视图和事件只保存安全元数据，不复制正文或 worker 绝对路径。
- `context_pressure` 事件同时保留两套**不混画**的读数：`estimatedInputTokens` 是 `readingScope=next_request`、`estimateMethod=local_v1` 的下一请求同口径估算，供前端圆环、预算条和跨步骤趋势使用；`pressureTokens` / `tokenUsage` 是 `providerMeasurementScope=previous_request` 的上一请求上游实测，`projectedTokens` 则用该锚点加本地有符号增量，专供压缩决策和诊断。这样 Provider 锚点首次到达时不会把“换了一把尺子”画成上下文突然回落。锚点与本地估算差出一个量级（<0.5× 或 >2×，通常意味着换了模型或计量口径）时不采信，事件带 `anchorRejected` 并继续使用估算。真正的下降仍可能来自每步临时事实帧重建、图片裁剪和语义压缩，界面会把它们与口径切换分开说明。事件还带 `breakdown`：三个桶（`system` 系统提示（含画布摘要）、`tools` 工具 schema、`messages` 会话消息（含工具结果））的字节与估算 Token、`envelopeBytes` 协议外壳余量、`tokenScale` 与每个桶/分段的 `scaledTokens`，以及 `systemSegments` 系统提示内部分段。兜底判据为 `compactionThresholdBytes` 48 KiB / `historyMessageThreshold` 16 条 / `requestHardLimitBytes` 192 KiB。
- **输入预算的三段算式**（`context_pressure` 的 `contextWindowTokens` / `reservedOutputTokens` / `overheadTokens` / `inputBudgetTokens` / `budgetSource`，压缩事件另带 `compactAtTokens`）：输入预算 = 上下文窗口 − 输出预留 − overhead，其中 overhead 是工具 schema、协议包装与兜底轮的比例预留（窗口的 4%，夹在 4096–32768），输出预留取「用户填的预留输出」与「渠道模型能力声明的最大输出」中的较大者；预留被配成不小于窗口时夹到半窗。压缩触发线是输入预算的 85%，`compactAtTokens` 给出该线的整数读数（下取整），实际判据仍是 `projectedTokens / inputBudgetTokens ≥ 0.85`。`budgetSource` 说明这份预算的来源：`channel-model` 表示按渠道模型解析（任务行的 `channel_model_id` 在画布 Agent 上一直为空，因此主要靠请求里的 `channelId` + `channelModelKey` 兜底），`logical-route-intersection` 表示逻辑模型取**所有可用文本路由中最小的可用输入容量**（逐条算「窗口 − 输出预留 − overhead」再取最小值）——路由选择发生在上下文装配之后，装配按大窗口做、执行落到小窗口时请求会被上游直接拒；只分别取「最小窗口」与「最小输出预留」会在两者落在不同路由上时高估小窗口线路的容量（512k/64k 与 1M/16k 会算成 475520，而 512k 线路实际只有 427520）。窗口未声明（0）时不下发这几个字段，判据退回 48 KiB / 16 条的字节口径。
- **取消/失败时停在压缩上的轮次要收干净**：语义压缩是「暂停步进 → 压完继续」的中途动作，本轮若在压缩期间被取消（或已经失败），调度器不会再推进这一轮——收尾路径（`CleanupPending` 清理，HTTP 取消与后台调度共用）会先把服务端保底检查点落盘并清掉 `contextCompaction`，再取消压缩子任务。否则 `GET /agent/runs/:id` 会永远显示「正在压缩」、那份检查点永久丢失（dev 实测发生过：`ag5a8fcabe` 在 `usableInputTokens=12800 / ratio=1.44` 请求压缩后被取消，压缩任务 `ag50e15ee` 随之取消，之后既没有 `context_compacted` 事件也没有检查点）。收尾只落检查点与 `context_compacted` 事件（`mode=fallback`、带 `reason`），**不改写终态**：`cancelled` / `failed` 就是终态，不会被"复活"成 `completed`。
- **任务与账务事实每步现读回灌**：`context_pressure` 之外，每一步的请求尾部会带一条运行时消息（`kind=task_facts`），列出最近 32 个任务的事实投影（`taskId` / `taskStatus` / `taskType` / `operation` / `submissionOutcome` / `providerTaskId` / `phase` / `nodeId` / `error` / `billing`），更早的只报 `olderTaskCount`。事实全部来自数据库现读而不是事件记忆（状态里只有一窗事件，靠它推断"提交过什么、花了多少"会得出错误结论）：`submissionOutcome` 以有无上游任务 ID 为准（`accepted`），已进入终态但没有 ID 的报 `completed`，行被删掉的报 `unavailable`，不会凭本地状态编造上游回执；失败任务的 `error` 走媒体任务的脱敏口径，带 URL / 凭据字样的一律换成固定文案。消息里同时带 `authority`（`状态观察，不是执行或重复提交的授权`），避免模型把"看到某任务成功过"当成再提交一次的授权。这类每步重拼的运行时消息（待办清单、事实帧）在持久化与下一步装配时会被剥掉，只保留在当步请求里；空输出催办与输出/参数纠错那三类一次性指令则**不会**被剥掉（否则重试时模型看不到纠正要求）。
- 运行态体积治理：`canvas_updated` 只下发增量——几何变化只发坐标字段，分镜行编辑只发变化的那几行（前端按行 id 三方合并；删除行下发完整旧行、新增行下发完整新行，本地改动过的行仍然是冲突而不是静默覆盖）；单步净增超过 15KB 时，把最旧的画布增量折叠成 `canvasPatchSlimmed` + `requiresRefresh`（客户端改为拉全量画布），事件序号与游标不受影响。
- **轮内不再卸载工具正文**（2026-09-21 删除）：正文卸载（会话消息 ≥40 KiB 或 >24 条时，把可重新读取的正文换成骨架）是"别把 `state_json` 顶到 512 KiB"的副产物——检查点拆分后消息已经搬出 `state_json`，这个动机不存在了。保留它的代价反而更明确：① 它按**字节**判据改写历史**中段**，会作废其后的前缀缓存（provider 每步都按前缀命中计费，实测这个部署的命中数以 1,056 token 的块为粒度，改中段 = 作废改点之后那一段）；② 被卸载的正文下一步往往就要用，模型只能重读，而"卸载省下的是便宜的缓存命中 token、重读花掉的是全价的未命中 token"，实测 dev 上一轮能卸载 14 次、同一 SKILL.md 被读 5 次。现在轮内只有一种裁剪：**图片**（超过保留轮次的看图结果换成文字回执，落 `context_images_pruned` 事件，含 `prunedImages` / `retentionRounds`）。上下文治理只剩两级：图片裁剪 → 语义压缩（token 口径 85%，无窗口时退回 48 KiB / 16 条）。修复历史中段的动作一律不做，宁可让压缩从**头部**整段重写一次（一次代价），也不改中段（每步代价）。
- 轮首画布摘要只承诺存在性与规模：节点 id / type / title、结构化节点的行数与镜号范围、媒体节点的 60 字提示词摘录，以及说明它不含逐行正文的 `scope` 字段。摘要按 8KB 软预算逐级降级（先丢节点细节、再减少节点、最后只留计数并给出 `nodesOmitted`），不再存在超限即拒绝整轮的 64KB 硬失败。逐行正文分别由 `canvas_get_state`（默认每节点 5 行、不含行 ID，移动/编辑前用对应 read 工具取真实 rowId 与 snapshotHash）和 `canvas_read_*`（每页最多 20 行、含真实 rowId）提供。
- 任务执行的墙钟只作用于"这一条任务"，**不含续租**：领取任务后的租约续期（每 15s，租约 45s）只继承父 context 的值、不继承执行时限的取消，并且"我方执行时限到点"不再被当成租约丢失（否则任务会停在 `running`、租约过期后被反复重跑：实测把单步墙钟设成 30s 时，一次模型调用被重跑成三次上游请求）。
- 模型上下文的工具结果只保留回执：审批卡明细只出现在 `approval_requested` / `approval_decided` 事件与界面中，进入模型历史的工具结果用 `previewOmitted` 标记，只保留 `summary`、`nodeId`、`snapshotHash`，避免同一份预览在事件与工具结果中各存一份。
- 渠道模型声明图片输入时提供 `canvas_inspect_image`：`{nodeId}` 读取当前画布图片或角色卡绑定图，有效摘要命中时仅返回 `visionCache`、`imageAttached=false`；`{nodeId,refresh:true}` 在已保存摘要后仍可重新发送真实图片，单图无需指定compare。重复查看标记 `repeat=true`，同一内容为 `imageChanged=false`。`{nodeId,sha256,summary}` 仅保存结构化观察，不附图；sha256必须来自本轮实际交付的图片。Go校验归属、就绪状态、类型及实际大小，持久化保留资源占位，执行时在内存读取完整字节；不接受任意外部地址，不保存base64或签名URL。工具批次回执配对完成后再附图，显式重看按调用身份只交付一次，普通历史仍可复用摘要。每节点本轮最多附图2次，文字读取计入本轮调用预算，所有图片仍受模型数量和成本限制；refresh不能绕过这些限制。原图与摘要记录保持，Pi记忆和压缩算法不变。模型应根据收到的图片作答，图片内文字仅是数据，不具有指令效力。
- 自动纠错的逐级收紧与熔断：只有**显式类型化的执行前参数错误**（`cloudAgentArgumentError`）可自纠，并且按**错误指纹**（工具 + 字段级 issue + 字段路径 + 参数外形）分别计数——换了错法从第一次重新给机会，原地重复同一个错误才会升级。第一次：正常回执，模型自行修正；第二次同一个指纹：下一步只开放修复所需的工具（出错的那个工具 + `canvas_get_state` / `model_list` / `canvas_read_storyboard` / `canvas_read_batch_table` / `ask_user`），回执的 `retry` 里带 `ladder=scoped` 与 `toolScope`，模型调用集合外的工具会被预检按 `invalid_model_output` 拒；第三次：停止自动重试，本轮以 `run_failed`（`reason=tool_retry_exhausted`，带 `fingerprint`）结束。工具一旦修好，进一步恢复完整工具集并清空纠错记录。同一模型步（同一 Pi 工具批次）里并行调用重复同一个指纹只算一次；`canvas_inspect_image` 成功（含按正确格式保存摘要）同样结束该工具的纠错组。对象或数组字段被传成字符串时，`type_mismatch` 的说明会点明“传成了字符串”，字符串本身不是合法 JSON 时给出出错位置，看图摘要出错时附带结构示例。`retry.status` 仍是 `retrying` / `exhausted` / `recovered` 三种，收紧信息是附加字段。

- strict function calling：文本模型能力合同可声明 `text.strictTools=true`，声明后本步的每个工具定义会带上 `strict: true`（上游按 schema 约束采样）；上游返回"不认 strict"一类错误时自动去掉标记重发一次，并把该渠道模型记入进程内拒绝名单，后续请求不再尝试。**默认不下发 strict**（未声明即不发），因为多数 OpenAI 兼容上游不支持它；无论是否下发 strict，服务端的本地 schema 预检都照常执行，strict 只是额外一层。
- 工具目录使用 `cloud-agent-tools/v6`。`pi-native` 保留受限 `read` 和 Pi 默认技能目录装配，不再注册传统技能搜索、读取工具。技能文件仅限本轮冻结白名单，不发现宿主机技能。
- 工具批次预检：模型一次返回的多个工具调用在执行前先过一遍预检——工具必须在本轮工具表内、必须获本轮授权、参数必须满足**本轮下发的 JSON schema**（缺必填字段、类型不符、未定义字段、枚举/上下界越界、数组超限都在这里被拒），并且**每一步最多执行一个写入或生成调用**（只读工具不受限）。命中预检的调用不会进入业务代码：不读画布、不申请审批、不提交任务，回执按字段级参数错误（`reason=invalid_tool_arguments`、`field`、`issue`，并附本轮 `parameters`）交回模型自纠；同一批里第一个写入未通过校验时，后续写入整批取消，回执标 `errorClass=call_skipped`、`admission=batch_cancelled_after_write_failure`；同批第二个及以后的写入以 `admission=single_write_per_step` 跳过，提示下一步单独提交。批次策略跳过不算参数错、不消耗自动纠错名额，也不会改动画布。旧检查点里的批次没有预检结论时按原行为直接执行。
- 当前共享目录共 33 个工具，L0 并集 25 个、L1 8 个；父子代理身份、权限、画布上下文及开关继续裁剪每轮实际目录。节点整理 `canvas_arrange_nodes` 属于 L0，在具备画布写权限时从首步披露。L1 包括分镜 3 个、批量表 2 个、素材和角色 3 个。画布已移除预演和导演的 10 个工具，明确意图或历史场景不能重新开放；旧图片转导演工作流在创建任务前被拒绝，历史数据保留。绘图原生读写、拆图层、OCR 和标注专用工具已移除；图像分析走模型多模态，视觉修改走参考生图。画布写入要求 `contextScope: ["canvas"]`，禁止 shell、任意网络请求和外部 MCP。
- 新压缩采用 Pi 0.87.1 原生 `compact()`：按 token 选择保留边界，长工具轮次可分别生成历史摘要与轮次前缀摘要。Go snapshot 的 `compactAtTokens` 与 Pi 触发设置一致；摘要输出上限独立计算。每个摘要子调用仍是 Go 的 `cloud_agent_context_compaction` 任务，按单步墙钟计时、不占模型步数，重启复用同任务。同一轮最多压缩 4 次。Pi 语义摘要写入检查点的 `historySummary`，执行和待办事实由 Go 提供；固定 JSON 合同仍为 version 1、最长 64 KiB。上下文由检查点帧、确认回执和 Pi 切点后的原文组成，保留完整工具调用与结果，不再固定最近两轮。旧在途压缩继续按原合同恢复。窗口未知时使用未配置的默认调度预算，不能将其当作真实能力。内部接口、存储与降级细节见[Agent 上下文压缩](/docs/backend/agent-context-compaction)。
- 压缩过程对外只有两个事件：`context_compaction_requested` 带触发读数（`basis` 为 `tokens`／`bytes`、`projectedTokens`、`usableInputTokens`、`compactAtTokens`、`pressureRatio`、`budgetSource`、`sourceBytes`、`turnCount`），`context_compacted` 带 `mode`（`model` 为压缩模型输出，`fallback` 为服务端保底检查点）、`resume`、`historyMessages`、`compactedTurnCount`、`droppedTurns`，降级时附 `reason`。压缩模型失败、输出不合规、或本轮在压缩期间被取消／失败，服务端都落保底检查点并写 `mode=fallback`；终态轮次的收尾只落检查点与事件，不改写已经失败或已取消的状态。
- **`context_pressure` 的读数契约**（上游 #601 的契约与我方 V2 读数的**并集**）：每次普通 Agent 步进的模型调用发出之前都会落一条 `context_pressure` 事件（`schemaVersion: 2`、`phase: "before_request"`），把"这次请求装了多少、离装不下还有多远"作为可观测读数下发，`requestId` 是本次请求的任务 ID。主读数是 `projectedNextInputTokens`：有可采信的上游实测锚点时等于"锚点实测 + 本地估算的有符号增量"（`tokenSource` / `measurementSource` 为 `provider`，`tokenScale` 给出实测÷估算的换算比例）；没有实测时退回纯本地估算（`tokenSource` 为 `estimate`）。两把尺子各有自己的名字、谁也**不覆盖**谁：`estimatedInputTokens`（`readingScope: "next_request"`、`estimateMethod: "local_v1"`）永远是本地下一次请求的估算，`pressureTokens` / `tokenUsage` / `providerUsage`（`providerMeasurementScope: "previous_request"`）永远是上游对**上一次**请求的实测，消费方不得把两者画成一条曲线（`tokenUsage` 是我方的对外名、`providerUsage` 是上游同义名，两者同时下发且数字一致）。本读数只增加可观测性：请求准入与正文裁剪的既有判据不变。
- 上游实测锚点的采信与治理：上游没有回 usage 的调用（`usage_available=false`）不定锚、不猜用量，读数继续用估算；只有"模型调用"这一步能配锚（媒体任务发的是另一份信封，`operation` 不匹配即跳过），并且只认本用户、成功、`text` 能力的那条调用。上游实测与本地估算差出一个量级时不采信（比值低于 0.5× 或高于 2×，通常是换了模型或计量口径），事件给 `anchorRejected` 说明原因并继续用估算。锚点可以跨步沿用，但**换模型、换线路、换系统提示或工具 schema、换模型窗口，以及超过 3 步未刷新**（`anchor.ageSteps`）都会作废：真机上出现过锚点被冻结、估算已经涨了 50% 而读数还停在老值的情况。
- 事件还带 `breakdown` 占用分布（与下方"输入预算"一条互为补充）：三个桶（`system` 系统提示（含画布摘要）、`tools` 工具 schema、`messages` 会话消息（含工具结果））各自的字节与估算 Token，协议外壳余量 `envelopeBytes`（tool choice、缓存键这类不属于任何桶的部分，单独报而不摊进桶里），按锚点比例换算的 `tokenScale` 与每桶/每分段的 `scaledTokens`，以及 `systemSegments` 系统提示内部分段（`policy` / `mediaPolicy` / `capabilities` / `execution` / `customSystemPrompt` 全局提示词 / `canvasRules` 当前画布规则 / `memory` 个人记忆 / `workspace:<文件名>` Node 装配的工作区块 / `other` 零头）。分段按编译顺序逐块量出，合计与 `system` 桶严格相等：编译之后才拼接的个人记忆由 `memory` 登记（到下一个工作区段为止，不把后续文件算成记忆），实际装配进信封的 Harness 工作区文件各自登记为 `workspace:<文件名>`，零头归入 `other`，不出现"分段加不到桶"的错觉。补报的 `after_request` 沿用该步准入时冻结的同一份分布。
- 窗口口径另在事件里平铺一份（与下方"输入预算的三段算式"一条互为补充）：`contextWindowTokens` / `reservedOutputTokens` / `usableInputTokens` / `inputBudgetTokens` / `overheadTokens` / `budgetSource`，再加 `compactAtTokens`（可重读正文就地裁剪的触发线，输入预算的 85%，只是给读数一个参照刻度、不是本读数触发的动作）。**没有解析到模型自己声明的窗口时不下发这些字段、也不给占用率**（`modelLimitConfigured: false`）：窗口未知就说未知，不拿兜底默认窗口冒充真实能力编一个百分比。
- `context_transition` 事件说明"读数为什么变"：`window_resolved`（窗口从未确认变为已确认，读数改用窗口口径，**不是**上下文变少）、`model_changed` / `route_changed` / `window_changed`（锚点因换模型、换线路或换窗口而作废；窗口变化另带 `before` / `after` 的窗口读数）。它只解释口径与锚点状态，不携带任何授权语义，也不改变执行边界。
- `canvas_list_node_types` 从服务端节点能力 registry 返回当前可用类型；可更新节点的 `updateFields` 同时包含字段类型、最大字符数和字段语义。模型不能从前端渲染器、技能或偏好文档推断额外能力。
- `canvas_apply_ops` 必须带 `snapshotHash`，每批最多 20 项；`add_node` 可省略坐标：服务端按画布内容落位（优先贴合本批连线的对端，否则追加到同泳道之后并避让已有节点），不再落到原点重叠；`update_node` 的 patch 额外支持 `x`/`y`（坐标绝对值上限 1e6）用于微调单个节点。支持新增文本、Markdown、图片、视频、音频、分组与分镜表节点，以及 `connect_nodes` 引用连线。媒体占位节点的 `content` 是提示词，不是媒体 URL；只建节点不提交收费生成。`update_node` 的字段映射完全由能力 registry 决定：文本 / Markdown 可改标题和正文，图片 / 视频 / 音频可改标题和下一次生成使用的提示词草稿；媒体更新参数中的 `content` 写入 `metadata.composerContent`，不会覆盖媒体结果 `metadata.content`、已提交提示词 `metadata.prompt`、任务状态或引用状态。锁定节点、删除、任意元数据写入、自连接、重复边与不存在的端点仍被服务端拒绝。
- `canvas_apply_ops` 创建节点、编辑提示词或连线不会提交生成任务，也不会改变已提交任务的输入；收费生成独立使用 `generate_media`。操作参数错误按数组项返回 `field`（例如 `ops[0].snapshotHash`）和 `issue`（例如 `unexpected_field`、`type_mismatch`、`required`），并附本轮工具 schema；不把未知字段误报成缺少其他必填字段，不回显任意参数键和值。
- `canvas_arrange_nodes` 只改节点坐标：`snapshotHash` 必需，`mode` 取 `auto`（有引用连线按依赖分层、否则按媒体类型分区）/`flow`/`byType`/`row`/`column`/`grid`，`groups` 把节点按给定顺序排成横向位置带（仅位置分带，不创建容器、不改层级），`align` 做对齐或等距分布，`gap` 调整组间距，`dryRun` 只预演。`nodeIds` 省略时整理全部可整理节点，锁定节点、背板等容器节点、隐藏批次子节点与已归属背板的子节点保持不动并在回执中说明；一次最多 50 个节点。整理与 `add_node` 的自动落位共用服务端布局实现（`backend/internal/canvas/layout`），与前端"自动整理节点"使用同一套常量与算法。
- `model_list` 复用生成面板的当前模型目录。生成前传 `mode` 和实际 `referenceNodeIds`（无参考传空数组），服务端读取当前用户画布内的就绪资源，按真实素材类型、数量及生成操作构建意图并调用统一能力匹配，不让多图生视频落入仅文生视频候选；返回 `intent` 供核对。空参数仍可浏览完整目录；空候选不降级到不匹配模型。每项的 `selection` 是 `logicalModelId` 或 `channelId` + `channelModelKey`，工具调用必须原样选择一种，不猜 ID 或混用；时长、画幅、音频、价格仍需核对返回配置，任务准入再次强校验。默认只返回选型所需的 `name`、`capability`、`selection`、`priceLabel` 与 `catalogHint`；需要 `options`、`profiles`、`defaults`、`priceTiers` 时显式传 `verbose: true`，避免为一次选型注入整份能力配置。
- `generate_media` 支持图片 / 视频 / 音频：必填 `mode`、`prompt`、`nodeId`（可续用草稿，无草稿时才新建）、`title`、有序 `referenceNodeIds`（无参考传空数组），再加一种模型选择；`snapshotHash` 可省略，省略时服务端使用当前画布内容快照。图片 / 视频要求 `size`，视频要求正数 `durationSeconds`，图片 / 音频时长为 0。可传来源节点 `sourceNodeId`、`quality`、视频 `videoGenerateAudio`。`sourceNodeId` 仅接文本 / 镜头提示词节点；参考图片、视频、音频只放 `referenceNodeIds`，无文本来源时留空且不重复传入。引用从当前画布节点的账号资源解析，校验归属、类型、就绪状态和模型能力，不接受任意 URL。图片生成仅接图片参考；视频可按模型能力接图片、视频、音频参考；音频生成当前仅支持文本输入。
- 普通媒体和分镜 `generate_media` 都要求画布已完成引用规范化；普通媒体在审批准备与事务内写入时共用门禁，无 `referenceFieldsVersion=1` 时返回 `reference_migration_required`，不新建草稿或生成任务。审批后撤销到旧文档同样会被拒绝，需先在画布中规范化再重新发起。
- `generate_media.prompt` 使用 `@图片1`、`@视频1`、`@音频1` 引用素材，各类型按 `referenceNodeIds` 的出现顺序独立编号，文本来源不占媒体编号。已有标签保留；遗漏的画布素材以“素材名称：@标签”补入 `【资产参考】`，不推断素材用途。节点入边由保存的引用字段派生并同步排列，草稿、审批和实际任务保存同一份带标签的提示词。未绑定的媒体编号和补齐后超过16000字符的提示词会在提交前被拒绝，模型自身的提示词长度限制仍由任务准入校验。临时标注图没有持久画布节点，不自动添加无法解析的编辑器标签；历史节点不自动改写。
- `model_list` 的每一项都带服务端签发的 `selectionId`（HMAC 签名、绑定签发用户、不透明）：`generate_media` **优先原样回传 `selectionId`**；兼容期也接受把 `model_list.selection` 展开到顶层参数（非空 `logicalModelId`，或完整的 `channelId` + `channelModelKey`）。两者互斥，被改写、跨用户、格式不对的 `selectionId` 都是字段级参数错误（`field=selectionId`、`issue=invalid_value|mutually_exclusive`、`requiredAction=fix_arguments`），提示重新调用 `model_list`。
- 参数选择与收费授权分开：用户明确说“随便 / 你决定 / 按默认”时，Agent 可从当前目录选择能力及预算匹配的模型，优先用户最近明确使用的可用模型，其次价格清楚的低成本选项；支持时沿用参考图原始比例，否则选目录默认，时长用目录默认。未要求音频且模型不支持时用默片。用户接受已推荐方案后不再要求特定确认口令；仅真正缺失或冲突的阻塞项一次性询问。本轮已有目录结果应复用。以上是 Agent 的参数选择策略，服务端仍强校验具体规格，不提供绕过预算 / 能力校验的默认兜底，也不绕过独立收费审批。
- 媒体参数先进行无任务、无预留账单的准入校验，再在同一事务创建草稿节点、来源 / 资产连线及待审批检查点；`approval_requested` 和运行中的 `approval` 携带目录真实 `modelName`。用户批准后才在事务中绑定任务、创建预留账单并更新检查点；拒绝或取消保留未生成草稿，不提交媒体任务。`nodeId` 可续用同类型、未锁定、idle、无任务且无媒体结果的空白占位节点或当前运行草稿；跨轮 Agent 草稿还要求原运行属于同一用户和画布、已结束且清理完成。续用必须重新读取快照并重新审批，不能复用旧审批、覆盖已有任务或成品，不能通过循环新建节点绕过限制。画布读取的 `generationDraft` 提示未提交、原运行状态、是否仍在清理及仍需审批；写入仍重新强校验。已明确审批的规格不得被模型默认值静默替换。媒体终态回写原节点；已删除或已换任务的节点不自动复活，结果仍可从任务中心查看。
- Agent 的 `snapshotHash` 只覆盖 Agent 读写的内容：忽略浏览器自己维护的账目（顶层 `viewport`/`updatedAt`/`chatSessions`/`activeChatId`/`directorScenes`/`showImageInfo`/`starterMode`/`backgroundMode`/`appearance`，节点的 `createdAt`/`updatedAt`，以及渲染测得的 `metadata.storyboardComposerHeight`）。浏览器在前端渲染后自动保存画布因此不再让 Agent 的下一步写入失效；节点内容、素材、锁定状态、连线与布局（位置/尺寸）变化仍需重新读取。`canvas_get_state` 另返回 `mediaSnapshotHash`，供 `generate_media.snapshotHash` 使用，并额外忽略节点 `position`；创建生成草稿后的审批也固定该内容哈希。因此移动图片或草稿不会使生成审批失效，执行时保留最新坐标；节点内容、素材、锁定状态和连线变化仍需重新读取并审批。画布修改与撤销继续使用包含位置的 `snapshotHash`，数据库写入仍使用完整快照 CAS。客户端刷新保留本地视口。发布前已按旧算法生成的待审批内容可能要求重新读取和审批，不自动替换旧快照重提任务。
- `read_only` 只允许读取；`request_approval` 对写画布和媒体生成暂停为 `waiting_approval`；`auto` 可在预算内执行已授权画布操作，但图片 / 视频生成始终独立审批，不能绕过。`maxGenerationTasks` / `maxVideoSeconds` 为非负整数，0 表示该项不设业务上限，正数按本轮累计执行；不再固定 8 次模型调用、8 个生成任务或 120 秒视频。积分上限仍必填且大于 0，实际报价在任务创建与预留积分前校验，时长必须符合所选模型的实际能力。失败事件保留具体错误和已有任务的 `taskId`、`nodeId`、`status`；媒体结果的 `phase` 区分 `admission` 与 `completion`，`taskSubmitted` 表达是否已提交。已提交的收费生成失败作为工具错误交回模型，整轮保持可继续，不得自动重试收费生成；只有生成结果无法回写画布时才把整轮标为 `failed`。模型应报告错误，不能自行删减提示词。
- 必须有当前用户已保存的画布。系统提示里的 `canvasSummary` 是节点目录，不是整张画布的 JSON：每条只含 `id`、`type`、截断后的 `title`，以及不支持操作的类型标记；最多列入 120 个节点，并按约 24KB 兜底截断，装不下的节点记入 `omittedNodes` 与 `totalNodes`。正文、提示词、媒体和结构化表不进目录，由 `canvas_get_state` 按 `offset` 每页读取 40 个节点、资产可引用状态及相关连线，按 `nodeIds` 精读最多 8 个节点（正文每字段最多 16000 字符），通过 `hasMore` / `nextOffset` 和字段 `Truncated` 判断是否完整。工具结果留在当轮消息里，历史压缩会卸掉可重读正文，不会在后续每一步把整页结果再打包一次。分镜表包含镜头、角色节点与资产绑定；摘要每页最多 20 行，精读每次 1 行，可用 `storyboardOffset` 翻页；单行叙事文本累计最多 24000 字符，角色 / 绑定各最多 16 项。上下文不含媒体 URL、任意元数据或未同步修改；节点名称不等于图像视觉识别。普通任务重试接口不能重试 Agent 任务。
- `plan_update` 接收 `items` 对象数组并整表替换待办清单，最多20项，`[]` 清空；返回 `items` 与 `pendingTitles`。清单由模型自行决定建立、更新或清空，在界面以 PlanBar 展示，并保留跨轮继承快照。权限为 `request_approval` 时，首次建立至少2项清单仍按既有审批规则执行；`auto` 直接写入。未完成项不触发催办、不阻止收尾、不消耗恢复次数，服务端也不会自动清空或标记完成；清单不增加执行授权。
- **完成闸门与最终答复的发布时机**：模型给出不带工具调用的正文时，它就是一次**候选收尾**，服务端先核对事实再决定能不能以它收尾——判据是用户插话与交付协议事实：子代理结果尚待收集（`pending_subagents`）或子代理须提交结构化结果（`structured_subagent_result`）、用户刚发来插话还没送进上下文（`pending_interjection`）、上一步正文被输出上限截断（`truncated_output`，截断的正文不是完整答复，一律先降级为过程说明）。通过时这段正文作为本轮**唯一一次**最终答复发布（`assistant_message` 带 `final: true`，本轮 `completed`）；未通过时正文降级为过程说明（同一事件带 `final: false`，用户仍看得到内容，但不会被当成结论），并落一条 `completion_blocked` 控制事件（载荷含 `blockers`、`attempt`、`maxAttempts`、`fingerprint`），同时把阻塞原因作为 runtime 帧交回模型继续本轮。带工具调用的正文一律是过程说明（`final: false`）。流式草稿（`assistant_delta` / `assistant_snapshot`，以及断线重放时由运行快照 `activeMessage` 补出的那条）同样不是最终答复：客户端把它们按 `final: false` 处理，等结算事件到达后再按真实标记更新同一条消息。待批审批与在跑的生成任务不需要进闸门：前者把运行停在 `waiting_approval`，后者（`advanceCloudAgentMedia`）会让本轮一直等到任务结束，两者都到不了收尾分支；`ask_user` 是刻意的收尾动作，不受闸门阻挡。
- `finish_run(summary)` 接收最终答复全文（必填），不检查待办状态。通过协议与交付保护后持久化最终答复、本轮 `completed` 和含 `committed/runId/finalMessageId` 的工具回执；同批剩余调用按“本轮已结束”回执收尾，重放不重复发布。尚有未送达用户插话时返回 `completionBlocked=true`、`requiredAction=answer_interjection`，不计恢复次数；子代理协议未满足时返回 `blockers` 与 `requiredAction=resolve_blockers`。正文路径的协议阻塞通过 `completion_blocked` runtime 帧报告 detail，界面事件仍为服务端控制行。协议恢复按阻塞原因计数，最多允许同一原因2次、累计6次，下一次超过上限时以 `run_failed.reason=completion_blocked` 停止；修改待办不改变计数，用户插话送达仍会重置。上一轮交接取 `final: true` 的答复，没有时退回最后一条正文。
- `ask_user` 给出一个问题与 2–6 个候选项后结束本轮，界面弹出选项面板；用户点选或输入后作为新一轮继续。运行中也可以用插话直接回答。
- 长期记忆：每个用户一份记忆文件，分「关于用户」和「工作笔记」。建 run 时冻结快照（`state.memory`）并把 `request.memoryMode` 定为当前模式（服务端推导，客户端值被覆盖），快照以 `agentContextSource: "agent_memory_doc"` 的 user 数据消息插在当前用户消息之前，不进 system，因此系统提示与工具前缀不随记忆内容变化；续轮历史不带上一轮的快照。用户这条消息含“记住、以后、下次、叫我”等说法时，快照末尾附一句提示。`memory_update` 一次最多 10 项 `add` / `replace` / `remove`，单条最多 400 字，全文默认 5000 字，每轮最多调用 8 次；同一调用 ID 重放不重复写。工具在 `memoryMode` 为 `auto` / `review`、非 `read_only`、非子代理时暴露；它写的是用户自己的记忆文件，不是画布，因此不进审批链（`request_approval` 下同样直接执行，修改可撤销）。执行时以文件当前模式为准：`auto` 立即生效，`review` 写成待确认修订，运行中被改成 `off` 时返回工具失败。成功写入或生成待确认修订时发出 `memory_updated` 事件（`status`、`revisionId`、`summary`、`changes`、`charCount`、`capacity`、`callId`），面板渲染为记忆卡（已生效的可撤销）。旧的 `remember_lesson` / `recall_lessons` 已从工具表移除。
- `canvas_get_state` 首次调用传 `{}`，仅接受可选的 `offset`、`storyboardOffset`（非负整数）和 `nodeIds`（最多 8 个字符串组成的数组）；当前画布由运行绑定，不接受 `canvasId`、`limit` 或 `page`。读取工具分别反馈非对象 / 多对象、JSON 格式错误、未知字段和字段类型错误。可纠正的工具参数失败在 `tool_failed.result` 及模型工具结果中返回 `reason: invalid_tool_arguments`、本轮已声明的 `parameters` 和 `guidance`；画布读取额外给出 `exampleArguments: {}`。失败调用仍如实记录，由模型修正参数后继续，不静默丢弃字段或自动重放写操作；资源归属、审批、快照和收费校验仍按原规则执行。
- `canvas_get_state.nodes[].outputReference` 的 `ready` / `issue` 仅表示该节点产物能否作为其他生成的参考，不诊断本节点的生成输入。`generation` 返回当前画布、当前用户所属任务的 `taskId`、`taskStatus` 和安全的失败 / 取消 `error`；无任务绑定为 `not_submitted`，无法验证归属或读取失败为 `unavailable`。节点无法作为草稿提交时返回 `submitBlockedReason` / `submitBlockedIssue`，与写路径共用节点准入规则；未被阻止不等于已获授权，草稿所属运行和审批仍在提交时校验。`task_get` 同样返回安全错误详情。`generate_media` 准入失败可返回 `snapshot_conflict`、`task_bound`、`target_locked` 等结构化 `reason` 和 `nodeId`，不自动选择新节点或重新生成。
- `task_get` / `generation` 的执行状态与回写状态分开：`succeeded` 不返回执行 `error`；回写失败仍通过 `writebackOutcome` / `writebackError` 暴露，不能因生成成功而隐藏。失败 / 取消任务保留脱敏错误，缺少详情不能伪装成成功。Agent 文本步骤的持久诊断为 `upstream_dns_failed` 时，`run_failed.reason` 同步该分类并明确提示检查渠道域名及后端 DNS，不自动重跑。
- `GET /agent/runs/:id` 的事件已全量落库到上游的 `cloud_agent_event_records`（append-only，主键 `(run_id, sequence)`）：默认返回尾部一窗并给出 `eventSeqBase` / `eventCount` / `latestSeq` / `eventsTruncated`，位置字段、增量读取与页大小见下方"运行详情的事件分页"两条；SSE `GET /agent/runs/:id/events` 按 `Last-Event-ID` 游标同样从事件表增量读。内存里只保留最近 40 条的尾部窗口（供运行视图首屏、续轮摘要、压缩事实与记忆提取直接读），窗口之外的按 `sequence` 分页读表，因此**运行记录不再占用状态体积、也不再把 512KiB 状态线变成能力上限**。窗口左移不影响历史：写路径只追加 `sequence` 大于旧水位的事件行。单条事件载荷在产生时封顶 128 KiB（超限压成 `requiresRefresh` 回执，不让整轮因一条过大的载荷判死）。事件保留期 TTL 未实现（事件永久保留）；画布删除只清事件上的画布归属、保留审计内容。`GET /agent/runs/:id` 返回运行信息；`POST /agent/runs/:id/cancel` 取消当前运行及活动子任务；`POST /agent/runs/:id/undo`（请求体可省略，仅接受可选 `reason`）撤销当前用户一次已结束运行的全部画布修改，返回 `{ revision, restoredNodeIds }`：只恢复本次运行改过的节点、连线和画布字段，其他节点上的后续编辑保留，撤销作为一次新修订经 Agent 写入路径落库并推送 `canvas_changed`；本次运行改过的内容之后又被编辑过时返回 HTTP 409 `reason=agent_undo_conflict`（`details.ids` 列出冲突对象），画布不变；运行仍在进行返回 409 `reason=conflict`，提交过生成任务或快照未完整保留返回 400，任务不取消、不退款；`POST /agent/runs/:id/approvals/:approvalId/decision` 接受 `{"decision":"approve"|"reject","reason":"..."}`，审批决定幂等且服务端校验归属。Agent 调用 `director` 工具（导演台）写入或预演前会追加 `director_open` 运行事件，载荷 `{ canvasId, nodeId, sceneId, shotId?, action, requestId? }`，前端据此打开导演台；`request_approval` 下先审批、批准后才发。`action=preview` 时运行挂起等待浏览器视口录制，前端完成后调用 `POST /agent/runs/:id/director-preview`，请求体 `{ requestId, videoResourceId?, error? }`（`videoResourceId` 与 `error` 必须二选一，视频须是当前用户已就绪的视频资源），成功返回 `{ accepted: true }` 并恢复该工具调用；运行不属于当前用户、`requestId` 未知、已完成或已超时返回 404 `reason=director_preview_not_found`。超时由 `CANVAS_AGENT_DIRECTOR_PREVIEW_TIMEOUT`（默认 120s）控制，到期后工具回执 `reason=director_viewport_unavailable`、`retryable=true`。
- `GET /agent/skills/usage` 需要登录，只聚合当前用户最近最多 200 次 Agent 运行的日志；返回技能启用次数、检索命中、成功/失败读取、总纲/卡片读取和最多 5 条最常读卡片路径，不返回技能正文。损坏的日志会返回错误而非静默给出不完整统计。
- 运行详情的事件**分页**：事件全量在 `cloud_agent_event_records`（append-only，主键 `run_id` + `sequence`），运行详情默认只返回**尾部一窗**（最新 40 条），并同时给出四个位置字段：`eventSeqBase`（本次返回的首条事件之前已入库的条数，不变量是 `events[i].seq == eventSeqBase + i + 1`）、`eventCount`（该轮次累计事件条数）、`latestSeq`（本次返回的最后一条序号，可直接作为下次 `sinceSeq`）、`eventsTruncated`（还有更早的记录没随本次返回）。不返回事件时 `eventsTruncated` 为 false，`eventSeqBase` 退回内存窗口在整条日志里的偏移。
- 运行详情查询参数：`?sinceSeq=<seq>` 只返回该序号**之后**的事件（增量 / 断线重连，单次最多 500 条，按 seq 升序）；`?eventLimit=<n>` 覆盖默认页大小，取值 1–500，大于窗口时由服务端从事件表往前补页。两个参数都必须是整数，越界或非法返回 400；游标追平或越界时返回空 `events` 而不是报错。读取一律走 `(run_id, sequence)` 的 keyset 分页（`sequence > ? ORDER BY sequence LIMIT ?`），不用 offset，也不会为这些字段载入整条日志。升级前把事件放在 `state_json` 里的旧轮次在事件表中没有行，读取回退到内存窗口，行为与升级前一致。
- 首次通过取消接口取消运行时记录一次 `run_cancelled` 事件，`source: user_request` 表示来自用户取消 API，并携带当时的 `activeTaskId` / `mediaTaskId`；此事件表示取消请求已接收，关联任务最终状态以任务查询及收尾状态为准。运行记录损坏或超限时优先保证取消和后台收尾，事件无法保存会记录服务端告警；旧导出日志不能据此追溯取消发起来源。
- `GET /agent/runs/:id/events` 返回 `agent_event` 和首次 / 状态版本变化时的紧凑 `run_snapshot` SSE；无变化时只发送 heartbeat。事件 `Seq` 在运行内递增；支持 `?after=` / `Last-Event-ID`，游标不是运行 ID，服务端把它作为运行详情的 `sinceSeq`，因此断线重连只读该游标之后的增量。`cleanupPending: true` 时即使运行已进入终态也会继续推送，直到后台收尾完成。前端应以快照恢复状态，代理只对这一精确路径关闭缓冲。
- 媒体生成是异步的：`generate_media` 提交成功即返回回执（`status: submitted`、`taskId`、`nodeId`、`pendingGenerations`），运行继续执行后续工具，不再停在这次调用上。生成结束后（Worker 读取快照、工具推进或看门狗每 60 秒巡检时）服务端回写画布，并追加 `generation_settled`（`taskId`、`nodeId`、`callId`、`mode`、`status`、`summary`、`error`，原位新版本另带 `versionId` 与 `adopted`）；同时把结果合并成一条「[系统通知] 生成结果」在下一步边界送达模型（送达事件 `generation_notice_delivered`），不阻止收尾。工具 `wait_generations` 在仍有进行中的生成时把运行挂起为 `waitKind: generations`、让出 Worker，最后一个生成结束时带结果恢复；没有进行中的生成时立即返回。取消或结束运行不取消已提交的生成，生成照常完成并写回画布；回写失败不再判死整轮，结果以通知如实告知。运行行的 `media_task_id` 记录最早一个待回写的生成，供巡检定位。
- `generation_task_created` 携带 `canvasId`、`nodeId`、`taskId`、`title`、`mode`、`referenceNodeIds`。草稿、提交、画布工具写入，以及媒体成功 / 失败 / 取消的真实节点变更，均在画布写入与运行检查点的同一事务持久化 `canvas_updated`。节点已删除或换任务时不伪造更新；`run_failed` 本身不代表节点媒体任务失败。
- 未注册 Agent 能力的节点不阻断整张画布读取：摘要和 `canvas_get_state` 仅返回基础信息，并标记 `agentSupported: false` 与原因；不暴露任意 metadata，不授予该类型的创建、修改、连线或媒体引用能力。
- `approval.preview` 和 `canvas_updated.actions` 是服务端根据同一解析、快照与 Capability 规划流程生成的解释信息，不是授权凭证。审批卡片明确列出新增/修改节点、节点类型、修改字段、名称变化和连线两端；执行事件保存同样的可读信息，供历史消息显示和点击定位。实际写入仍重新校验用户归属、`snapshotHash`、Capability、节点锁、预算和审批 `callHash`。
- 可纠正且尚未产生副作用的工具参数错误会在 `tool_failed` 的顶层及 `result.retry` 返回 `{ groupId, attempt, maxAttempts, status }`。`status=retrying` 表示 Agent 可按字段、schema 和示例自动纠正；同一工具累计三次仍失败时返回 `status=exhausted`，随后才产生 `run_failed(reason=tool_retry_exhausted)`。纠正成功的 `tool_completed` 返回同一 `groupId` 和 `status=recovered`。前端应按 `groupId` 折叠中间失败，不能将其显示为独立红色错误。权限、安全、存储错误以及已提交的收费生成任务不进入该重试流程。画布并发冲突（`stale_snapshot`、`entity_version_conflict`、`node_locked`，即用户与 Agent 同时编辑）不计入纠错次数、不收紧工具：只要两次冲突之间模型调用过读取工具（`canvas_get_state`、`canvas_read_storyboard`、`canvas_read_batch_table`、`canvas_read_content` 或 `director` 的 `read`），就按工具单独计数（`tool_failed` 带 `environmentConflict: { attempt, maxAttempts }`）；没有重读就原样重交仍按参数错误走上述梯度。同一工具连续 5 次冲突时不判失败，回执改为 `requiredAction=ask_user`、`message` 为「画布一直在变化，我先暂停：要等你编辑完再继续吗？」，并追加一次 `canvas_contention` 运行事件（载荷 `{ toolName, attempts }`），前端显示为系统消息「画布一直在变化，Agent 已暂停等你」；该工具成功即清零，新一轮运行重新计数。
- `canvas_updated` 包含 `canvasId`、`operation`、`callId`、`actions`、可选的 `preview`/`text` 和 `canvasPatch`。`canvasPatch` 为 `{ canvasId, updatedAt, nodes: [{ before, after }], connections: [{ before, after }] }`；新增对象的 `before` 为 `null`，仅包含有变化的节点和连线。当前工具不开放删除。节点 action 保存操作、节点 ID、执行前标题、类型、修改字段和可选的修改后标题；引用 action 同时保存来源与目标节点 ID、标题和类型，不要求前端从内部 ID 猜测对象。`callId` 用于合并同一画布操作的工具完成消息。
- 前端对增量按 40ms 窗口合批，三方合并远端基线、当前 Store 和编辑器，正常完成 / 失败无需全量 GET；保留无关节点编辑、拖动与视口，同字段冲突、删除或新任务绑定不强行覆盖。只有事件缺口、断流、增量冲突或没有增量的事件源需要全量校准，同一画布协调器最多每秒发起一次，单请求在途，期间重复通知合并为一次尾随校准。已识别增量协议后，相邻 `tool_failed` / `run_failed` 不重复触发整图刷新。
- Agent 创建 / 续聊请求在客户端先持久化完整正文、幂等键、父运行和消息 ID，再提交；网络超时或响应丢失只允许用同一正文和 key 有界重放，不能换 key 生成新收费轮次。客户端区分“服务端已明确返回错误”和“未收到服务端确认”，不再把 HTTP 409/500 一律描述成请求未确认。待确认记录损坏时对话暂停发送，不把它当成“从未提交”。
- 生成按钮与提交入口共用节点任务状态：排队 / 运行中不可重复生成，终态解除任务锁，历史 `taskId` 不永久禁用。聊天留痕保留节点名、引用与失败任务 ID，点击使用现有画布聚焦；已删除节点只提示，不自动重建。聊天缓存不重复保存增量中的完整节点正文。

Agent 的聊天列表缓存只负责 UI 恢复；运行、技能快照、审批、工具调用、子任务和事件均以服务端持久化状态为准。提交响应丢失时，客户端应使用同一幂等键重试，不生成新的提交。

运行返回请求选择器 `model`、`channelId`、`channelModelKey`、`logicalModelId`，客户端仅在同一选择器续聊时继承上下文读数。`context_pressure` 的 `normalizedInputTokens`、`projectedTokens` 和占用率显示最近有效上游输入用量，无实测时才用本地估算；`estimatedInputTokens` 独立用于诊断。成功模型步骤确认 usage 后立即发布 `phase=after_request`、`readingScope=latest_provider_request`，`requestId` 指向完成的任务。逻辑模型名称不与渠道模型键混比；备用路由成功后采用实际模型/渠道及其用量，无新用量且实际 provider 改变时作废旧读数。Pi 根据自己的原生计量决定压缩，当前模型窗口随后端 `modelLimits` 更新；Go 只恢复已有操作并发布 `context_compaction_requested` / `context_compacted`，前端不以展示占用率预测压缩。

媒体完成事件分别报告生成与回写结果：`tool_failed.result.status` 始终是媒体任务真实状态，`generationError` 是脱敏后的生成错误；`writebackError` / `writebackReason` 记录回写失败，不能覆盖生成错误。`targetNodeId` 保留原调用目标，`nodeId` 只在匹配到真实任务绑定时返回。回写原因包含 `canvas_unavailable`、`target_node_missing`、`task_binding_changed`、`result_resource_unavailable`，缺少可验证目标时为 `target_node_unknown`。终态 `run_failed` 同步提供目标节点、`generationStatus`、两层错误及回写 `reason`，并持久化 `failureMessage`。回写必须同时匹配原目标节点和任务 ID，不能仅凭另一个节点复制的 taskId 改写目标；恢复收尾同样使用任务持久化的目标信息。失败任务只承诺保留任务记录，不宣称已经生成可用媒体。

原生 Skills 使用 `native_skill_enabled` 和 `native_skill_read` 事件，展示技能名、冻结身份及包内相对路径；正文、临时绝对路径和内部文件元数据不进入公共运行视图。读取调用与 Pi assistant/toolResult 检查点配对，重复结果不能重复落事件。历史 Skills 的 `tool_completed` / `tool_failed` 继续按旧工具回执展示。

Worker 内部读取为 `GET /internal-agent/runs/:id/skills/:nativeName/file?path=SKILL.md&offset=0&limit=12000`，不经公网 `/api` 代理。除内部 bearer 和协议版本头，还检查用户、worker owner、lease epoch、运行状态、冻结版本与包完整性。`offset` / `limit` 以 Unicode 字符计，默认每页 12000、最大 12000；响应带 `content`、`offset`、`limit`、`totalRunes`、`hasMore` 及版本/摘要。仅白名单内的 UTF-8 `.md`、`.txt`、`.json` 文件可读，路径穿越、越权、二进制和损坏包明确拒绝。Pi loader 使用 `noSkills: true` + `additionalSkillPaths` 隔离宿主机技能，并严格核对发现集合；详见 [原生 Skill 运行时](./agent-native-skills)。

模型任务失败的 `run_failed` 事件保留 `taskId`，并提供安全分类 `reason`：`model_connection_reset`、`model_request_timeout`、`model_stream_stalled`、`model_connection_refused` 或 `model_task_failed`。中转在流内回报空闲断流（`Upstream stalled`）时先以 `model_failure_recovered`（`reason=stream_stalled_retried`）重试一次，再断才以 `model_stream_stalled` 结束，不再归为请求超时。账号活动任务上限只统计生成、上传等产出任务，Agent 运行自身的占位、模型步和上下文压缩任务不计入；生成因上限被拒时作为 `state_conflict` 工具回执（`requiredAction=wait_for_generations`）交给 Agent，不结束本轮。`text` 不透传原始上游错误，避免泄露地址和凭证；前端用事件类型而非摘要关键词判断工具成功 / 失败。失败不会触发自动付费重试。

## Agent 会话队列与默认发送方式

已有会话使用下列接口，均验证当前账号和会话归属，动态子代理对话不接收该用户消息入口。首条空会话仍由 `POST /api/agent/runs` 创建，结果未知时先核对原请求，不能另造会话。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET / PATCH | `/api/agent/ui-settings` | 读取或按 revision 保存 `defaultSendMode=interject/queue`；初始 interject，与系统提示词、workspace 和记忆独立 |
| POST | `/api/agent/conversations/:id/messages` | 提交 `{mode,expectedRunId,request,replyToQuestionId?}`，request 沿用 CloudAgentRequest 与原幂等键 |
| GET | `/api/agent/conversations/:id/queue` | 返回有序 items、revision、paused、pauseReason、awaitingQuestionId、questionRunId、latestRunId |
| PATCH | `/api/agent/conversations/:id/queue` | `{revision,action:pause/resume}` 暂停或恢复队列 |
| PATCH | `/api/agent/conversations/:id/queue/:messageId` | `{revision,prompt}` 编辑正文，或 `{revision,action:interject}` 提升；不能混用，已领取/派发时拒绝 |
| DELETE | `/api/agent/conversations/:id/queue/:messageId?revision=...` | 移除未派发消息，保留防止重放复活的收条 |
| DELETE | `/api/agent/conversations/:id` | 从历史列表移除会话；归档同步到其他设备，执行记录保留，正在运行及排队的任务继续遵循原状态 |

发送收条为 `{messageId,conversationId,delivery,queueRevision,runId?}`。delivery 是 queued、started、interjected 或 cancelled；queued 只表示已收下，未创建模型运行或预留费用。相同身份与原正文重试返回既有收条；编辑或移除后也不会被原 POST 覆盖。陈旧 expectedRunId 返回 `agent_conversation_stale_parent`，不会将输入静默改投另一个新轮。

问题回答必须为 interject 并携带当前 `replyToQuestionId`；缺少关联、问题已更新或已有另一份待发回答，分别返回明确409原因 `agent_question_pending`、`agent_question_stale`、`agent_question_answer_pending`。旧直接续聊和插话接口同样遵守问题与会话准入边界。默认方式修改只影响新的提交，不能重写未知请求的原接口、模式、正文或问题关联。

入队与实际建轮分别校验存储和执行准入。后台 RuntimePolicy.task 的 `agentMaxQueuedMessagesPerConversation`、`agentMaxQueuedMessagesPerUser` 默认20、100，范围1–9999；即时插话与唯一问题回答不会因普通待发条数受阻，仍校验其他配额。暂停和错误只返回可操作提示，不暴露存储连接细节。停止会话先暂停队列并作废在准备中的派发，再取消同一锁边界决定的最新运行。

完整字段与错误信封见 `/api/openapi.yaml`。会话目录中的 `archived=true` 是缓存移除标记，客户端不再加载其正文。升级需配套更新 backend 与 web，数据库迁移至67；不修改记忆算法。

## Pi worker 错误与有限恢复

`POST /internal-agent/runs/:id/recovery` 使用现有内部 Token、协议版本、用户、worker owner 与 session epoch 请求头。提交 `revision`、`class`（network/http_5xx/timeout/rate_limited/conflict/result_unknown）、`operation`（snapshot/control/checkpoint/model/tool/phase/renew/compaction），可附 `taskId`、`callId`、`httpStatus`、`retryAfterMs`。拒绝未知字段、超大请求、旧 revision 和过期 epoch；同 run/epoch/操作/分类重报幂等。返回 `status`、`attempts` 和可选 `nextRecoveryAt`；终态以新运行快照为准。

worker 仅在传输边界分类暂时故障。恢复前读取 Go 的权威快照，沿原任务/回执继续，不重发原工具或模型操作。Go 决定 1/2/4/8/16 秒退避并抖动，最大 30 秒；429 尊重 Retry-After，超过剩余 10 分钟窗口即终止。后端整体不可达或鉴权失败时共享暂停新领取，并按间隔探测协议恢复。

普通内部异常通过现有 `/fail` 结束本轮并安排清理；错误上报最多 3 次、总时限 15 秒，排队请求取消后立即退出且不会延迟发送。SDK 错误流仍将原始异常传递到共享边界；JSON 序列化错误不归为网络故障。原生 Skill 只把本地路径/范围拒绝作为可修正的工具结果，协议或冻结身份损坏直接失败。已提交但响应丢失先核对终态，取消和租约丢失立即退出。上报未确认时只记录安全分类，不宣称成功；后端持续不可达期间无法实时更新页面。公开 GET/SSE 仍沿用 `failureMessage` 和 `run_failed`，不增加公开请求参数。

## Canary Agent 调度协议

运行视图增加 `runtimePhase` 与 `waitReason`，区分模型、工具、审批和容量等待。内部协议为 `canvas-pi-wire/v2`，Pi SDK 保持 0.87.1；旧协议返回 426。`GET /internal-agent/events` 为内部 Token 鉴权 SSE，支持递增全局游标续传；`POST /internal-agent/capacity` 保存实例容量，运行 `/phase`、`/control`、`/release` 分别提交阶段、读取轻量控制和按 epoch 释放租约。工具 `/advance` 先保存幂等操作，再返回 pending 与 operationId。公开请求确认仍在持久化成功后返回，幂等键和公开运行 SSE 游标保持原合同。详见 [多会话事件调度](./agent-event-scheduler)。

路径前缀是 `/api`。前后端一起发布，不按 `/api/v1`、`/api/v2` 做路径版本。不兼容变更随版本一起改接口和调用方。

机器可读规范：运行中的 `GET /api/openapi.yaml`，源文件 `backend/internal/handler/openapi.yaml`。前端 TypeScript 仍走 `web/src/services/api` 的 `http`，不从 OpenAPI 生成客户端。

出站模型服务域名解析失败返回 HTTP / `code: 502`、`reason: upstream_dns_failed`，不归类为用户参数错误。公开消息不包含上游域名、DNS 服务器或请求 URL；原始解析错误仅保留在内部错误链。此分类不会自动重试、切换渠道或放宽 SSRF 校验；上下文取消仍按取消处理。

模型 HTTP 失败及经过 Provider 错误转换的业务失败，在通用提示后追加经过过滤的 `；上游：具体原因`，供任务错误和画布卡片展示内容安全、提示词、尺寸等可操作信息。只读取上游 `error` / `message` / `msg` / `detail` 消息字段，不回传整个 JSON；消息中的 HTTP(S) URL 隐藏，包含余额、账务、凭据、请求诊断或 HTML 的消息不追加原文，保留通用分类提示。后台响应拦截规则仍对最终用户文案生效；不会修改历史任务错误或改变重试、退款策略。

## 管理员 Agent 工具总数

`GET /api/admin/settings/agent-scheduler` 返回 `{ setting, toolCount }`；数量由当前后端工具目录计算，页面位于「Agent（beta）」，沿用后台皮肤圆角。更新配置继续返回保存后的 `setting`。实际每轮工具仍按能力、权限和任务披露。

快照注册、检测、比较、告警、快照管理和兼容领取机制已移除。Worker 的容量心跳和领取直接使用 owner，不携带工具快照身份；工具参数、权限、审批与运行租约校验继续生效。后端与 Worker 配套更新，参见 [Agent 工具目录](/docs/backend/agent-tools)。

## 管理员 Agent 默认技能

- `GET /api/admin/agent/skill-defaults`：管理员读取 `{ revision, items, totalFiles, totalBytes, contextEstimateBytes }`。每项含技能 ID、名称、固定版本 ID、版本标签、position、enabled（0/1）、status、fileCount、totalBytes；合计仅统计启用项，上下文预估是技能包整体读入的保守上限。
- `PUT /api/admin/agent/skill-defaults`：管理员提交 `{ revision, items: [{ skillId, skillVersionId, position, enabled }] }` 整体替换，返回新 `{ revision }`。私有、已删除、禁用技能或不属于该技能的版本均拒绝。revision 冲突须重新读取后再编辑。
- `GET /api/agent/skill-defaults`：普通登录用户可读取 `{ count, skills: [{ skillId, skillName }] }`，仅启用项，按 position 排序，不要求先安装技能。

默认技能只注入新会话，来源、版本和内容 hash 随成功建 Run 的事务冻结到会话；旧会话不随管理配置改变，被拒绝的请求不修改基线。公共 Run 技能摘要的 `source` 为 `global` 或 `user`；选择器据此显示旧会话的有效默认集合，新会话则读取当前默认摘要，默认技能展示不依赖市场分页或安装。用户可追加新技能，或将同 ID 的全局来源升级为用户来源；已选用户技能即使每轮重复提交 ID 也保持冻结版本，更新该技能版本目前需要新会话。

后端启动时把平台预置的内置技能 `yingce-canvas-tools-guide` 补种为首位启用的默认技能，每个技能只补种一次；技能不存在、已删除或已停用时跳过，管理员停用、调整顺序或移除后不再补回。已在默认集合中的平台技能随内置包更新改指当前版本，保留管理员设置的启用状态与顺序。补种和版本跟随都会递增 revision，基于旧 revision 的后台保存返回冲突；没有变化的重启不改 revision。

revision 保存在 `system_settings.agent_skill_defaults_revision` 对应设置行中；清空后仍递增，多个服务实例先锁定该行再执行 CAS。Run 准入保留总文件 1024、包总字节 16 MiB、初始 Skill 索引估计 512 KiB 预算；错误详情携带 `budget`（`files` / `total_bytes` / `context_bytes`）、`limit`、`actual`。Native 索引仅含转义后的名称、规范化描述和入口路径，并为 XML 包装与 Worker 绝对路径预留空间；入口正文、引用文件不计入初始上下文预算。后台保存时使用当前技能元数据预检，建 Run 时使用冻结版本元数据重新检查；`contextEstimateBytes` 返回索引估计，不等于 `totalBytes`。正文按需读取后，实际模型请求由模型窗口准入与压缩检查。单文件和单包原有预算保持不变。

建 Run 还会按当前模型可用输入窗口检查 canonical 请求及初始 Skill 索引的保守 token 估计，超限返回 `budget=context_tokens`；该预检同样不计尚未读取的入口正文与引用文件。

## 用户 Agent 设置

账户设置中的「Agent（beta）」提供自定义系统提示词和长期记忆文件管理。`GET /api/agent/settings` 返回 `{ systemPrompt, revision }`，仅读取当前登录账户；无设置时返回空提示词与 revision 0。`PATCH /api/agent/settings` 接收同样结构，最多 12000 个 Unicode 字符，拒绝非法 UTF-8 和除换行、回车、Tab 外的控制字符；保存时裁去首尾空白。revision 不匹配返回 409，重新读取后再保存；空字符串恢复默认行为。

自定义正文直接追加到创建运行时的系统上下文，包含在已有运行快照、上下文计量和上游缓存标识中；修改仅影响后续新运行（含后续对话轮次），运行中的任务保持原快照。该设置适用于本账户所有画布；当前画布的 Workspace 文档在其后注入并声明画布规则冲突时优先。本次用户明确要求优先，两者都不能扩展平台权限、预算或绕过审批；旧 user/project/canvas 偏好文档不再参与运行。

## 管理员支付订单

`GET /api/admin/payments/orders` 需要管理员权限，支持 `status`、`keyword`、`providerId`、`timeField`、`from`、`to`、`page`、`pageSize`。关键词匹配订单号、渠道交易号、用户名称、用户名或邮箱，也支持完整用户 ID 精确匹配。用户名和邮箱搜索忽略大小写；所有筛选同时生效，返回匹配总数和当前页订单。`timeField` 为 `created`（默认创建时间）、`paid`（渠道支付时间）、`credited`（入账时间）。`from`、`to` 为 `YYYY-MM-DD`，包含起止日期，按北京时间转换为左闭右开的时间区间；未填写的边界不限制，倒置日期或无效状态/时间口径返回 400。

每条管理员列表订单在原有字段之外包含 `user: { id, username, displayName, email }`，由当前页用户 ID 批量读取；用户不存在时返回 `user: null`，保留原 `userId` 与历史订单。此身份摘要仅用于管理员订单列表，不添加到普通用户支付接口或支付状态同步响应。

后台支付订单列表展示用户身份，点击名称打开用户详情；订单详情提供完整订单号、渠道交易号、用户 ID 和各阶段时间。同步支付状态与关闭订单位于更多菜单，关闭订单仍需确认。

官方易支付插件 `official-payment-epay` 通过既有支付接口接入，不新增业务路由。管理员必须显式填写可信支付网关；V1 支持 MD5 下单、查单与通知验签，未付款订单的关单仅关闭本地记录。V2 目前只支持 RSA 下单和通知验签，不支持查单、刷新收银台及自动关单；相应操作返回明确失败，不能按“订单已关闭”处理。启用前需在实际网关验收回调和到账，不能用插件安装成功代替支付链路验收。

### 支付对账筛选及 CSV 导出

`GET /api/admin/payments/reconciliations` 支持 `providerId`、`status`（`running` / `completed` / `failed`）、`from`、`to`（账单日期，包含起止日）、`page`、`pageSize`。`GET /api/admin/payments/reconciliations/:id/items` 支持 `result`、`page`、`pageSize`；`result=abnormal` 同时选出所有非 `matched`、非 `recovered` 明细，未指定或 `all` 表示全部。具体结果还支持 `matched`、`recovered`、`local_order_not_found`、`provider_record_missing`、`amount_mismatch`、`trade_no_mismatch`、`credit_failed`。

三个只读导出接口均在 service 校验管理员权限，返回 `text/csv; charset=utf-8` 附件，设置 `Cache-Control: no-store`。导出复用列表筛选条件，不受 `page`、`pageSize` 影响：

| 接口 | 参数与内容 |
| --- | --- |
| `GET /api/admin/payments/orders/export.csv` | 与订单列表相同的筛选；完整订单号、渠道交易号、用户身份、商品、渠道、金额、币种、积分、订单/渠道状态及各阶段时间 |
| `GET /api/admin/payments/reconciliations/export.csv` | 与对账列表相同的筛选；每日执行状态、总笔数、一致/补发/异常笔数、失败原因、发起人 ID 或系统、开始/完成时间 |
| `GET /api/admin/payments/reconciliations/:id/items/export.csv` | `result`；单次对账的完整交易明细及对账开始/完成时间，便于区分同日重跑结果 |

最多导出 10000 行数据（不含表头）；超限返回 400 业务错误，提示缩小筛选范围，不截断文件。无匹配数据时接口返回仅含表头的 CSV；前端无数据时禁用导出。导出不查单、不重跑对账、不补发积分。

对账完成不代表无异常，汇总保留异常笔数；失败记录仍可导出汇总及失败原因。明细仅允许已完成的对账，执行中或失败返回 409。对账重跑复用记录并替换明细，明细导出使用可重复读快照，保证汇总与明细来自同一次数据库快照。订单及关联用户身份也在同一快照内读取。

明细的“记录金额”附带“金额来源”：通常为渠道账单，`provider_record_missing` 为本地订单。该字段不声称同时保存渠道和本地金额，不根据订单当前值推算历史差额。订单金额和积分为订单数据，未支付订单的积分不代表已经发放。

CSV 使用中文表头、UTF-8 BOM、CRLF；金额按整数分精确转换为两位小数，积分从微积分转换并保留最多六位小数，时间表头注明北京时间。空时间留空。文本转义逗号/引号/换行，并在公式触发字符前加单引号；可被解析为数字或科学计数法的 ID/订单号也加单引号防止表格软件丢失精度，不生成 `="..."` 公式。通用 CSV 消费者可能看见该保护前缀，按文本导入并按需移除；仅 CSV 引号不能声明列类型。

前端使用已经应用到列表的筛选条件导出；更改条件后，先查询/筛选再启用导出，分页和刷新沿用已应用条件。明细抽屉支持“仅异常”和单独刷新，切换记录/筛选时取消旧请求，避免旧响应覆盖新记录。下载接口的 JSON 错误 Blob 会解析为业务提示，超量或重跑冲突不会被保存为 CSV。

## 信封

成功：

```json
{ "code": 0, "data": {}, "msg": "ok" }
```

失败：HTTP status 与 `code` 都不是成功；`reason` 是稳定机器可读原因。

```json
{ "code": 40301, "data": null, "msg": "账号素材数量已达到 100 个上限", "reason": "quota_exceeded" }
```

`code === 0` 才是业务成功。HTTP 200 但 `code !== 0` 必须当失败。前端判断类型用 `ApiError.reason` / `ApiError.code`，不要解析 `msg`。

## 错误码

`code` 默认等于 HTTP 状态。需要区分同一状态的不同原因时，使用 `status * 100 + n`。没有单独的 1001/2001 号段，以免和 HTTP 状态、现有 42901 以及重试判断打架。

| code | HTTP | reason | 含义 |
| --- | --- | --- | --- |
| 0 | 200 | — | 成功 |
| 400 | 400 | `invalid_argument` | 请求不合法 |
| 401 | 401 | `unauthorized` | 未登录 |
| 403 | 403 | `forbidden` | 无权限 |
| 404 | 404 | `not_found` | 资源不存在 |
| 409 | 409 | `conflict` | 冲突 |
| 409 | 409 | `project_name_conflict` | `POST /projects` 同一用户下已有同名项目；客户端可有限更换名称重试 |
| 409 | 409 | `agent_run_finished` | `POST /agent/runs/:id/permission` 运行已结束，所选权限只用于下一轮 |
| 409 | 409 | `agent_subagent_permission_fixed` | `POST /agent/runs/:id/permission` 子代理固定为只读，不能切换执行权限 |
| 409 | 409 | `agent_approval_not_permitted` | 批准审批卡时当前执行权限（运行中已收紧）不允许该写入；卡片保留，可切换权限后再批准或拒绝 |
| 409 | 409 | `agent_undo_conflict` | `POST /agent/runs/:id/undo` 本次运行改过的节点、连线或画布字段之后又被编辑过；撤销未写入，`details.ids` 为冲突对象 |
| 404 | 404 | `director_preview_not_found` | `POST /agent/runs/:id/director-preview` 的运行不属于当前用户，或 `requestId` 不是该运行当前等待的导演台预演（未知、已完成或已超时） |
| 409 | 409 | `skill_version_conflict` | `PUT /skills/:id/files` 的 `baseVersionId` 已不是当前版本；`details.currentVersionId` 为最新版本，客户端需重新加载后再编辑 |
| 400 | 400 | `drama_budget_exhausted` | 关联短剧的精修画布上创建生成任务时，作品已达到预算上限（预算含画布精修花费）；在短剧设置里提高预算后再生成 |
| 409 | 409 | `drama_segment_changed` | 把画布视频采用为剧情段视频时，段版本与 `expectedRevision` 不符或刚被并发修改；刷新单集详情后重新采用 |
| 429 | 429 | `rate_limited` | 限流（未细分） |
| 500 | 500 | `internal` | 内部错误 |
| 502 | 502 | `bad_gateway` | 上游失败 |
| 503 | 503 | `unavailable` | 暂时不可用 |
| 504 | 504 | `timeout` | 超时 |
| 40301 | 403 | `quota_exceeded` | 账号配额用尽（不自动重试） |
| 40301 | 403 | `storage_capacity_exceeded` | 账号文件容量不足，上传或媒体生成被拒；前端据此展示“购买空间”入口 |
| 40302 | 403 | `storage_read_only` | 账号超出文件容量且 7 天宽限期已结束，内容写入被拒；`details` 含 `usedBytes`、`totalBytes`、`readOnlyAt` |
| 40901 | 409 | `conflict` | 幂等冲突 |
| 42901 | 429 | `rate_limited` | 请求限流（可带 Retry-After） |

模型错误把已有字符串码放进 `reason`（如 `model_capability_not_supported`），`code` 仍为 400。

## 技能库分类 API

以下接口需要登录。技能库分类与技能广场共享分类分离：`skills.tag` 仍表示共享市场分类；用户技能库分类记录在用户自己的技能状态中，只影响该用户技能库和画布 Agent。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/skills/library-categories?scope=mine\|created` | 返回当前用户可见的个人分类和平台分类，以及所选视图下每类数量、全部技能数和未分类数量。`mine` 包含自己创建及已加入的公开技能；`created` 只统计自己创建的技能。 |
| POST | `/api/skills/library-categories` | 请求 `{ "name": "分镜", "scope": "personal" }`。`scope` 可省略并默认为 `personal`；管理员可指定 `platform`，该分类对所有用户可见、可分配和筛选。同一用户可见范围内分类名唯一。 |
| DELETE | `/api/skills/library-categories/:id` | 删除个人分类（仅分类所有者）或平台分类（仅管理员），只解除该分类与技能的关联，不删除技能。 |
| PATCH | `/api/skills/:id/library-category` | 请求 `{ "categoryId": "分类 ID" }` 设置分类；空字符串清除分类。仅允许对自己创建或已加入的技能操作，并且只能使用当前用户的个人分类或平台分类。 |

`GET /api/skills` 可带 `libraryCategoryId` 或 `libraryUncategorized=true`，仅用于 `scope=mine` / `scope=created`，且两者不能同时使用。它们可与共享分类筛选 `tag` 同时提供，结果需同时满足两个筛选条件。分类列表的数量不受搜索词影响，表示对应技能库范围内的完整数量。

技能列表响应中的 `categories` 是技能广场共享分类，包含 `value`、`label` 和 `count`；`count` 统计已启用且公开的技能，不受当前搜索词、分页和视图筛选影响。它与技能库个人/平台分类是两套独立分类。

| GET | `/api/skills/:id/files` | 当前版本的文件清单：`path`、`kind`、`mimeType`、`size`、`sha256` |
| GET | `/api/skills/:id/file?path=` | 单个文件；文本返回 `content`，二进制只返回 `binary=true`，文本超过 512KB 返回 400 |
| GET | `/api/skills/:id/file/raw?path=` | 原始字节，`Content-Security-Policy: sandbox`、`nosniff`、`no-store` |
| PUT | `/api/skills/:id/files` | 作者批量修改文本文件并生成新版本，见下文 |

`PUT /api/skills/:id/files` 请求：

```json
{
  "baseVersionId": "编辑开始时的 versionId",
  "operations": [
    { "op": "delete", "path": "old.md" },
    { "op": "rename", "path": "draft.md", "to": "references/camera.md" },
    { "op": "write", "path": "SKILL.md", "content": "# 技能\n..." }
  ]
}
```

- 服务端按顺序把操作应用到当前版本的完整文件集，再整体重建 ZIP、`skill_versions` 和 `skill_files`，并在同一事务里以 `current_version_id = baseVersionId` 为条件更新技能行；并发写入（另一标签页、GitHub 同步、技能信息抽屉）会让后到请求得到 409 `skill_version_conflict`，`details.currentVersionId` 为最新版本。
- 路径必须已经规范化：相对路径、不含 `..`、`.`、空层级、反斜杠、控制字符和首尾空格，最多 8 层、单层不超过 255 字节，不能使用 `.git`、`__MACOSX` 或 `.DS_Store`；文件与文件夹不能重名。
- `write` 只接受 UTF-8 文本，单文件不超过 512KB，且目标类型必须可按文本预览；已有二进制文件不能被覆盖。`SKILL.md` 不能删除或重命名。整包仍受 512 个文件、20MB 限制，单次最多 256 个操作，请求体上限与安装上传一致。
- `SKILL.md` 变化时同步 `skills.instruction`；frontmatter 的 `metadata.version` 作为版本号，缺省时使用时间戳。单文件 Markdown 技能编辑后包含多个文件时 `sourceType` 变为 `zip`，避免技能信息抽屉以 instruction 重建整包时丢失附属文件。
- GitHub 技能返回 409 `failed_precondition`，请在仓库修改后同步。内容与当前版本完全相同时返回 `changed=false`，不生成新版本。
- 成功响应 `data={ skill, files, changed }`；单个操作校验失败返回 400，`details.operationIndex` 指向出错的操作。

## 场景与道具图片

`PUT /api/projects/:id/assets/:assetId/image` 接收 `{ resourceId, expectedVersionId }`，返回标准信封 `data={ asset }`。只允许当前用户在自己项目内，为场景或道具绑定本人已就绪的图片；资源必须有有效尺寸和图片 MIME。两个字段均必填，过期版本拒绝，主版本必须属于目标资产。

项目资产摘要可包含 `visual={ definition, status }`：definition 保留描述与提示词，status 为 `missing|ready`。未出图的设定使用 `entity`；真实图片绑定后，同一资产使用 `image` 和真实资源定位，旧版本及图片引用保留。继续使用现有资产、版本、表现表，无数据库迁移。

受管图片任务使用 `metadata.operation=project_asset_image`、`projectAssetId` 和 `projectAssetVersionId`，由任务成功事务绑定资源，媒体保存恢复同样适用。结果的 `projectAssetImageStatus=bound|stale` 表示已绑定或资产版本已变化；stale 仍保留生成文件，不能自动重发收费请求。历史画布图片匹配只信任服务端版本表现记录，不信任客户端自报的历史。

| `POST /dramas/:id/canvas-assets` | `{ resources: [{ resourceId, title?, category? }] }`（1–64 项）为投送到画布的短剧媒体登记素材记录：画布保存要求媒体节点由当前用户的素材引用资源。素材 ID 由资源确定（`drama-<resourceId>`），同一资源只登记一次，只建素材入口不复制媒体。不存在、未就绪或不是图片/视频的资源跳过、不让整批失败；返回 `{ assets: [{ resourceId, assetId }] }`，缺少的资源由前端决定是否中止投送 |
| `GET /dramas/:id/takes?ownerId&kind` | 版本记录：`kind` 为 `cast`（`ownerId` 是设定 ID）、`video`（剧情段 ID）或 `final`（集 ID），最多 50 条、新版本在前。每条含 `version`、`resourceId`、`taskId?`、`prompt`（截 300 字）、`durationMs?`、`createdAt`、`current`，以及来源 `source`：`pipeline` 流水线生成、`upload` 制作台上传、`canvas` 从精修画布采用（按产出任务所属的画布或采用标记判断，不新增列）。同时返回对象当前的 `currentResourceId` |
| `PUT /dramas/:id/episodes/:episodeId/segments/:index/video` | 把精修画布上的视频采用为剧情段当前视频：`{ resourceId, taskId?, cascade, expectedRevision? }`。资源必须属于当前用户且是已就绪的视频；`expectedRevision` 与段版本不符返回 409 `drama_segment_changed`。写入在一个事务里完成：新增版本记录、按段版本 CAS 改写视频并递增版本（调度中在途的生成结果因版本不符只进版本库，不覆盖采用的视频），取消本段排队中的重新生成，已有成片标记过期，已完成或正在合成的集退回视频阶段。默认只换本段；`cascade=true` 时后续已有视频的段重新排队生成（首帧换成新视频的尾帧），并按 `start` 的校验恢复制作，被拒原因放在 `resumeError`。写入后在请求内抽尾帧并按实际时长校准 `videoSeconds`，失败时段标记 failed 并写明原因（`videoError`），超时由调度循环补做（`tailPending`）。返回 `{ adopted, unchanged?, requeued, paused, tailPending?, tailError?, videoError?, videoSeconds?, resumeError? }` |
| `GET /dramas/:id/chapters/:chapterId` · `PATCH …` | 读取单章原文 / 修改原文 `{ title?, text? }`（不能超过 1.2 万字与原字数中的较大值）；已写好的剧本不自动重写，需再调用 `rescript` |
| `DELETE /dramas/:id` | 删除作品与全部制作记录 |

编排由后端调度循环推进，浏览器只提交意图；制作台目前按 3 秒轮询摘要和当前集详情，没有新增 SSE，也不需要调整代理缓冲配置。模型选择只接受逻辑模型或系统渠道模型；浏览器自定义渠道密钥无法驱动无人值守流水线。

### 参考图尺寸

设定参考图的画幅通过尺寸参数约束，不只写在提示词里：场景与道具固定 16:9，角色按参考图方案（自定义方案可选 16:9 / 4:3 / 1:1 / 3:4 / 9:16）。`settings.assets.resolution` 可指定分辨率档位 `1k` / `1.5k` / `2k` / `4k`，空串按图片模型默认档位。提交时把画幅换算成所选模型在该档位下接受的 `size`（像素或比例），模型有独立分辨率参数时同时下发 `imageResolution`；只在宽高比相差不超过约 20% 时替换（16:9 可落到 3:2），否则不提交并让这张参考图失败、写明原因，不再退回模型默认的方图。模型不能指定尺寸、没有接近的尺寸或不支持所选档位时，创建作品与保存设置返回 400。生成结果的实际宽高与要求画幅明显不符时（例如模型无视尺寸参数返回 1:1），结果只进入版本记录、不设为当前参考图，设定标记失败并写明实际尺寸。估算按实际提交的尺寸与档位报价。

### 剧情段视频画面

剧情段视频按作品画幅出片，画面参数只按所选视频模型的能力合同换算，与任务准入同一份配置：

- 声明了画面比例（`video.ratios`）的模型：作品画幅在列表里时发送 `size`（如 `9:16`），不在列表里视为给不出。
- 能力里带 `fixedScreenSpec` 的模型（如 AutoDL）：没有独立比例参数，任务准入会清空 `size`，横竖由完整分辨率标签表达。从 `video.resolutions` 里挑与作品画幅一致的标签作为 `vquality` 发送：标签写了像素（`768p竖(768*1376)`）或比例（`736p(1:1)`）的按数值判断，否则“竖”按 9:16、“横”按 16:9；优先默认分辨率，其次与默认分辨率同档（默认 `768p横`、竖屏作品取 `768p竖`），再按配置顺序取第一个。3:4、4:3 只有“竖 / 横”标签时视为给不出。
- 既没有比例也没有 `fixedScreenSpec` 的模型视为给不出任何画幅。

给不出作品画幅的视频模型：创建作品、保存设置与按段生成返回 400；已排队的段提交前失败并写明原因，不调用上游，避免模型按自己的默认画幅（多为横屏）出片。`videoGenerateAudio` 按模型能力发送：声明同步出声的模型为 `"true"`，否则为 `"false"`。估算报价使用同样的画面参数与声音开关。

### 精修画布

短剧是事实源与调度方，关联的画布是精修台：前端按需把设定、剧情段与成片投送到画布（节点 `metadata.dramaRef` 回指短剧对象），写回只经显式采用（设定参考图走 `PUT …/cast/:castId/image`，段视频走 `PUT …/segments/:index/video`），没有双向自动同步。

- 预算口径：`GET /dramas/:id` 的 `production.spentMicrocredits` 是作品总花费，含关联画布上生成任务的花费；其中画布部分为 `canvasSpentMicrocredits`。画布花费在读取时汇总：任务的 `project_id` 是关联到作品的画布，按其计费订单下单金额计（已退款除外，在途订单也计入），口径与流水线一致。派发、继续制作与修改设置都按总花费判断预算；关联画布上创建生成任务时作品预算已用完返回 400 `drama_budget_exhausted`。
- 资源保护：短剧表直接持有的资源（设定参考图、剧情段视频与尾帧、成片以及全部版本记录）在资源引用快照里记为 `短剧` 引用，素材“彻底删除”与 24 小时孤儿资源清理都会保留它们。
- 段视图新增 `revision`（采用时的乐观并发校验）与 `videoSeconds`（当前视频进入成片的秒数，与成片时间线一致）。
