# Agent 工具目录

管理员在「Agent（beta）」查看当前工具总数。数字由后端当前工具目录实时计算，包含原生技能读取和父子代理的工具全集；实际每轮可用范围仍按权限、任务、上下文和开关筛选。页面读取失败时显示暂不可用，不把未知状态显示为零；重新读取配置时同步更新工具数量。卡片沿用后台皮肤圆角。

`GET /api/admin/settings/agent-scheduler` 返回 `{ setting, toolCount }`。该接口继续要求管理员身份，数量不是可编辑配置项；更新配置继续返回保存后的 `setting`。

调度设置包括每执行器调度槽、驻留上限、每用户与每画布驻留上限。`maxResidentPerUser` 默认32，在数据库准入事务内统计跨 Worker 的有效租约，并先做用户公平、再做用户内部画布公平；配置热更新不会中断已有会话，降低上限后等待自然排空。工具调用预算仍由资源与策略中的限制控制，不以驻留数代替模型并发数。本地部署资源预算见生产部署专题。

## 披露与执行

工具先按能力和权限进入合格目录，有画布时直接披露 storyboard、角色卡、素材查询和绑定；批量表保持原条件。预演和导演的 10 个工具已从画布目录移除，历史场景及用户意图均不能重新开放；历史场景数据保留。参数校验、单次写入、归属、快照冲突、审批、预算、运行租约和回执幂等继续由原有执行路径约束。

`canvas_arrange_nodes` 属于 L0，具备画布写权限时从首步披露，无需整理、排版或对齐关键词。当前工具数量以运行时目录为准；只读模式不提供节点整理工具。

Worker 的首次及后续模型预检只提交当前 `allowed` 的具体工具，与实际模型请求保持一致。服务端保存的完整工具目录包含尚未披露的 L1，不能直接作为预检工具列表；原生技能 `read` 继续随原生技能运行披露。

Worker 直接使用服务端下发的工具定义。启动不读取本地工具制品进行比对，不登记工具快照；心跳和领取不再携带快照身份，也不按快照兼容性筛选执行实例。运行总览中的工具快照管理、检测、告警、诊断导出和按快照排空入口已移除。

## 统一分镜工具

合同 v18、系统策略 v26。新建 script 并写入 composerContent，风格与要求保存为相连文本节点，再 storyboard.split；局部修改用 resplit，连续 rowIds 和用户原话由调用方提供，其余上下文由服务端读取。read 默认附 Markdown 表，保留分页与字段投影；update 仅做少量指定行更新。lock/unlock 管理保护；锁定镜头拒绝所有写动作，unlock 除外，共享引用影响到锁定行也拒绝。

split/resplit 与媒体共用 PendingGenerations、系统通知和 wait_generations。提交、账务预留、任务绑定和 Agent 检查点同事务提交，遵循本轮积分与生成数量上限。当前工具步骤只收到 submitted/taskId，写回完成后在同一运行的下一模型步骤收到结果及新旧行对应关系；依赖结果时挂起，完成后继续。旧三个分镜工具不再注册，冻结会话调用旧名时返回明确退役提示。

## 参数语义与运行回执

- `storyboard` 的 `add_assets` 增加且保留原角色/资产，`remove_assets` 按节点及用途移除，`upsert_assets` 增加或改用途；`add_references` / `remove_references` 增减共享输入。增量数组须非空。`set_assets` / `set_references` 是明确替换；清空行资产不会清共享输入。回执分别列出行级与共享影响。
- `set_references` 整体替换共享引用列表，各行继承输入和派生连线随之更新，显式行级资产保留。`update.patch` 对全部选中行相同；逐行不同内容使用 `update.updates`；镜头数量变化用 resplit，每批最多100项、表内最多100行。任一目标、字段或引用无效则整批拒绝。景别、运镜、光影等创作列与领域字段合同一致。
- `storyboard` 的 `read` 用 fields 选择创作字段、missingAnyFields 筛选任一列缺失的行。summary 默认 rows=[]，显式 fields 也返回所选正文；长文本按 nextReads 读原文，分页按 nextRead。coverage 分别表达选择范围已到末尾、整表行覆盖和正文截断；提示词覆盖为空不等于生成被阻塞。`canvas_get_state.nodeIds` 精读单次最多8个；整画布目录省略该字段。
- 编辑短回执返回 changed、affectedRows、changedRows 及快照，创建/追加返回 createdRows，删除返回 removedRowIds。callLimits.mutationCallsPerStep 固定为1；下一模型步骤可复用成功回执快照，实际冲突或状态未知时再读取并核对原操作。
- 批次可用稳定 `operationId` 去重，读取 `operationIds` 查询持久提交目标；同键同参数不重复执行或审批，同键不同参数拒绝。`replayed` 回执属于历史提交，不能替代当前字段查缺。纯创作字段更新可携带 `storyboardRevision`，允许无关布局变化，仍拒绝表内容、依赖资产和实体世代冲突；其余动作继续使用全画布版本。提示词复制有效输入中的 `promptHandle`，生成时才按最终素材顺序转换为序号，原正文不改写。
- `taskSubmitted` 仅表示曾提交任务，即使为 true 也可能失败；交付以 `status/task_get` 和实际产物为准，不能因此自动重复提交生成。

参数错误不再回传整份 `parameters`，使用 `field/issue/argumentHints/guidance` 定位修正；可明确保留语义时提供 `exampleArguments`，示例中的占位符需要替换为真实读取值。快照冲突返回 `nextRead` 和 `retryArgumentsPatch`；小载荷示例保留原操作，大载荷不重复回传。分镜读写的行选择错误返回 `invalidRowIds/duplicateRowIds`。

读取回执和原生技能 `read` 提供本次读取后的 `readCallsUsed/readCallsLimit/readCallsRemaining`。后台配额配置和扣减规则不变，技能同一步同页重试仍不重复扣减；缓存回执的预算按当前运行状态补充，不写入内容缓存。

`add_node` 只支持 `type/id/nodeType/title/content/x/y`，尺寸样式使用后续 `update_node.patch` 并核对节点能力。`set_parent` 只调整容器归属，不承担排版；后续写入使用回执新快照，需要精确坐标时回读。

## 升级

后端和 Worker 配套更新，旧 Worker 的快照注册协议不再提供。迁移 59 保留版本记录，新安装不再创建相关表；已存在的历史表与列不自动删除，也不再读写。工具目录导出文件只用于离线文档与参数合同测试，不参与运行时领取。
