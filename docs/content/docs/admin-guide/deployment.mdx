## 先确认部署类型

后台管理员权限不等于服务器操作权限。服务器安装、备份、容器和数据迁移由有运维权限的人执行。

正式服务器默认使用官方 Release 镜像、生产编排和 Host Updater。源码构建、本地试用或自定义部署的在线更新边界不同，先依据实际安装方式确认。

安装步骤和编排选择见 [Docker 部署](../overview/docker.mdx)。不要将后台可打开当成已经具备安全在线更新条件。

## 应用更新

入口：系统设置 → 系统更新（`/admin/settings/system-update`）。

1. 查看当前版本、部署状态和更新器是否可用。
2. 阅读目标版本的升级说明，确认备份及迁移前提。
3. 选择合适维护窗口，按页面执行受管更新并观察进度。
4. 更新后验证登录、模型生成、任务、资源访问和相关功能。
5. 失败时读取更新记录，由运维按对应版本规则决定恢复或回退。

涉及数据库迁移时，回退不是简单换一个旧镜像。先确认备份和版本兼容条件，不能对生产数据直接试错。

## 文档更新

文档源码在 `docs/content/docs/`，是独立构建的文档站。修改公开正文后需要重新构建 docs 镜像，才能把内容放进当前交付方式；不需要因此重建所有业务镜像。

维护流程：修改文档 → 审核和文档构建检查 → 发布 docs 镜像 → 由受管更新流程选择版本 → 独立更新 docs → 检查正文、搜索和资源。

官方自动部署只有显式配置后才生效。自部署管理员不会因为上游文档改变就自动被更新；由本机更新器和 `scripts/update-docs.sh` 管理选择、更新及回退。具体命令与配置见 [文档站独立交付](../backend/docs-deployment.mdx)。

## 升级到包含文档服务的版本

旧受管实例需要满足更新器过渡能力，按发布说明先完成过渡版本，再启用包含 docs 的完整编排。不能假定任意旧更新器都能一步升级。

## 验收清单

- 顶栏文档入口打开同域 `/docs`，正文、导航、中文搜索和图片正常。
- docs 更新后，原应用登录、任务和素材仍正常。
- 文档故障仅按文档更新记录恢复，不以恢复业务数据库处理文档错误。
- 保留当前与上一个可用版本的信息，核对文档适用版本，避免用户读到尚未部署的功能说明。

实际发布、官方部署配置、arm64 运行和受管升级演练分别需要证据；CI 构建成功不能替代生产验收。
