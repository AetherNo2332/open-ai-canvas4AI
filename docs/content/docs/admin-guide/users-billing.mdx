## 用户管理与用户分组

入口：用户与运营 → 用户管理（`/admin/users`）、用户分组（`/admin/user-groups`）。

1. 先搜索并核对目标账号，避免对同名用户操作。
2. 按页面支持的动作调整账号状态、权限或密码等信息。
3. 变更分组时核对分组价格与权益，再保存。
4. 让测试账号重新读取账户信息并验证效果。

管理员角色和用户分组用途不同，价格分组不等于后台管理权限。冻结或调整账号前先检查是否有正在进行的任务及未处理订单。

## 积分运营

入口：积分运营（`/admin/credit-operations`）。页面包含异常计费核对、注册与签到赠送、人工调账及自动退款相关设置。

1. 先按用户、任务或时间核对账务记录。
2. 判断是预占额度、最终扣费、返还还是实际异常。
3. 需要调账时明确目标账号、方向、数量和原因，再提交。
4. 保存后核对记录和余额；请求超时时先查询结果，避免重复调账。

赠送规则调整后用符合条件的测试账号检查领取结果。具体规则与约束见 [积分奖励专题](../backend/credit-rewards.mdx)。

## 支付充值

入口：支付充值（`/admin/payments`）。

1. 配置支付服务所需插件与凭据，确认站点公网回调地址正确。
2. 设置并启用商品，区分积分商品与存储权益。
3. 从普通用户端创建小额测试订单并付款。
4. 对照支付订单、到账记录和实际余额或权益，确认完整流程成功。

保存支付配置或前端显示付款完成，都不能替代服务端订单确认。发生到账争议时先查订单和回调处理结果，再决定处理方式。

## 兑换码

入口：兑换码（`/admin/redemption-codes`）。按页面要求配置兑换内容、数量及可用条件，生成后妥善分发。发放前抽查一枚测试码；停用或作废前核对其使用状态。

兑换失败先核对码是否有效、已使用或不满足条件，不直接给用户重复补发等额积分。

## 推广中心

入口：后台推广中心（`/admin/referral`）。配置页面提供的推广规则，查看邀请和佣金记录。用户端展示的是积分返佣；规则调整后说明适用范围，用新测试订单核对计算结果。

## 处理一笔争议的顺序

记录用户诉求 → 查任务或订单 → 查账务变化 → 判断是否需退款或调账 → 执行一次明确操作 → 再次核对并回复用户。避免仅凭截图修改余额。
