## 先区分三个概念

| 概念 | 含义 |
| --- | --- |
| 渠道 | 一个模型服务来源，包含地址、凭据和协议等连接信息 |
| 渠道模型 | 该来源实际提供的模型及其能力、成本和可用状态 |
| 前台模型 | 用户看到和选择的统一模型入口，可映射到后台来源 |

入口：模型与渠道 → 渠道与模型（`/admin/channels`）、前台模型（`/admin/models`）。前台模型菜单受相应功能开关影响。

## 接入一个渠道

1. 新建或编辑渠道，填写可辨认的名称。
2. 选择匹配的协议或已安装的协议插件，填写上游地址和凭据。
3. 添加或同步实际提供的模型；核对模型标识，而不只看展示名称。
4. 设置模型类型和能力：文本、图片、视频、音频等只能启用实际支持的内容。
5. 配置价格、并发及页面提供的其他策略，保存后测试连接和小任务。
6. 从请求明细核对结果、上游错误和费用，再开放给用户。

密钥无效、余额不足、地址错误和协议不匹配要分别处理。不要通过扩大所有网络访问权限来解决某一个地址不可达的问题。

## 配置前台模型

1. 进入前台模型，建立或编辑用户可见条目。
2. 关联有效的渠道来源，核对可用状态。
3. 设置名称、类型、展示信息和实际支持的参数。
4. 核对报价规则，再用普通用户检查选择器与真实生成。

管理员看到渠道存在，并不代表用户已经能选到对应前台模型。排查时按「渠道 → 渠道模型 → 前台入口 → 用户权限」检查。

## 能力与价格

图片尺寸、数量、参考限制，视频时长、分辨率、参考方式，以及文本思考选项都应按模型实际能力设置。模型或协议变化后重新测试，避免把不支持的参数暴露给用户。

计费可能按次数、时长、Token 或其他模型规则计算。配置后核对输入组合对应的报价，再检查一次实际结算；用户分组价格因素还需结合 [分组与积分运营](./users-billing.mdx)。

## 停用与排错

停用前确认哪些前台模型、短剧或电商流程依赖它。生成失败时先在请求明细按任务和时间定位，再检查连接、能力、限额及上游状态；不要直接修改多个渠道后再猜哪个生效。

技术专题：[视频 Token 计费](../backend/video-token-billing.mdx)、[请求与任务稳定性](../backend/task-runtime-stability.mdx)。
