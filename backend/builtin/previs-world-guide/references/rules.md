# 行为规范

## 1. 先读后写
- 写入前必须用 `director` 的 `read` 读取目标场景，拿到最新 `snapshotHash`。每次写入成功后，下一次写入使用新返回的 `snapshotHash`，不要复用旧值。
- 读场景时提供 `sceneId` 或已绑定场景的 `nodeId`。返回包含精确 transform、真实对象 ID、`markers`、`scene.paths`、`objects[].motionPath`、`cameras[].motionPath` 和 `cameras[].moves`。
- 不要凭记忆、画面描述或旧消息猜坐标、ID、路径标签。用户已经画好的路径优先复用，不要另起一套。

## 2. 坐标与单位
- Y 轴向上，单位米，地面 Y=0。成人约 1.8 米高，演员默认面朝 +Z；`rotation=[0,yaw,0]`，yaw=atan2(dx,dz)，面朝 +X 时 yaw≈1.571。
- 演员原点的 Y 是脚底离地高度：站在地面为 0，站在台阶、桌面或屋顶时为台面高度。低于地面的值会被拉回 0。
- 路径点的 Y 是离地高度。演员的路径高度写入关键帧 `lift`，人偶世界高度由脚底高度加 `lift` 得到。
- 道具原点在底面中心；放在地上就是 y=0，放在桌面就是桌面高度（桌高约 0.75）。摄影机与道具的路径高度直接作为位置高度。

## 3. 一次补丁做一件完整的事
- 每次 `director apply_patch` 最多 32 项操作，按顺序执行，后面的操作能看到前面的结果。
- 搭景、摆人、位移、运镜拆成可独立审批的补丁。不要一次塞满 32 项。
- 审批卡逐条显示操作摘要，所以每个对象要有可读的 `name`，每次操作要能单独看懂。

## 4. 用对操作
| 要做的事 | 操作 | 不要用 |
| --- | --- | --- |
| 实物（树、车、房子、桌椅） | `object_add kind=prop propId` | box / cylinder 拼凑 |
| 一片街区、城镇、园林、森林 | `object_add kind=layout` | 上百个单独道具 |
| N 个同类 | `object_array_add` | N 条 object_add |
| 人物 A 点到 B 点 | `actor_travel` | `object_update pose=run`（原地姿态） |
| 人物沿一条路线或用户画的轨迹 | `object_motion_path_set`（`pathPoints` 或 `pathId`） | 一帧帧手写关键帧 |
| 推拉摇移、环绕、跟拍 | `camera_move` | 用 camera_keyframe_upsert 手算 |
| 时间、天气 | `world_update` | 改背景色 |

## 5. 不确定就问
- 用户说「从这里到那里」，但场景里没有标记点或参考轨迹：请用户右键地面标记 A、B，或用画笔画一条轨迹。不要编坐标。
- 场景里有多个人、多个运镜或多个路径时，先根据真实 ID 与标签确认主体。
- 镜头时长不够：先说明，再用 `shot_update` 加长，或缩短动作。不要静默压缩到看不清。

## 6. 写完自检
- 再读一次场景，核对对象数量、谁在哪、路径起止时间 `motionPath.end`、运镜段是否在镜头时长内、人物是否面朝正确方向。
- 需要看画面时用 `director` 的 `preview`。场景摘要只说明数据，不代表已经看到画面；preview 没有录制完成的同步回执。

## 7. 修改与删除
- 改已有对象用 `*_update`，不要删了重建，避免丢失 ID、关键帧和用户手动调整。
- 删除前确认删的是哪一个。运镜、路径、动作各有删除操作，见 [修改与删除](edit.md)。

## 8. 审批与只读
- `read` 是只读；`create_scene`、`apply_patch`、`preview` 是写 action，可能进入审批或只读拦截。
- 审批预览与实际执行使用同一份补丁计划。等待用户批准后再认为场景已改变；回读是最终事实。
