# 用文本 / Markdown 节点写分镜

分镜表工具（storyboard）未在本轮提供时——通常是画布 Agent 设置里的"分镜表工具"开关被关闭——此时**不能创建分镜（脚本）节点**，也不能复制已有的分镜节点：节点创建接口会拒绝 script 类型。分镜内容用**文本节点或 Markdown 节点**承载（推荐 Markdown，方便分镜卡排版与阅读）。

## 边界先讲清

- 开场先告诉用户：当前是 Markdown 分镜文档，只承载内容；镜头级资产绑定、锁定、批量生成回填需要重新开启分镜表工具。
- 不能创建或复制分镜（脚本）节点——画布写入会直接拒绝；不写 `metadata.storyboard`、不编造 rowId、不声称具备行状态。
- 画布上**已有的** script 节点（用户存的剧情）照常可读可改正文；分镜稿落到新的文本/Markdown 节点，不要写进 script 节点。
- 用户明确要"给人看的排版文档"时用 Markdown 节点；普通记录用文本节点即可。

## 落点与结构

- 一个"场"一个节点：`canvas_apply_ops` 的 `add_node`（nodeType=markdown 或 text），标题写"第X场·地点·时间"，正文写整份镜头卡；创建前照常 `canvas_list_node_types` 查字段合同，按最新快照提交，创建时省略坐标。
- 大场次拆多个节点时，标题连续编号；节点内结构固定，便于人读也便于后续誊写：
  - `## 场次`头部：场号、场景、时间、出场人物、光线基调；
  - 每镜一个小节：`### 镜头 N（Xs · 景别 · 运镜）`，编号在全场内连续；
  - 场与场之间用 `---` 分隔；换场必须注明新场景、时间或光线变化。

## 每镜字段（固定键序，加粗键 + 换行列出）

- **画面**：只写可见动作与走位。"意识到、回忆起"等不可见信息转译成眼神、停顿、手部动作或道具反应。
- **台词**：只写本镜实际念出的台词或旁白；按一秒约 5 个中文字符估时长，超长就拆镜。
- **首帧**：imageGenerationPrompt，描述第一帧的构图、人物位置、光源、材质；不写画幅比例。
- **运动**：videoMotionPrompt，只写主体运动、环境运动和结尾状态；一镜只保留一个主运镜，有起点、动机和停止点。
- **结尾状态**：continuityOut——本镜结束时人物位置、朝向、手中道具与光线；它是下一镜的开场。
- **必备**：mustHave，最多 3 项；没有就省略整行。

## 拆镜手法

- 先读剧情（script 节点或用户消息），列出场景、人物、冲突与结尾；再按因果切镜头：一个镜头只服务一个叙事目的（建立、反应、动作或转折）。
- 大远景只承担空间与处境；对白与反应优先中景、近景或过肩。避免每镜都是推拉摇移。
- 连续性成链：写每一镜前回看上一镜的**结尾状态**；人物、服装、道具、光线、时间在镜间保持一致，变化必须有剧情原因。
- 镜头时长 3–8 秒为主；一场戏 5–15 镜常见，超过 20 镜先考虑是不是把两场写成了一场。

## 衔接生成（分镜表工具关闭时）

- 生成走 `generate_media` 普通模式：mode+prompt+nodeId+title+referenceNodeIds，模型目录先 `model_list` 按实际输入筛选，`selectionId` 原样复制；以分镜内容为文本来源时，用承载分镜卡的文本/Markdown 节点真实 ID 作 `sourceNodeId`。
- 反复出现的人物、道具、场景仍先出三视图再做镜头（见 canvas-tools-guide 的"资产"一节）；引用一律用真实节点 ID 或 `generationSpec.referenceBindings` 声明，不写"参考图1"。
- 连续镜头合成一个视频请求的做法同样适用；提交后照常异步等待，不轮询。
- 每镜生成完成后可用 `canvas_inspect_image` 核对画面是否符合本镜字段，再继续下一镜。

## 迁回分镜表

用户重新开启分镜表工具后：分镜节点需要剧情在 script 节点的 composerContent 里——先把镜头卡誊写/整理进 script 节点正文（`update_node.patch.composerContent`），再调用 `split` 让服务端重建行；镜头小节结构与行字段一一对应，誊写时不要改写事实。
