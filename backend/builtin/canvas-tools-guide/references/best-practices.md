# 工具使用最佳实践

让每一次工具调用都有明确目的、最少参数和可核对的回执。下面的做法来自真实运行中反复出现的浪费与失败。

## 读取：够用就停

- 首次读画布用 `canvas_get_state {}`，之后按需续读，不为“确认一下”反复读整张画布。回执里的 `snapshotHash` 与节点身份可以直接用于下一次写入。
- 结构化内容用专用读取：分镜用 `canvas_read_storyboard`，批量表用 `canvas_read_batch_table`。不要从 `canvas_get_state` 的摘要里猜行 ID 或列 ID。
- 只在要判断画面时调用 `canvas_inspect_image`。同一版本已经看过，就复用已有观察，不重复附图。
- 用户说已修改画布，或回执报告快照冲突时，重读相关节点，再按新状态继续。

## 写入：一步一个，等回执

- 每个模型步骤最多一个写入或生成调用。相互依赖的写入等前一个回执返回再做；彼此独立的节点改动可以放进同一个 `canvas_apply_ops`。
- 只传必需字段，省略用不到的可选字段，不传 `null`。分镜、角色由系统分配 ID，不要自己编造。
- 回执说执行成功才算完成；待审批、已提交、生成成功是三个不同结果，按回执原文说明。

## 生成：异步提交，不等不轮询

- `generate_media` 提交成功后立即返回 `status=submitted`，生成在后台进行。提交后继续做别的事：编排下一镜、写说明、提交下一个生成。
- 不要用 `task_get` 轮询进度。生成结束时会收到以「[系统通知] 生成结果」开头的消息，里面写明每个节点成功、失败或回写情况。
- 只有下一步必须依赖结果时（例如要查看生成的图片再决定怎么改），才调用 `wait_generations`。它会挂起运行，生成结束后带着结果恢复。
- 还有生成在进行时可以照常收尾，在答复里写明哪些生成仍在进行、完成后会出现在画布上。
- 生成失败不会自动重试。重新收费生成需要用户明确同意。

## 视频：把多个分镜合成一个请求

逐镜头各发一个视频请求，会让每段画面、人物和光线都不连贯，花费也成倍增加。连续镜头属于同一场景、同一组人物时，合成一个视频请求：

1. **先分组**：按场景和连贯性把镜头分组。同一场景、同一组人物、动作前后衔接的镜头放一组；换场景、换时间、需要完全不同参考的镜头另起一组。
2. **算总时长**：一组的总时长 = 各镜头时长之和。先用 `model_list` 查目标模型允许的时长，总时长不能超过上限；超过就拆成两组，在镜头之间的自然断点处拆。
3. **写一段多镜头提示词**：按镜头顺序写，每个镜头一行，写清序号、时长、景别、机位或运镜、画面内容和对白。例如：
   ```
   镜头1（3秒，中景，固定机位）：林彻推开医院大厅的门，逆光走进。
   镜头2（4秒，近景，缓推）：他停下，看向墙上的警示标语，神情凝重。
   镜头3（3秒，特写）：标语上的字被手电光扫过。
   ```
   开头先用一两句交代整组共同的风格、光线和人物外观，避免每个镜头重复。
4. **合并参考素材**：把这组镜头用到的角色卡、场景图合并到一个 `referenceNodeIds`，去掉重复项。超过模型允许的参考数量时，优先保留角色卡与主要场景。
5. **用普通生成提交**：`generate_media` 的普通模式（mode=video，prompt、referenceNodeIds、nodeId、title、size、durationSeconds=总时长）。给新视频节点起能看出范围的标题，例如“第1集第2场 镜头1-3”。
6. **说明归属**：合成的视频是一个新节点，不会自动回填到各分镜行。在答复里说明它覆盖哪几个镜头；用户要求时，再把它绑定到对应分镜行。

只需要单独重拍某一个镜头，或用户明确要求逐镜生成时，才用分镜模式（`storyboardNodeId` + `storyboardRowId`）逐行生成。

## 资产：剧本和分镜定稿后先出三视图

剧本和分镜都经用户确认后、生成任何镜头之前，先为反复出现的人物、关键道具和主要场景生成三视图参考，再用它们生成镜头。没有统一参考时，各镜头里的人物和场景会各长各的。

1. **列清单**：用 `canvas_read_storyboard` 读全部行，按行汇总需要的人物、道具、场景。只出现一次、不影响辨认的群众和杂物不做三视图。画布上已有可用参考或角色卡的直接复用，不重做。
2. **人物**：一张图里并排正面、侧面、背面全身，中性站姿、双手空置、纯净浅色背景、均匀光线，三个视角保持同一张脸、发型、服装和比例。武器和关键道具单独做，不放进人物手里。
3. **道具**：同一件物品的正面、侧面、背面（需要时加顶视），纯净背景，加一个常见物体或人手作尺寸参照。
4. **场景**：同一空间在同一时间、同一光线下的全景加两个其他方向，或一张平面布局。告诉用户这是视觉参考，不是精确的建模图。
5. **提交与核对**：每项一个 `generate_media` 图片请求，标题写明对象和"三视图"，例如“林黛玉 三视图”。生成是收费操作，按本轮权限取得授权；多项可以连续提交，不必等前一个完成。结果回来后用 `canvas_inspect_image` 核对各视角是否一致，不合格的只重做那一项。
6. **建卡与绑定**：核心人物用 `canvas_create_character` 建角色卡（`primaryImageNodeId` 定妆图 + `turnaroundImageNodeId` 三视图，或单图复用）。再用 `canvas_edit_storyboard` 的 `add_assets` 把人物、道具、场景按 `character`、`prop`、`environment` 绑定到用到它们的行，之后生成镜头时直接引用。

用户明确不要三视图，或只做一个不复用人物的镜头时，可以跳过；跳过时说明后续镜头之间的人物和场景可能不一致。

## 出错：读回执，不盲试

- 参数错误按回执的字段和说明修正一次；同一错误连续出现时停下来，向用户说明。
- 回执说某个字段“传成了字符串”时，直接把对象或数组放进参数，不要先把它序列化成 JSON 字符串。看图摘要 `summary` 就是对象：`{"short": "...", "detailed": {...}}`。
- 快照冲突、节点被锁，说明画布正在被别人修改：重读后按新状态重做，或等用户编辑完成。
- 权限、审批、预算不足时如实说明，不要换个工具绕过。
