## 实现边界

1. Go 返回终态工具回执或模型失败判定后，Node 结束 Pi 运行，不再发送租约绑定的快照、模型步骤或检查点。Go 的账号归属和 lease epoch 校验保持有效。
2. `canvas-terminal-history` 使用 Pi `context` hook，仅为上一轮已终结且缺失回执的历史调用补充“结果未知”的错误投影，闭合模型协议。保留真实回执，不回放写入或收费操作，不伪造业务成功，不改写数据库历史。当前运行的缺失回执仍由 Go 权威回执恢复。
3. 看图描述继续由 Markdown 提供：多图观察须在正文点名 nodeId，内部思考与查看计划不是观察证据；重复读取保护保留。
4. 用户新增硬要求：**原图必须保留在模型上下文中，不能裁剪、移除或只替换为文字摘要**。移除 Go 的按工具轮次删图与按模型上限替换旧图逻辑。图片数量、文件大小不满足模型能力时，在创建下一模型任务之前明确拒绝。
5. `canvas-original-image-context` 从当前 Pi session active branch 的全部祖先恢复被文本压缩隐藏的原始图片引用，保留 inspection 的 nodeId 数据说明，不重放旧用户指令、不读取兄弟分支、不重复附送已有原图。Go canonical 中比 Pi 检查点更新的图片引用先补入 Pi 条目，再进行新的模型请求或自动压缩。
6. 语义压缩仍走 Go 原结构化压缩与计费链路；原图持久化为账号资源引用和原始元数据，请求时水合完整资源字节。没有图片转换、裁剪或 base64 持久化。
